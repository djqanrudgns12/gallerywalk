# 3D 모듈 규격 v4 — 메인홀·큰 전시실·큰 외관 (ADR-071, PRD_V2 §3·§5·W-03·W-06·W-11·W-12)

> 배치 엔진 v4(`packages/core/src/domain/layout/v4/`)가 이 이름들을 낸다(이름 목록은 `domain/templates/geometryV4.ts`).
> 좌표·UV·재질 칸·굽기 규칙은 `modules.md` §1·§3·§4를 그대로 따른다. 여기에는 **v4에서 달라지는 것**만 적는다.
> 높이와 상관없는 조각(`mh_floor_2x2`, `mh_ext_plaza_2x2`, 설비)은 v3 것을 그대로 쓴다.
> 운영 배치 판(`ALGO_VERSION`)은 이 묶음이 `assets:build` 예산을 통과한 뒤에만 4로 올린다(ADR-071 결정 1).

## 1. 높이·두께

| 구역 | 벽 높이(바닥 → 천장 아랫면) | 근거 |
|---|---|---|
| 전시실 `mh4_room_*` | **6.0m**(`LAYOUT_V4.roomHeight`) | W-09 "방이 아니라 전시관" |
| 메인홀 `mh4_hall_*` | **10.0m**(`LAYOUT_V4.hall.h`) | W-03 광장 같은 홀 |
| 현관 천장 | 9.0m(`geometryV4` `porticoCeilingY`) | W-11 |

- 벽 두께는 v3처럼 0.3m이고, 문·포털 조각만 두께 면을 그린다.
- 천장·바닥 판은 v3 `geometry.py`와 같게 Blender +X·−Y로 2m(glTF x·z 0..2)이다(`modules.md` §1, 배치 `tiles()`와 맞음).
- 같은 날개 이웃 방 사이는 **2.0m 두꺼운 벽**(`LAYOUT_V4.roomGap`)이다. 방 사이 문은 그 깊이의 통로다.
- 배치 수치는 `contract.mjs`가 뽑는 `contract.json`에서 읽는다. 스크립트에 다시 적지 않는다(`modules.md` 머리말과 같음).

## 5. 예산(조각 하나 · 묶음)

| 묶음 | 삼각형 | 재질 칸 | 텍스처 | glb |
|---|---|---|---|---|
| `core-v4.glb`(전시실 7조각) | 조각마다 ≤ 6,000 | ≤ 4칸/조각 | 기본색 1024² KTX2 + 구운 빛 | ≤ 1.6MB |
| `hall-v4.glb`(홀 9조각) | 조각마다 ≤ 8,000 | ≤ 4칸/조각 | 같음 | ≤ 1.8MB |
| `exterior-v4.glb` | 현관 ≤ 40,000, 나머지 ≤ 6,000 | ≤ 4칸/조각 | 같음 | ≤ 2.4MB |

- 첫 화면 바이트 상한(PRD_V2 §7)은 광장·현관·홀 앞쪽만으로 지킨다. 전시실 묶음은 계단을 오르는 동안 받는다.
- 그리기 호출은 같은 조각을 인스턴스로 묶어 센다(PLAN §6.2). 홀 벽 조각 하나가 10m라 v3보다 조각 수가 적다.

## 6. 검수

- `verifyOutput.mjs`에 v4 조각 이름·높이(6m·10m)·기준점·두께 면 유무를 더한다.
- 짝 규칙: 같은 자리에 `mh4_room_portal_4m` + `mh4_hall_portal_4m`, `mh4_room_door_4m` + `mh4_room_doorframe_4m`이 함께 놓인다. 둘 다 두께 면을 그리면 깜빡인다.
- 캡처 검수는 키 아트(그림 세션, `.local/art/m0/keyart/`)와 나란히 놓고 디자인 비평을 받는다(PRD_V2 §9.3).
