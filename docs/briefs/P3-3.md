## 목표
PLAN §9.2 **교사 표**의 경로를 Hono 라우트로 잇는다. 유스케이스(`apps/server/src/application/*.ts`)는 이미 있다 — 라우트는 검증·인증·속도 칸·응답 모양만 맡는다. 웹 어댑터(`apps/web/src/adapters/api/client.ts`)가 이미 이 경로·모양을 부르므로 **그 기대와 맞춘다**(경로·`If-Match` 정수·Bearer·응답 스키마).

## 읽을 것
AGENTS.md(§3), PLAN §9.2(교사 표·멱등·고치기 충돌·대표작·전시 경계), §9.3, §11(PIN 칸 셋·시작 코드), ADR-024·025·048·055·056·057 보충, `apps/server/src/{ports,application,http,security,live}/**`, `apps/server/test/{support,helpers,http,application}/**`, 웹 어댑터 `apps/web/src/adapters/api/{client.ts,http.ts}`와 그 시험(경로·머리·응답 기대), core 스키마 `packages/core/src/types/{exhibition,room,artwork,reaction,api}.ts`, P3-2 보고 요지: 보안은 `createSecurity(env,{db,clock})` → `ServerSecurity`(`identify(clientRequestOf(c))`, `pinGuard.check/fail`(+`delayMs` 기다림은 라우트), `devices.isRegistered/register`), 인증은 `http/middleware/auth.ts`의 `teacherAuth(deps)` + `new Hono<TeacherEnv>()`.

## 만들 것
- `apps/server/src/http/routes/teacher.ts` — `teacherRoutes({ deps, security, live? })`:
  - 인증 없음: `POST /api/teacher/exhibitions`(시작 코드·기기 등록·쉬운/쓰인 PIN — 쓰인 PIN도 PIN 실패로 셈), `POST /api/teacher/pin`(PIN 칸 셋 → 맞으면 PIN 세션 넣고 `{exhibitionId}`; 틀리면 `E_PIN_INVALID`, 잠김 `E_PIN_LOCKED`, 전역 지연).
  - 인증: `GET /api/teacher/me`, `GET|PATCH /api/teacher/exhibitions/{id}`, `POST …/{id}/open|close|reopen`(close·지우기 때 `live?.closeExhibition(id, 'E_EXHIBITION_CLOSED')`), `POST …/{id}/link/rotate`, 전시실(`POST …/{id}/rooms`, `PATCH|DELETE /api/teacher/rooms/{roomId}`, `PUT …/{id}/rooms/order`), 작품(JSON 글 작품 `POST …/{id}/artworks` — 파일 업로드는 미디어 작업(P3-4)과 함께라 **이번엔 JSON(글)만**, `PATCH|DELETE /api/teacher/artworks/{aid}`, `POST …/{aid}/restore`, `PUT /api/teacher/rooms/{roomId}/artwork-order`, `POST /api/teacher/artworks/batch`), 반응(`GET …/{id}/reactions`, `PATCH /api/teacher/reactions/{rid}`, `GET …/{id}/reactions.csv` — BOM 붙은 UTF-8, RFC 5987 파일 이름).
  - 모든 경로: 토큰의 전시 = 대상 행의 전시(아니면 `E_NOT_FOUND`), `If-Match` 정수(빠지면·어긋나면 `E_CONFLICT`), 응답은 웹 어댑터가 기대하는 core 스키마 모양.
- 없는 유스케이스는 `apps/server/src/application/`에 새 파일로(`pin.ts`: PIN 로그인, `teacherReactions.ts`: 목록·숨김/고르기·CSV). PIN으로 전시를 찾으려면 저장소에 `exhibitions.getByPinHmac`이 필요 — **포트(`ports/index.ts`)·SQLite(`store/repos.ts`)·메모리(`test/support/memoryStore.ts`)에 이 메서드 하나만 더해도 된다**(다른 포트 변경은 보고).
- `apps/server/src/http/app.ts` — `createApp`에 선택 인자 `teacher?: { security: ServerSecurity; live?: … }`를 받아 `teacherRoutes`를 붙이는 몇 줄.
- 시험 `apps/server/test/http/teacher.test.ts`(메모리·SQLite 두 저장소, 임시 DB): 만들기 멱등·시작 코드·쉬운/쓰인 PIN, PIN 로그인·잠김(가짜 시계), me, 고치기 충돌, 전시 경계(전시 A 토큰으로 B의 전시실·작품·반응 → `E_NOT_FOUND`), 열기(게시 0이면 `E_NOTHING_PUBLISHED`)·닫기, 전시실·작품 순서, 반응 CSV.
