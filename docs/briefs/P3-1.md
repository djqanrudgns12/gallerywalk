## 고칠 파일(이것만)
- `apps/server/src/env.ts` — 환경 값 zod 검증(§9.9 목록). 비밀값(`PIN_HMAC_SECRET` 32바이트 base64/hex, `RATE_KEY_SECRET`, `START_CODE_HMAC`)이 없거나 짧으면 시작 거부. `config.ts`의 키와 같은 이름의 환경 변수는 `overrideConfig`로 덮어씀(숫자·참거짓만, 모르는 키 무시하고 기록). 운영(`NODE_ENV=production`)에서 `RETENTION_TEST_MINUTES`가 있으면 시작 거부. **`.env` 파일을 읽지 않는다** — `process.env`(또는 시험에서 넣은 객체)만 받는 순수 함수 `loadEnv(source)`.
- `apps/server/src/store/db.ts` + `apps/server/src/store/migrations/0001_init.sql` — PLAN §10.2 그대로(STRICT, `artworks.fail_code` 포함, 색인·복합 외래키). 열 때 `journal_mode=WAL` `foreign_keys=ON` `busy_timeout=5000` `secure_delete=ON` `synchronous=NORMAL`. 앞으로만 가는 마이그레이션(`meta`에 판 기록, 같은 판은 다시 안 돎, 트랜잭션).
- `apps/server/src/log.ts` — JSON 한 줄(시각·수준·requestId·경로·상태·ms·exhibitionId), 날마다 회전·7개 보관(`DATA_DIR/logs`), 별명·메모·PIN·토큰·IP 원문을 넣지 않음, 경로의 `/t/` 뒤는 `***`.
- `apps/server/src/http/middleware/{requestId,securityHeaders,bodyLimit,errors}.ts` + `apps/server/src/http/app.ts` 연결 — §9.3 순서. 보안 머리는 §11.4 그대로(CSP·Referrer-Policy·nosniff·Permissions-Policy·HSTS). `/api/*`는 `Cache-Control: no-store`. 오류 봉투: `AppError` → `errorCatalog`의 http·retryable, zod 오류 → `E_VALIDATION` + `issueFields`, 그 밖 → `E_SERVER`(기록에 원인, 응답에는 원인 없음). JSON 본문 64KB 넘으면 `E_FILE_TOO_LARGE`가 아니라 `E_VALIDATION`? — **PLAN에 코드가 없으니 무엇을 골랐는지 보고**.
- `apps/server/src/http/routes/health.ts` — `GET /api/health`: DB 열림·디스크 남은 공간(`fs.statfs`)·대기열 길이(지금은 0을 돌려주는 자리, P3-4가 채움).
- `apps/server/src/index.ts` — 시작 순서(§9.1)·끝내기(SIGTERM: 새 요청 거부 → 20초까지 기다림 → `wal_checkpoint(TRUNCATE)` → 닫기). 127.0.0.1만.
- 시험: `apps/server/test/**`(Vitest). 임시 폴더에 DB(시험마다 새로), 환경 값 검증(빠진 비밀값·짧은 비밀값·운영에서 시험 키), 마이그레이션 두 번 돌려도 같음, 복합 외래키가 다른 전시 참조를 거절(§10.2 "전시 경계" — 작품 → 다른 전시의 전시실, 반응 → 다른 전시의 작품·방문자), 오류 봉투 모양(`ApiErrorSchema.parse`로 확인), 보안 머리, 기록 가리기(토큰·`/t/…`가 기록에 없음), 건강 확인.
