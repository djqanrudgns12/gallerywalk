## 목표
`packages/core/src/domain/`에 순수 함수 두 묶음을 만든다: **보관 규칙**(G-18, PLAN §9.6·§9.7)과 **자동 투어 시간표**(G-16, PLAN §6.13, ADR-046). 서버 작업·화면·소리 재생 연결은 범위 밖.

## 읽을 것
AGENTS.md(§2·§3 특히 "domain = 순수 함수, 외부 패키지 금지"), PLAN §6.13 전체(시간 기준·카메라 일정·소리 이음·시험), §9.6 캐시 표·§9.7 보관 정리, PRD G-16·G-18, ADR-046(`docs/decisions.md`), `packages/core/src/config.ts`의 `TOUR_*`·`EXHIBITION_TTL_DAYS`·`MEDIA_*_MAX_AGE_SEC`·`PURGE_DELETED_HOURS`·`PDF_INCOMPLETE_PURGE_HOURS`, `packages/core/src/types/settings.ts`(`TourSettings`)·`media.ts`(`AudioAnalysis`), 기존 도메인 코드 모양 참고 `packages/core/src/domain/pages/*.ts`.

## 고칠 파일(이것만)
- `packages/core/src/domain/retention/RetentionPolicy.ts` — 시각(UTC ms)을 인자로 받는 순수 함수: `expiresAt(createdAt, retentionDays)`, `isGone({expiresAt, deleting}, now)`(만료 또는 지우는 중 → 없는 전시로 다룸), `mediaCacheSeconds(expiresAt, now)` → `{maxAge, sMaxAge, staleIfError}`(§9.6 표: 각각 min(설정, 남은 초), 0 아래로 내려가지 않음), `deletedArtworkPurgeAt(deletedAt)`, `incompletePdfPurgeAt(createdAt)`, `daysLeft(expiresAt, now)`(화면 "○일 뒤 지워져요"용, 올림 규칙 주석).
- `packages/core/src/domain/tour/tourSchedule.ts` — `planTour(input) → TourPlan`. 입력: 전시실 목록(순서대로, 각 전시실의 관(1관·2관…)별 작품 수, 배경음악 `{durationMs, audibleStartMs, audibleEndMs, loudnessDb}` 또는 null), `TourSettings`. 출력: 구간 목록(홀·이름판·작품 구간(다가가기/머무르기)·문 통과·출구)의 시작·끝 초, 전시실마다 곡 재생 계획(시작 위치 ms·페이드인 구간·페이드아웃 시작 시각·다음 곡과의 겹침), 곡 이득(dB, ±`AUDIO_GAIN_LIMIT_DB`), 오래 머무르는 작품의 가까이 가기 표시, 전체 길이(교사 버튼 옆 "약 12분" 용). §6.13 규칙 전부: MUSIC/FIXED, 곡 없는 전시실 40초, 상한 360초, 최소 시간(이름판 + 작품당 5초)에 못 미치면 최소 시간을 쓰고 곡은 끝에서 페이드아웃 뒤 조용히, 나뉜 전시실은 곡 시간을 관 작품 수 비율로 나누고 관 사이에서 곡이 끊기지 않음, 페이드아웃 4초가 마지막 작품→문 통과 구간과 맞물림, 다음 곡은 이전 곡이 30% 아래로 줄어든 때 시작해 겹침 ≤ `TOUR_SONG_OVERLAP_SEC`. 카메라 경로·GSAP 타임라인·음량 곡선 실제 재생은 범위 밖(시간표만).
- `packages/core/src/domain/retention/index.ts`, `packages/core/src/domain/tour/index.ts` — 내보냄(`@gallery/core/retention`·`@gallery/core/tour`는 이미 `package.json`에 있음).
- 시험: 같은 폴더의 `*.test.ts`(Vitest, `fast-check` 사용 가능). PLAN §6.13 "시험(단위)" 줄 전부: 노래 5곡(150~180초)·곡 없는 전시실·나뉜 전시실·아주 짧은 곡에서 시간표 합계, 페이드아웃이 문 통과 구간을 덮는지, 겹침 ≤ 1초. 구간이 빈틈·겹침 없이 이어지는지(속성 시험). 보관: 경계 시각(정확히 만료 시각), 남은 시간이 설정보다 짧을 때 캐시 초, 음수 없음.

## 건드리지 말 것
`packages/core/src/config.ts`(필요한 키는 **보고**만 — Claude가 넣는다. 투어 키는 방금 더 넣었다: `TOUR_APPROACH_SEC`·`TOUR_LINGER_CLOSEUP_SCALE`·`TOUR_PATH_DISTANCE_SCALE`·`TOUR_HALL_FADE_IN_SEC`·`TOUR_EXIT_FADE_OUT_SEC`·`TOUR_NEXT_SONG_AT_LEVEL`), `packages/core/src/types/**`, `packages/core/package.json`, `domain/layout/**`(Claude가 고치는 중), `domain/classify/**`(다른 서브에이전트가 고치는 중), `apps/**`, `docs/**`, `.env*`, 다른 저장소. git 명령 금지. 새 의존성 금지.

## 끝 조건
1. `npx vitest run --project core --maxWorkers=1 packages/core/src/domain/retention packages/core/src/domain/tour` 통과(**자기 폴더 시험만** — 같은 시각 다른 에이전트가 이웃 폴더를 고치는 중이라 core 전체는 Claude가 마지막에 돌린다. 무거운 시험·e2e·빌드는 돌리지 않는다).
2. `npx tsc -b && npx tsc -p packages/core/tsconfig.test.json`에서 **자기 파일의 오류 0**(다른 에이전트 폴더의 오류만 남으면 고치지 말고 보고), `npx prettier --check packages/core/src/domain/retention packages/core/src/domain/tour` 통과.
3. 도메인 규칙: 외부 패키지·DOM·Node API·`Date.now()` 직접 호출 없음(시각은 인자로), 화면 문구 없음, 숫자는 설정 키에서.
