## 만들 것
1. `apps/server/src/upload/`(새 폴더): 본문을 읽기 전 검사(§9.4 0번: 인증 → 전시 경계·상태(지우는 중·만료 거절) → 속도 칸 → 동시 수신 칸(전시당·전체, 넘으면 `E_BUSY`) → `Content-Length` 필수·한도 → 공간 예약(×`UPLOAD_RESERVE_FACTOR`)), busboy로 `c.env.incoming`를 바로 받기(Hono 본문 파서 쓰지 않음, 파일 1·필드 1 `meta`·부분 3, `limit`·`truncated`·연결 끊김·`UPLOAD_IDLE_TIMEOUT_SEC` 무응답이면 임시 파일 지우고 예약 풀기, `TMP_DIR`에), `file-type` 매직 바이트 확인, 내용 해시 중복(`E_DUPLICATE`, 지운 작품과 같은 파일은 허용), 대기열(동시 `PROCESS_CONCURRENCY`, 대기 `PROCESS_QUEUE_MAX` 넘으면 `E_BUSY` 재시도 가능), 처리 → `MEDIA_DIR/exh/{exhibitionId}/{assetId}/`(임시 이름 → 이름 바꾸기) → 한 트랜잭션으로 asset·artwork 행 → `layout_dirty=1`, 실패는 작품 `FAILED` + 사유 코드·파일 정리.
   - 진행 중인 업로드를 전시별로 기다리거나 취소하는 손잡이를 둔다 — "지금 삭제"(`application/deleteExhibition.ts`, 이미 있음)가 쓰는 업로드 기다림 포트에 실제 구현으로 연결한다(지금은 빈 구현).
2. 경로(`apps/server/src/http/routes/teacher.ts`의 지금 multipart 거절 자리 + 새 경로):
   - `POST /api/teacher/exhibitions/{id}/artworks` multipart: 그림·HEIC·소리(`meta` JSON: id·roomId·order·title·kind). 처리 끝난 뒤 응답. 멱등(같은 작품 ID + 같은 요청 해시면 저장된 결과, 다르면 `E_CONFLICT`).
   - `PUT|DELETE /api/teacher/exhibitions/{id}/poster`, `PUT|DELETE /api/teacher/rooms/{roomId}/bgm`.
   - PDF 3단계: ① `POST …/{id}/artworks` JSON `{id, kind:'PDF', pageCount, …}` → `PROCESSING` ② `PUT /api/teacher/artworks/{aid}/pages/{i}`(1..n, 쪽마다 멱등, 순서 상관없음, 그림 처리 길) ③ `POST /api/teacher/artworks/{aid}/complete`(모든 쪽이 오면 `PUBLISHED`/설정대로, 빠지면 `E_VALIDATION`). 웹 어댑터의 실제 경로 이름을 따른다.
3. 의존성 묶기(`apps/server/src/deps.ts`)와 포트(`apps/server/src/ports/index.ts`)에 필요한 것만 더한다(바꾼 포트는 보고).
