## 만들 것
1. `apps/server/src/jobs/`(새 폴더):
   - **보관 정리**(60초마다): `deleting = 1` 또는 `expires_at <= now`인 전시마다 `deleteExhibition(deps, id)` — 실패(폴더 지우기 실패 `E_SERVER`)는 기록하고 다음 주기에 다시. 한 주기에 너무 많으면 나눠서.
   - **지운 작품 정리**(1시간마다): `deleted_at`이 `PURGE_DELETED_HOURS` 지난 작품의 파일(`exh/{exhibitionId}/{assetId}/`)과 행(쪽·반응 연쇄). 어느 작품·포스터·배경음악에도 붙지 않은 asset 2시간 지난 것. `TMP_DIR`의 1시간 지난 임시 파일·폴더(지금 받는 중인 업로드의 파일은 건드리지 않게 `apps/server/src/upload`의 관리자와 맞춘다).
   - 지운 뒤 `store.checkpoint()`(이미 있음). 기록은 개수만(§9.8 — 이름·별명·메모·PIN·토큰·IP 없음).
   - 작업은 겹쳐 돌지 않는다(앞 주기가 안 끝났으면 건너뜀). 끝내기(서버 종료) 때 진행 중인 주기를 기다리거나 멈출 수 있게.
2. 저장소 조회(포트 `apps/server/src/ports/index.ts`·SQLite `apps/server/src/store/repos.ts`·메모리 `apps/server/test/support/memoryStore.ts`): 정리 대상 전시 목록, 정리 대상 지운 작품, 붙지 않은 asset 목록·삭제. 인덱스가 필요하면 새 마이그레이션 파일(`0002_*.sql`, 앞으로만)로.
3. **보관 기간 시험 모드**: 개발에서만 `RETENTION_TEST_MINUTES`(환경 값, `apps/server/src/env.ts`)로 보관 기간을 분 단위로(PRD 15.6). 운영(`NODE_ENV=production`)에서 켜져 있으면 시작 거부(env 검증 오류).
4. 시작 코드(`apps/server/src/index.ts`): 앱이 듣기 시작한 뒤 작업 시작, 끝내기 순서에 작업 멈춤을 넣는다(지금 끝내기 순서를 지킨다).
5. 주기·나눔 같은 수치는 `packages/core/src/config.ts`에 이미 있는 것을 쓰고(`PURGE_DELETED_HOURS` 등), 없는 것(정리 주기 60초·1시간, 붙지 않은 asset 2시간, 임시 1시간, 한 주기 상한)은 **넣지 말고 보고** — Claude가 넣는다. 그동안은 작업 모듈 맨 위에 이름 붙인 상수로 두고 보고에 적는다.
