## 만들 것
1. **경로**(`react-router` 7은 이미 의존성에 있다):
   - `/` 첫 화면: 박물관 안내판 스타일, 숫자 6칸 + 키패드(`inputmode="numeric"`). 6자리가 차면 바로 `/{코드}`로 간다. 아래에 작은 글자 버튼 `선생님이세요?` → `/t`.
   - `/{6자리}` 학생 전시.
   - `/t/*`는 지연 로드(`React.lazy`) 자리 `apps/web/src/app/teacher/TeacherApp.tsx`. 빈 화면이고 P5에서 채운다. 교사 코드가 학생 묶음에 들어가지 않게 한다.
   - 그 밖의 주소는 `/`로 보낸다.
2. **기기 서비스 한 곳** `apps/web/src/app/services.ts`: `createHttp`·`createDeviceStore`·`createTokenTools`·`createApiClient`를 한 번만 만든다. `ui/`·`viewer/`는 `adapters/`를 가져오지 않는다. `app/`은 가져와도 된다.
3. **학생 전시 흐름** `apps/web/src/app/student/` (Zustand `visitorStore`, PLAN §7.2의 `phase`):
   - 불러오기: `api.student.exhibition(code)`. 오류마다 화면이 다르다.
     - `E_EXHIBITION_CLOSED`·`E_NOT_FOUND` → 막 내림 "이 전시는 막을 내렸어요" + `처음으로`
     - `E_EXHIBITION_DRAFT` → 준비 중 "아직 준비 중인 전시예요" + `처음으로`
     - `E_OFFLINE`·`E_SERVER` → 다시 시도 화면(문구는 `errorCopy`)
   - 불러오는 동안은 `LoadingMuseum`을 띄운다.
   - 포스터(`EntryPoster` 부품을 그대로 쓴다):
     - 전시 이름·한 줄 소개·학교·학급(있을 때)·"{날짜}까지 열려요"·작품 수를 보인다.
     - 포스터 그림 주소는 `mediaPath`(core)로 만든다. 없으면 부품의 기본 모습을 쓴다.
     - 별명은 선택이고 `NICKNAME_MAX_CHARS`까지 받는다. 캐릭터는 `student-m`·`student-f` 중에서 고른다.
     - 고른 캐릭터와 마지막 별명은 기기에 기억한다. 저장소를 고칠 수 없으면 `localStorage`를 try/catch로 감싸 쓰고 보고한다(DeviceStore 포트에 더하는 것은 Claude가 정함).
   - 관람 화면은 포스터 **뒤에 미리** `<VisitScreen entered={false} … onProgress>`로 띄운다. `ready` 전에는 입장 버튼을 잠그고 "준비하고 있어요" + 가는 진행 막대를 보인다(PLAN §7.3).
   - 입장(`onEnter`):
     - 별명을 적었으면 PRD 13.2 동의 시트를 띄운다. 공개 설정이 '모두에게'를 포함하거나 함께 관람 이름표로 보이므로 "다른 친구들도 볼 수 있어요" 판을 쓴다. `알겠어요` 체크 + `시작하기` → `api.student.registerVisitor(target, { nickname, consentVersion: CONSENT_VERSION })` → 관람(`entered={true}`).
     - 별명이 비었으면 동의 없이 바로 관람(익명). 함께 관람 토큰이 있어야 하므로, 기기에 방문자 토큰이 없으면 `tokens.newToken()`으로 만들어 `device.setVisitor(id, { token, consentVersion: null, nickname: null })`로 저장한다(서버 등록 없음, ADR-057 R-5).
     - 등록 실패: `E_MEMO_BLOCKED`·`E_VALIDATION`이면 칸 아래 문구. `E_OFFLINE`이면 별명 없이 들어가도 되게 하고 문구로 알린다.
   - `VisitScreen`에 넘기는 값: `view`, `code`, `character`, `liveToken`(위 토큰), `entered`, `onProgress`, `onHome`(→ `/`).
   - `rememberExhibition`으로 최근 전시를 기억한다(있는 포트를 그대로 쓴다).
   - 인앱 브라우저(카카오톡·네이버·인스타그램·페이스북·라인 UA) 감지 → `showInAppBrowserHint`. 판정은 순수 함수로 두고 시험한다.
4. **문구**: `packages/core/src/copy/ko.ts`에 새 묶음 `entry`(첫 화면)와 `consent`(PRD 13.2 그대로 + '모두에게' 판)만 더한다. 이미 있는 묶음(`poster`·`closed` 등)은 쓰기만 하고 고치지 않는다. 학생 문구에는 기술 낱말(서버·동기화·브라우저·업로드·오류 코드·에러)을 쓰지 않는다.
5. **모양**: CSS 모듈만 쓴다. 색·간격·모서리·글꼴은 `tokens.css`·테마 변수만 쓴다. 금지: 이모지·기본 `<select>`·`backdrop-filter`·UI 그라데이션·순검정. 터치 영역은 44px 이상이다. 휴대폰(390)·태블릿(820)·데스크톱(1440) 세 크기에서 넘침이 없어야 한다. 높이는 `100dvh`, 가장자리는 `safe-area`. 덮개는 한 번에 하나만 연다(동의 시트).

## 끝 조건
1. 단위 시험(jsdom): 경로 판정(6자리·그 밖)·인앱 UA 판정·학생 흐름의 상태 전이(불러오기 → 포스터/막 내림/준비 중/다시 시도, 입장 → 별명 있음=동의 → 등록 → 관람, 별명 없음=토큰 만들기 → 관람, 등록 실패 처리). API는 가짜 `ApiClient`를 쓴다. 새 시험은 고치기 전 코드에서 실패하는지 본다.
2. `npx vitest run --project web apps/web/src/app`, `npx tsc -b`, `npx tsc --noEmit -p apps/web/tsconfig.json`, `npx prettier --check apps/web/src/app packages/core/src/copy`, `node tools/check/index.mjs`가 모두 통과한다. 넓은 검사(전체 시험·e2e·빌드)는 돌리지 않는다. Claude가 끝에 한 번 돌린다.
3. 화면 확인: Playwright 헤드리스 스크립트를 scratchpad에 둔다(저장소에 넣지 않음). `page.route('**/api/e/**')`로 가짜 응답(합성 전시·합성 글만)을 주고 세 크기에서 첫 화면·포스터·동의 시트·막 내림·준비 중을 캡처해 `.local/p4-1/`에 둔다. 저장소의 `tests/e2e/`에는 넣지 않는다. 관람 화면 자리는 비어 보여도 된다.
