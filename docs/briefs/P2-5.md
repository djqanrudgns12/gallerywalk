## 고칠 파일(이것만)
- `packages/core/src/domain/reactions/visibility.ts`
  - `acceptedFields(settings) → {sticker, memo, score}`: 지금 설정이 받는 칸. 반응 꺼짐이면 모두 false.
  - `checkReaction(settings, body) → 'OK' | 'REACTIONS_OFF' | 'FIELD_NOT_ACCEPTED'`: 받지 않는 칸에 값이 있으면 거절(서버가 `E_REACTIONS_OFF`·`E_VALIDATION`으로 바꿈).
  - `publicSummary(settings, artworkId, reactions[]) → PublicReactionSummary`(`types/reaction.ts` 모양): 숨긴 반응 제외, 스티커 수는 `stickerVisibility === 'PUBLIC'`이고 받는 칸일 때만(0인 스티커는 칸 없음), 평가 평균은 `scoreVisibility === 'PUBLIC'`일 때만(소수 첫째 자리 반올림은 화면 몫 — 여기서는 원래 평균), 메모는 `memoVisibility === 'SELECTED'`이고 교사가 고른 것만, 별명 방식이면 별명·익명 방식이면 null. 메모 순서는 고른 시각이 아니라 반응 `updatedAt` 오름차순 + id(결정적). 공개 칸이 하나도 없으면 빈 집계.
  - 반응 입력 모양은 `{sticker, memo, scoreFact, scoreDelivery, hidden, publicSelected, nickname, updatedAt, id}`를 받는 도메인 타입으로 정의(DB 행이 아님).
- `packages/core/src/domain/reactions/profanity.ts` — PLAN §11.6: 정규화(NFKC → 소문자 → 공백·특수문자 제거 → 반복 글자 줄이기 → 한글 초성 변형 비교). `isBlocked(text, list = DEFAULT_LIST)`. **목록은 최소로**(흔한 욕설·비하어 수십 개 + 초성 변형), 목록만 따로 `profanityList.ts`에. 우회(띄어쓰기·점·숫자 끼우기·반복)를 잡되, 평범한 낱말이 걸리지 않게(예: "시발점", "개나리", "수박씨" 같은 낱말 — 짧은 목록 항목이 긴 정상 낱말 안에서 걸리는지 시험으로 확인하고 필요하면 예외 목록).
- `packages/core/src/domain/reactions/nickname.ts` — `prepareNickname(raw) → {display, norm} | {error: 'empty' | 'too_long' | 'blocked'}`: 표시용은 `types/text.ts`와 같은 한 줄 정규화(NFC·공백 정리), 비교용 `norm`은 NFKC·소문자·공백 제거(같은 전시 안 같은 별명 판단은 서버가 `norm`으로). 길이는 `NICKNAME_MAX_CHARS`(코드 포인트). 욕설이면 `blocked`.
- `packages/core/src/domain/reactions/index.ts` — 내보냄. `packages/core/package.json` exports에 `"./reactions"`는 **Claude가 넣는다**(보고에 적기만).
- 시험: 같은 폴더 `*.test.ts`(Vitest, fast-check). **실제 욕설을 시험 파일에 쓰지 않는다** — `isBlocked(text, ['가짜욕', '나쁜말'])`처럼 가상 목록을 넣어 정규화·우회·초성·예외를 시험하고, 기본 목록은 "비어 있지 않음·모두 정규화된 모양"만 확인. 공개 규칙은 설정 조합 전부(스티커·메모·별점 × 공개 여부 × 이름 방식 × 반응 켬/끔)를 속성 시험으로.
