## 0. 읽는 법

- PRD는 **무엇을**, 이 문서는 **어떻게**를 정한다. 둘이 어긋나면 PRD가 맞다. 단, PRD의 `[추천]`을 바꾼 곳은 ADR에 이유가 있고 이 문서가 그 결정을 따른다.
- 수치는 모두 `packages/core/src/config.ts` 한 곳의 키로 둔다(§17). 이 문서에 적은 수치는 기본값이다.
- 각 절 끝의 "시험"은 그 절을 끝냈다고 말할 수 있는 최소 조건이다. phase 끝 조건은 §15.
- 사용자 결정(U-xx)이 나오기 전에는 **임시 기본값**으로 만들고, 바뀌어도 구조가 바뀌지 않도록 설정이나 포트 뒤에 둔다.

## 2. 아키텍처

### 2.1 실행 구성 (ADR-001·002·003·004)

```
학생 태블릿 · 교사 PC/태블릿 · 프로젝터 PC
        │ HTTPS  gallery.ssamuniverse.com   (주소·앞단은 U-01, 기본값 이 구성)
        ▼
CloudFront 서울(ICN) ── 캐시 행동
        │   /assets/*            : 1년, 해시 이름(바뀌지 않음) — 갤러리 것은 모두 /assets/g/ 아래(앱·템플릿 3D)
        │   /assets/g/m/*        : 작품 미디어. CDN 최대 1일, 브라우저는 남은 보관 기간 이하 (ADR-028)
        │   /api/* 그 밖        : 캐시 안 함, 모든 메서드
        │   viewer-request 함수: Host가 gallery면 갤러리 원본 선택 + 시청자 IP를 x-gw-viewer-ip로 넣음
        │   원본 비밀 머리 x-gw-origin-auth
        ▼
Cloudflare (DNS · WAF가 원본 비밀 머리 확인) → Cloudflare Tunnel(이 앱 전용)
        ▼
맥미니 · gallerywalk 서버 (Node 24 · Hono · 포트 4520 · launchd 데몬 · 전용 서비스 계정 · 터널 메트릭 20243)
        ├─ /api/*     JSON API (§9)
        ├─ /assets/g/m/*   작품 파생 파일 (디스크, Range 지원)
        ├─ /assets/g/* · /*   웹 앱 정적 파일(dist) · 템플릿 3D 에셋
        ├─ data/gallery.sqlite   SQLite(WAL) 파일 하나 (§10)
        ├─ media/exh/{exhibitionId}/…   작품 파일 (§10.3)
        └─ 작업: 처리 대기열(sharp, 동시 1) · 보관 정리(60초) · 지운 작품 파일 정리(1시간)
```

- 실시간 연결(웹소켓)은 없다. 학생 화면은 60초마다·화면 복귀 때 버전만 확인한다(ADR-027).
- 무료 원칙: 맥미니는 이미 있는 서버, CloudFront는 무료 요금제, Cloudflare는 무료 플랜. 새 유료 항목 없음.
- **CloudFront (ADR-002)**: 계정당 Free 요금제 3개(늘릴 수 없음)가 쌤유니버스(`E1VKUXOJAO8KBE`)·rollingthunder(`E3DFFMH3173961`)·글방(`E3TFCRGRU1HG1Q`, 2026-11-11)으로 모두 찼다. 기본안은 **글방 배포를 "쌤유 앱 공용 입구"로 함께 쓰는 것**: 그 배포에 `gallery.ssamuniverse.com`을 대체 도메인으로 붙이고, viewer-request 함수(런타임 2.0)가 Host를 보고 갤러리 원본을 고른다(`cf.selectRequestOriginById`). 무료 요금제는 **관리형 캐시·원본 요청 정책만** 쓸 수 있어(직접 만든 정책은 Business 이상) 두 가지로 푼다: ① 캐시 키에 Host를 넣는 대신 갤러리의 캐시할 파일을 모두 **고유 경로 `/assets/g/`** 아래에 둬서 글방 파일과 경로가 겹치지 않게 하고(글방 배포의 기존 `/assets/*` 동작·CachingOptimized를 그대로 씀, 동작 추가 0), ② 시청자 IP는 함수가 `event.viewer.ip`를 `x-gw-viewer-ip`로 넣는다. 무료 요금제는 한도를 넘어도 **추가 요금이 없다**(속도 조정만 가능). 사용자 채택(2026-11-11). 다른 앱 설정을 바꾸는 일이라 실제 콘솔 작업은 P7-2에서 사용자와 함께.
- 앞단은 코드가 아니라 **설정 문제**다. 서버는 앞단을 모른다. 공용 입구에서 막히는 것이 나오면 Cloudflare 직접 등으로 바꿔도 코드는 그대로다(ADR-002 대안 표).

### 2.3 주요 흐름

**학생 입장 (G-01, G-08)**
1. QR → `/{입장코드6자리}` → 앱 껍데기(서비스 워커가 있으면 즉시) → `GET /api/e/{code}` (전시·배치·작품 목록·공개 반응, §9.2).
2. 포스터 화면이 뜨는 즉시 미리 불러오기 시작: 템플릿 핵심 에셋 → 첫 전시실 썸네일 전부 → 첫 전시실 벽용 이미지 2장(대표작·첫 작품, §2.5 예산).
3. `입장하기` 누름 = 소리 잠금 해제(§8.3) + 입장 연출(1.6초). 연출이 도는 동안 남은 첫 방 에셋을 받는다. 첫 방 핵심이 준비 안 됐으면 포스터에 진행률이 보이고 버튼은 준비되는 순간 열린다(8.2 "첫 전시실이 준비되면 바로 입장").

**작품 올리기 (G-10, ADR-005·039)**
1. 교사 기기: 폴더·파일 받기 → 폴더 규칙(§5.2)으로 전시실·제목·순서 추정 → 기기 사전 검사(§5.3) → 막히면 카드에 한 줄 사유.
2. 통과한 것만 형식별로 보냄: 그림·HEIC 원본 / PDF는 쪽 그림으로 바꿔서 / 글은 JSON / 소리 원본.
3. 서버: 스트리밍으로 임시 저장 → 매직 바이트·크기 재확인 → 처리 대기열(동시 1) → (HEIC면 macOS `sips`로 JPEG) → sharp로 정규화·파생·분석(§5.4) → 임시 파일 삭제 → 작품 행 갱신 → 배치 "다시 계산 필요" 표시 → 응답(처리 끝난 뒤 돌려줌, 보통 0.3~1.5초).
4. 교사 화면: 카드에 올리기 진행률 → "다듬는 중" → 결과 한 줄(6.9). 미리 보기는 기기에서 같은 엔진으로 즉시 다시 계산.

**배치 다시 계산 (G-13, ADR-026)**
- 게시·숨김·순서·전시실·대표작·템플릿·전시실 추가/삭제가 바뀌면 서버가 `layout_dirty=1`.
- 누군가 배치를 읽을 때(교사 미리 보기 동기화, 학생 입장, 버전 확인) dirty면 그 자리에서 계산(100점 기준 50ms 이하) → 결과 해시가 이전과 다를 때만 `layout_version`을 올림.
- 교사 화면은 같은 `computeLayout`을 기기에서 돌려 즉시 보여 준다. 같은 판의 같은 함수라 결과가 같다(§4.10).

**반응 (G-07)**: 줌 → `반응 남기기` → (별명 방식이고 처음이면) 별명·동의 → 시트 → `PUT /api/e/{code}/reactions/{artworkId}`(기기 ID 헤더, 멱등). 학생 화면은 서버가 공개 설정대로 걸러 준 것만 받는다.

**보관 정리 (G-18)**: 60초마다 `expires_at <= now` 전시를 한 트랜잭션으로 지우고(연쇄 삭제), 그 전시 폴더를 지우고, 개수만 기록.

### 2.4 층과 포트


### 2.5 성능 예산 (PRD 10장, ADR-015·036)

**첫 관람까지 내려받는 양** (PRD 6MB 상한 안에서 다시 나눔)

| 묶음 | 목표 | 내용 |
|---|---|---|
| 앱 JS·CSS (gzip) | ≤ 450KB | React·three·R3F·GSAP·관람 화면. 교사 화면·pdf.js·QR·dnd는 따로 나눠 학생은 받지 않음 |
| 글꼴 | ≤ 300KB | Pretendard 동적 부분집합 + 템플릿 세리프 부분집합(쓰는 글자만, unicode-range) |
| 템플릿 핵심 | ≤ 2.5MB | 모듈 glTF(meshopt) + KTX2 질감 + 환경맵 + 빛 웅덩이 |
| 첫 전시실 | ≤ 1.2MB | 썸네일 전부(≤40KB×12 = 0.48MB) + 벽용 2장(대표작·첫 작품, ≤300KB×2) = 1.08MB |
| **합계** | **≤ 4.5MB** | 나머지 벽용 이미지는 입장 연출·이동 중 뒤에서 |

- 근거: 21대 × 6MB = 126MB를 학교 와이파이 100Mbps로 받으면 약 10초다. 4초 목표를 맞추려면 (1) 포스터 화면에 머무는 동안 미리 받고 (2) 첫 화면에 꼭 필요한 양을 줄이고 (3) 두 번째부터는 서비스 워커가 바로 연다. 실측(P6-5)으로 조정한다.
- 배경음악은 이 예산 밖이다. 미리 받지 않고(`preload="none"`) `입장하기` 순간 스트리밍으로 시작한다.

**GPU 메모리** (태블릿 256MB 이하, PRD 10.1)

| 항목 | 높음 | 보통 | 낮음 | 계산 |
|---|---|---|---|---|
| 그리기 버퍼(색+깊이, MSAA 없음) | ≈ 57MB | ≈ 40MB | ≈ 25MB | iPad 2048×1536 × 배율² × 8B |
| 템플릿 질감(KTX2 → ASTC/ETC2/BC) | ≈ 35MB | ≈ 35MB | ≈ 20MB | 2K 6장 + 밉맵. 낮음은 1K |
| 작품 벽용 상주 | ≤ 10장 ≈ 96MB | ≤ 6장 ≈ 58MB | ≤ 4장(1024) ≈ 16MB | 1600×1130×4B×1.33 ≈ 9.6MB/장 |
| 작품 썸네일 | 보이는 방 전부 ≈ 40MB | ≈ 30MB | 현재 방 ≈ 13MB | 512px ≈ 1.1MB/장 |
| **합계** | **≈ 230MB** | **≈ 165MB** | **≈ 75MB** | |

- PRD 10.4 "높음: 벽용 1600px, 앞뒤 1개 전시실"을 그대로 하면 약 330MB로 예산을 넘는다(C5). 그래서 **벽용 이미지는 지금 정지 지점 앞뒤 몇 칸에만 올리고 나머지는 썸네일**로 둔다(§6.5 상주 관리자).
- MSAA는 화면 배율 1.5 미만일 때만 켠다(배율이 높으면 그 자체로 계단이 줄고, MSAA 4배는 버퍼를 4배로 키운다).

**그리기**: 화면당 그리기 호출 ≤ 100(목표 60), 보이는 삼각형 ≤ 30만, 정지 상태에서는 다시 그리지 않음(`frameloop="demand"`), 실시간 조명 ≤ 2, 실시간 그림자·반사·피사계 심도 없음.

| 내려받는 것 | 실측 | 언제 |
|---|---|---|
| 외관 조각 `exterior.glb` | 1,008KB | 광장 첫 화면(먼저 받음) |

### 4.3 전시실 나누기 (`split.ts`, ADR-022)

- 전시실 하나의 게시 작품 수 n이 `ROOM_SPLIT_AT`(12)을 넘으면 관 수 k = ⌈n/12⌉, **고르게** 나눈다: 기본 ⌊n/k⌋개, 앞의 (n mod k)개 관이 하나씩 더(13 → 7·6, 30 → 10·10·10). 순서는 유지한다. §4.4-3의 크기 올리기로 다시 나눌 때도 같은 규칙.
- 대표작은 전시실마다 하나다(DB 부분 유니크 색인, §10.2). 지정 대표작이 들어간 관은 그것을, 나머지 관은 자동 대표작을 대표 벽에 건다.
- **자동 대표작**(지정이 없을 때, PRD "가장 큰 작품"을 구체화): 관의 작품 m개를 순서대로 0..m−1로 놓고, 후보 = 색인 ⌊m/3⌋ ~ max(⌊m/3⌋, ⌈2m/3⌉−1)(m=1 → 0, 2 → 0~1, 3 → 1, 4 → 1~2, 12 → 4~7). 후보 중 기준 크기 바깥 면적이 가장 큰 것, 같으면 `order`가 작은 것, 그래도 같으면 `id` 사전순. 소리 명판은 후보에서 빼고, 후보가 모두 소리면 첫 후보. 가운데에서 고르는 이유는 §4.4의 순서 보존 때문이다(Antigravity 지적).
- 관 이름: `{이름판} · 1관`. 배경음악은 원래 전시실 것을 이어서 튼다(관이 바뀌어도 곡이 다시 시작하지 않음).
- 비어 있는 전시실(게시 0)은 동선에서 빠진다(G-12).

### 4.4 방 크기 고르기 (`roomSizing.ts`)

**논리 좌표계**: 모든 관은 같은 좌표계에서 계산한다. 아래 = 들어온 벽 **N**(문 2개), 위 = 대표 벽 **F**, 왼쪽 = 걷는 순서의 첫 옆벽 **L**, 오른쪽 = 둘째 옆벽 **R**. x는 L(0) → R(W), y는 N(0) → F(D). 들어가는 문은 N의 L 쪽 끝, 나오는 문은 R 쪽 끝. 회랑 왼쪽 관의 거울상은 세계 좌표로 옮길 때만 생긴다(§4.6). 그래서 규칙은 하나다.

| 크기 | n(대표 포함) | 거는 벽과 순서 | 작품 없는 면 채우기 |
|---|---|---|---|
| S | 1~4 | L(대표 앞 작품) → F(대표, 그 오른쪽에 대표 뒤 작품) | R: 소개 글판 |
| M | 5~8 | L(앞) → F(대표) → R(뒤) | N 안쪽: 벤치 |
| L | 9~12 | L(앞) → F(대표) → R(뒤의 앞쪽 ⌈b/2⌉) → N(뒤의 나머지, 문 사이) | 가운데 벤치 |

계산:
1. **순서 보존**: 대표작의 관 안 색인 f. 앞 작품(0..f−1)은 L, 뒤 작품(f+1..m−1, b개)은 위 표의 자리. **순서는 바꾸지 않는다**(한쪽이 길어도 작품을 반대편으로 넘기지 않음 — 순서 보존과 부딪치는 균형 규칙은 버림, Codex 지적). 한쪽이 짧아 생긴 빈 공간은 6번이 채운다.
2. 벽 필요 길이 len = Σ바깥 폭 + `FRAME_GAP_MIN_M`×(개수−1) + `CORNER_MARGIN_M`×2. N은 여기에 문 2×2m + `DOOR_MARGIN_M`×4. 작품이 없는 벽의 len = 0.
3. **크기 올리기**: 어느 벽이든 len > `WALL_MAX_LEN_M`(16m)이면 S → M → L로 한 단계 올려 1번부터 다시(최대 두 번). L에서도 넘으면 그 관을 §4.3 규칙으로 둘로 나눠 각각 처음부터. 나눌 때마다 관의 작품 수가 줄어 반드시 끝난다(작품 1점의 바깥 폭은 3.66m를 넘지 않음 — 파노라마 2.4m × 대표 1.3배 + 매트 2×0.196 + 테 2×0.07 = 3.652m, 16m 벽에 늘 들어감).
4. 치수: W = max(len(F), len(N)(L 크기만), `ROOM_MIN_W_M` 8m — 문 2개가 들어가는 최소), D = max(len(L), len(R), `ROOM_MIN_D_M` 6m). 둘 다 2m 단위로 올림. D/W > 2면 W를 2m씩 늘린다(작품은 옮기지 않음).
5. 벽 안 배치: 1.2m 여백을 최소로 두고 남는 길이를 작품 사이·양끝에 **고르게** 나눠 가운데 정렬. M·L의 F는 대표작 하나를 가운데에. S의 F는 [대표, 뒤 작품들]을 한 줄로 가운데 정렬.
6. 빈 면 채우기: 작품이 없는 면마다 순서대로 소개 글판(관마다 하나) → 벤치 → 화분. 시험: "작품도 설비도 없는 벽 면 ≤ 1"(PRD 15.2).

- 소리 작품만 있는 전시실: S 크기, 소리 명판을 L에 고르게.
- 소리 명판은 작품 하나로 센다(바깥 폭 0.5m).

### 4.5 벽 자리 (`wallPlacement.ts`)

- 걷는 순서(논리 좌표): L(N 쪽 → F 쪽) → F(L 쪽 → R 쪽) → R(F 쪽 → N 쪽) → N(R 쪽 끝 → L 쪽 끝, 문 사이). 논리 좌표에서 시계 방향 = PRD 5.3 "입구 왼쪽 벽부터 시계 방향". 회랑 왼쪽 관은 세계 좌표에서 거울상이 되어 반시계로 걷게 되고, 그래서 방을 나와 늘 회랑 진행 방향으로 이어진다(ADR-021).
- L 크기의 N 벽 작품을 본 뒤에는 방을 가로질러 나오는 문으로 간다(볼록한 직사각형 방이라 직선 경로가 벽을 뚫지 않음).
- 액자 한가운데 높이 1.5m. 긴 세로(높이 1.8m)는 바닥에서 0.6m 띄워 한가운데 1.5m를 지킨다. 높이 2.6m를 넘는 바깥 크기는 1.5m 대신 아래 끝 0.4m로 맞춘다.
- 명판(작품 옆 작은 라벨): 액자의 걷는 방향 뒤쪽 0.15m, 높이 1.3m.

### 4.6 템플릿 문법 (`grammar/*.ts`)

공통 출력: 입구 홀, 관들의 배치(위치·방향·문), 연결 통로, 출구 벽. **v1은 근대 역사관만 구현**하고 나머지는 같은 인터페이스로 v1.1에 더한다.

**근대 역사관 (`modernHistory.ts`)**
- 세계 좌표(three: X 오른쪽, Y 위). 입구 홀 10×8m(고정 모듈 묶음)는 z < 0, 정면에 전시 이름 사인. 회랑은 중심선 x = 0, 폭 `CORRIDOR_WIDTH_M`(4m), 홀 출구 z = 0에서 +Z로 뻗는다.
- 관 i(0부터)는 짝수 = 오른쪽(+X), 홀수 = 왼쪽(−X). 회랑 쪽 시작 z_i = max(끝[같은 쪽] + `PART_GAP_M`(2m), z_{i−1} + `PART_STAGGER_M`(4m)), z_0 = 2m, 끝[그 쪽] = z_i + W_i. 같은 쪽 관은 겹치지 않고, 다음 관 입구는 늘 앞 관 입구보다 하류에 온다.
- 논리 → 세계: 오른쪽 관 (X, Z) = (2 + y, z_i + x), 왼쪽 관 (X, Z) = (−2 − y, z_i + x). 둘 다 L 쪽(x = 0)과 들어가는 문이 회랑 상류에 온다. 왼쪽 관은 X축 대칭이라 거울상이 저절로 생긴다.
- 회랑 길이 = max(끝[오른쪽], 끝[왼쪽]) + 4m(출구 앞 공간), 2m 단위. 회랑 벽은 관 문이 없는 구간을 2m 조각으로 채운다(관 폭이 2m 배수라 맞음). 관이 없는 면에는 다음 관의 이름판을 그 관 문 옆 회랑 벽에(멀리서도 다음 전시실이 보이게).
- 마지막에 출구 벽(감사 문구 사인 + 작품 수, PRD 5.5).
- 전시실이 많아지면 회랑이 길어진다(PRD 5.4). 100점 = 10관이면 회랑 약 60m — 그리는 범위는 §6.6이 막는다.

**v1.1 문법 요약**(모두 같은 출력 형식): 한옥 = ㅁ자 마당 회랑에 관 4개, 넘치면 두 번째 마당(빈 칸은 정원 창호·안내 벽 조각) / 화이트 큐브 = 관과 관을 문으로 한 줄(앙필라드), 넘치면 ㄹ자로 꺾음 / 클래식 = 원형 홀 둘레 방 최대 6, 넘치면 두 번째 홀 / 별빛 = 원 둘레, 넘치면 나선 바깥 한 바퀴.

### 4.7 정지 지점과 화면 맞춤 (`stops.ts`, `framing.ts`)

| 정지 지점 | 만드는 곳 | anchor |
|---|---|---|
| 입구 홀 | 홀 입구 안쪽 1.5m | 전시 이름 사인 |
| 전시실 소개 | 들어가는 문 안쪽 1.2m | 대표 벽 한가운데(이름판 받침은 들어가는 문 옆 L 쪽에 두어 앞쪽에 함께 보임) |
| 작품 | 작품마다 하나 | 액자 바깥 사각형 + 벽 법선 |
| 출구 | 출구 벽 앞 | 출구 사인 |

- **"다음 전시실 문"은 정지 지점이 아니다**(ADR-020). 관의 마지막 작품에서 `›` = 문을 지나 다음 관 소개까지 한 번에(1.6~2.2초).
- 위치 표시: 작품 정지 = `{관 이름} · {관 안 작품 번호}/{관 작품 수}`, 소개 = `{관 이름} · 소개`, 홀·출구 = 전시 이름.
- **화면 맞춤**(`framing.ts`, 기기에서)
  1. 물러설 수 있는 거리 maxD = 그 벽에서 법선 방향 맞은편 벽까지 거리 − `CAMERA_WALL_CLEARANCE_M`(0.4m). 논리 좌표로 F·N 벽 작품은 D, L·R 벽 작품은 W(방 깊이가 아니라 그 벽 앞 공간, Codex 지적). 홀·회랑은 템플릿 고정값.
  2. vfov `VFOV_DEG`(50°)에서 거리 d = max(바깥 높이 / (2·tan(vfov/2)·`STOP_FILL`), 바깥 폭 / (2·tan(hfov/2)·0.80)). 캡션이 차지하는 자리는 화면에서 빼고 계산한다.
  3. d > maxD면 화각을 넓혀 맞춘다(상한 `VFOV_MAX_DEG` 65°, 크게 넓히면 가장자리 액자가 찌그러짐 — Antigravity 지적).
  4. 그래도 넘으면 d = maxD로 두고 채움이 0.55보다 작아지는 것을 받아들인다(액자가 조금 작게 보일 뿐 잘리지 않음). 줌(채움 `ZOOM_FILL` 0.85)도 같은 규칙.
- 휴대폰 세로(PRD 9.5): 액자가 화면 위쪽 2/3에 오도록 카메라 목표점을 아래로 내린다(캡션 시트 자리).

### 4.8 이동 경로 (`paths.ts`, 기기에서)

- 같은 관 안: 직선(볼록한 직사각형 방이라 벽을 뚫지 않음) + 시선은 두 목표점 사이를 구면 보간. 시간 = 0.9 + 0.12×거리(m), 0.9~1.4초.
- 관 사이: 경로점 = 나오는 문 안쪽 1.2m → 문 중심 → 문 밖 1.2m → 회랑 중심선 → (다음 관 들어가는 문 앞) 회랑 중심선 → 문 밖 1.2m → 문 중심 → 문 안쪽 1.2m → 소개 정지 지점. **꺾은선의 꺾이는 곳을 반지름 ≤ min(`PATH_FILLET_MAX_M` 0.8m, 이웃 선분 길이의 40%) 원호로 둥글린다.** Catmull-Rom은 경로점이 안전해도 곡선이 바깥으로 부풀어 벽을 지날 수 있어 쓰지 않는다(Codex 지적). 시간 = 1.6 + 0.04×거리, 상한 2.2초.
- **안전 검사** `pathClear(path, layout)`: 0.1m마다 표본을 뽑아 걸을 수 있는 영역(관 안쪽·회랑·홀·문 구간, 벽에서 0.3m 안쪽) 안인지 본다. 배치 엔진 시험이 모든 이웃 정지 지점 쌍을 확인하고(§4.11), 실행 중 실패하면 0.3초 어둡게 바꿔 옮긴다. 먼 곳으로 가기(모아 보기·지도)는 경로 없이 같은 페이드(§6.7).
- 시선: 이동 방향의 0.6배 + 도착 목표의 0.4배를 섞어 "걸으며 고개를 돌리는" 느낌(8.2), 마지막 30%에서 도착 목표로 수렴.
- 호 길이로 속도를 고르게. 출발 가속 짧게·도착 감속 길게: `cubic-bezier(0.45, 0, 0.15, 1)`.

### 4.9 지도 데이터 (`map.ts`, ADR-018)

- 관 다각형·회랑·홀·문 위치·이름 자리를 2D로 투영해 낸다. 화면은 템플릿 지도 스타일(종이 질감 배경 그림 + 선 굵기·글꼴 토큰)로 SVG를 그린다. 전시마다 평면이 달라 정적 그림 한 장으로는 지도를 만들 수 없다(C11).

### 4.10 결정성

- 입력은 (`order`, `id`)로 정렬해서 쓴다. 객체 키 순서에 기대지 않는다.
- 난수는 `rng.ts`(mulberry32, 시드 = exhibitionId의 FNV-1a)만. 소품 종류·화분 위치처럼 꾸미는 데만 쓴다.
- 좌표는 1mm(소수 셋째 자리)로 반올림해 저장한다. 서버(Node)와 기기(Safari·Chrome)의 부동소수 끝자리 차이를 없앤다.
- 해시: 출력을 정규 JSON(키 사전순, 숫자는 소수 셋째 자리 고정 문자열, `hash` 칸 제외)으로 만든 뒤 SHA-256 앞 16자.
- 선택마다 동률 규칙이 있다: 정렬 (`order`, `id`), 자동 대표작(§4.3), 나누기(앞 관이 하나 더), 문 위치(L 쪽이 들어가는 문), 꾸밈 난수(시드 고정).
- 엔진을 바꾸면 `algoVersion`을 올린다. 저장된 배치는 다시 계산하지 않고, 그 전시에 다음 변경이 생길 때 새 판으로 계산한다(열린 전시가 수업 중에 갑자기 바뀌지 않게).

### 4.11 시험 (`layout/*.test.ts`)

- 관 작품 수 1·4·5·8·9·12·13·30, 전시 100점: 크기(S·M·L·분할), 액자끼리·문·모서리 겹침 없음, 모든 액자가 벽 안, 여백 ≥ 1.2m, 빈 벽 ≤ 1면, 정지 지점 수 = 홀 + 관마다 소개 + 작품 수 + 출구.
- 결정성: 같은 입력 두 번 → 해시 같음. 입력 배열 순서를 섞어도 같음. 다른 exhibitionId → 꾸밈만 다르고 액자 위치는 같음.
- 런타임 간 같음: 고정 입력 20개의 해시를 Node(Vitest)와 Chromium·WebKit(Playwright)에서 계산해 비교.
- 경로: 모든 이웃 정지 지점 쌍이 `pathClear`를 통과. 크기 올리기·나누기가 끝남(작품 1~200점 무작위).
- 회랑: 같은 쪽 관이 겹치지 않고, 관 입구 z가 순서대로 늘어남.
- 속성 시험(무작위 입력 500개, 시드 고정): 위 불변식이 모두 참.
- 스냅샷: 대표 사례 6개의 지도 SVG(사람이 한 번 보고 승인).

## 5. 작품 판정기와 처리 (PRD 6장, ADR-005·006·007)

### 5.1 나눠 맡기

| 단계 | 어디서 | 왜 |
|---|---|---|
| 형식·크기·그림 치수·PDF 쪽 수·글 길이·소리 길이 사전 검사 | 교사 기기 | 올리기 전에 바로 알려 주고, 학교 업로드 대역을 아낀다 |
| PDF → 쪽 그림, 글 붙여넣기 | 교사 기기(pdf.js) | PDF 원본(메타데이터·글꼴 포함)을 서버에 남기지 않는다 |
| HEIC → JPEG | 서버(macOS 기본 `sips`) | sharp 기본 바이너리는 HEIC를 못 읽고(F-5), Chrome·Edge·Samsung Internet도 못 읽는다(F-4). 맥미니에 이미 있는 Apple 코덱을 쓴다 |
| 회전 반영·메타데이터 제거·sRGB·파생 이미지·띠 조각·분석값 | 서버(sharp/libvips) | 큰 그림(웹툰 2만 px)도 기기 캔버스·메모리 한도 없이 처리하고, 모든 기기에서 같은 품질. Safari는 WebP 인코딩이 안 되고 PNG로 바뀐다(F-1) |
| 쪽 나눔 계획 | 학생 기기(보는 순간) | 기기 화면마다 결과가 달라야 한다(PRD 6.7) |

- **원본은 저장하지 않는다.** 서버가 다시 인코딩한 파일만 남는다. 그래서 위치 정보 등 메타데이터가 어디에도 남지 않는다(C17).

### 5.2 폴더 규칙 (`classify/folderRules.ts`, G-10)

- 받은 항목을 경로로 묶는다. 맨 위 폴더 하나만 올렸으면 그 아래 하위 폴더 = 전시실. 하위 폴더가 없으면 그 폴더 = 전시실 하나. 파일만 올리면 지금 고른 전시실(없으면 `전시실 1`).
- 2단계보다 깊은 폴더는 가장 가까운 전시실 폴더에 합친다. 숨김·시스템 파일(`.DS_Store`, `Thumbs.db`, `._*`, `desktop.ini`)은 조용히 버린다.
- 이름 정리(`titleFromName.ts`): 확장자 제거 → 앞번호(`^\d+(?:[\s._-]+(?!\d)|$)` — 구분자가 있어야 지우고 `3.1운동`·`2.5D`처럼 구분자 뒤가 숫자면 남김, `3학년`·`5월`도 남음, P2-2에서 고침) 제거 → `_`·`-`를 띄어쓰기로 → 연속 공백 하나 → 앞뒤 공백 제거 → 작품 제목 60자·이름판 30자로 자름. 결과가 비면 `제목 없는 작품`(점검 줄에 표시).
  - PRD 예시 "1905_을사늑약과의병 → 1905 을사늑약과 의병"의 **"을사늑약과 의병" 띄어쓰기는 규칙으로 만들 수 없다**(단어 경계 정보 없음). 규칙 결과는 "1905 을사늑약과의병"이고 교사가 칩에서 고친다(B4).
  - 폴더 이름의 앞번호는 정렬에만 쓰고 이름판에서는 지우되, 연도처럼 4자리이고 뒤에 글자가 이어지면 남긴다(`1905_…` → "1905 …").
- 순서: 자연 정렬(`2` < `10`), 같은 숫자면 한국어 정렬(`Intl.Collator('ko', {numeric:true})`).
- 소리: 전시실 폴더 안 소리 파일이 하나면 배경음악, 여럿이면 이름순 첫 번째가 배경음악·나머지는 소리 작품.
- 같은 파일이 두 번 들어오면(내용 해시 같음) 두 번째는 "이미 올린 작품이에요" 카드로 표시하고 올리지 않는다.
- 폴더 받기: 데스크톱 브라우저의 폴더 끌어 놓기(`webkitGetAsEntry`)·폴더 선택(`webkitdirectory`). iPad·휴대폰은 파일 여러 장 선택만(R6, 실기기에서 폴더 끌어 놓기가 되면 켬).

### 5.3 기기 사전 검사 (`upload/precheck.ts`, PRD 6.3)

| 검사 | 방법 | 막힘/경고 |
|---|---|---|
| 형식 | 확장자 + 첫 바이트(PNG·JPEG·WebP·GIF·HEIC·PDF·MP3·M4A·WAV·TXT) | 영상 → "아직 영상은 전시할 수 없어요"(G-23), SVG·그 밖 → 받지 않음 |
| 그림 치수 | 헤더만 읽음(전체 디코드 안 함) | 짧은 변 < 300px 막힘, < 800px 경고 |
| 비율 | 긴 변 ÷ 짧은 변 > 30 | 막힘 |
| 크기 | 그림·문서 25MB, 소리 20MB | 막힘 |
| PDF | pdf.js로 쪽 수만 | 30쪽 초과 막힘 |
| 글 | 글자 수(공백 포함, 줄바꿈 정규화) | 5,000자 초과 막힘 |
| 소리 | 미디어 요소로 길이 | 10분 초과 막힘 |
| 깨짐 | 위 단계에서 읽기 실패 | "파일을 열 수 없어요" |

- HEIC: 기기에서는 형식·크기만 보고 그대로 올린다(치수 검사는 서버). 서버가 `sips -s format jpeg`로 바꾼 뒤 같은 길로 처리한다. 변환이 안 되는 환경(맥이 아닌 서버)이면 `E_HEIC_UNSUPPORTED` "JPG로 다시 올려 주세요". iOS 파일 선택이 늘 JPEG로 바꿔 주지는 않는다(F-4).
- PDF(`pdfPages.worker.ts`): pdf.js 6.5로 쪽마다 긴 변 2400px로 렌더 → JPEG(0.92) Blob → 쪽 그림으로 올림(쪽 i/n). PNG면 쪽당 2~6MB라 30쪽이 학교 와이파이로 최대 180MB가 된다. JPEG는 모든 브라우저가 인코딩하고 서버가 다시 WebP로 만든다. 한글 글꼴이 깨지지 않게 CMap·표준 글꼴 파일을 함께 배포하고(`cMapUrl`, `standardFontDataUrl`) 한 쪽씩 차례로 렌더한다. renderer worker(6.5 새 기능)는 Chrome에서만 켜고 Safari는 메인 스레드 대체 경로(F-10).
- 동시 처리: 기기 쪽 사전 검사·PDF 렌더는 한 번에 하나, 올리기는 동시 3개. 100장을 한 번에 놓아도 탭이 죽지 않게 한다.
- 서버도 같은 검사를 다시 한다(§9.4). 기기 검사는 친절함, 서버 검사는 안전.

### 5.4 서버 처리 (`media/image.ts`, sharp)

순서: `sharp(input, {limitInputPixels: 1.2e8, failOn:'error'})` → `.rotate()`(EXIF 반영) → `.toColorspace('srgb')` → 메타데이터 버림(기본 동작, `withMetadata` 안 씀) → 파생 생성 → 분석.

| `zoom` | 보통 그림 | 긴 변 2048, WebP q85 | 줌 기본 |
| `zoom-hi` | 보통 그림 중 원본 긴 변 > 2048 | 긴 변 4096 이하, WebP q85 | 줌에서 손가락 확대 1.5배를 넘을 때만 |
| `strip-{i}` | 긴 세로·파노라마 | 짧은 변을 min(원본, 1440)으로 맞추고 긴 축을 2048px 띠로 자름(겹침 없음) | 줌 쪽 넘김·두루마리 |
| `page-{i}` | PDF 쪽 | 긴 변 2048, WebP q85 (+ 쪽마다 thumb) | 쪽 넘김 |
| `cover` | 소리(ID3 그림이 있으면) | 512, WebP | 소리 명판 |

- **긴 세로를 "원본 최대 4096"으로 줄이면 800×20000 웹툰이 164×4096이 되어 글자를 읽을 수 없다**(C2). 그래서 긴 축이 아니라 **짧은 변 기준**으로 맞추고 띠로 나눠 저장한다. 쪽은 기기에서 띠 위의 창으로 만든다(§6.8). WebP는 한 변 16,383px를 넘을 수 없어(F-5) 띠 저장은 어차피 필요하다.
- 긴 세로·파노라마의 `thumb`·`wall`은 전체를 줄이지 않고 **벽에 보이는 창 부분**(긴 세로는 위쪽, 파노라마는 왼쪽부터 비율 0.62/1.6)을 잘라 만든다. 800×20000 전체를 512로 줄이면 20×512가 된다.
- 잘라 내기는 `.rotate()`로 방향을 먼저 바로 세운 뒤 정수 좌표로만 한다(F-5).
- 투명 배경은 파일에서 채우지 않는다(WebP 알파 유지). 화면에서 매트 색 위에 그려 "매트 색으로 채움"을 지킨다. 템플릿을 바꿔도 다시 처리할 필요가 없다(C10).
- GIF는 첫 장면만(`pages: 1`).

**분석값 (`media/analyze.ts`, artwork `analysis` JSON)**
- `edgeLuma`: 가장자리 4% 띠의 평균 밝기(0~1). 매트 밝은/어두운 선택에 씀(PRD 6.5, 템플릿 팔레트는 화면에서 고름).
- `linePitchPx`·`linePitchConfidence`: **회전을 바로 세운 원해상도**(짧은 변이 2400px를 넘으면 2400으로만 줄임)에서 긴 축 방향 줄마다 활동량(이웃 화소 밝기 차의 합, 양옆 가장자리 8%는 테두리 선 때문에 뺌)을 구하고, 그 1차원 배열의 자기상관에서 찾은 글 줄 간격(원본 px). 못 찾으면 null. 줄인 배열로는 짧은 줄 간격이 사라지므로 반드시 원해상도 배열에서 구한다(Codex 지적).
- `lineProfile`: 같은 활동량 배열을 `PROFILE_BIN_PX`(8px) 칸으로 묶은 바이트 배열(최대 4,096칸, base64). 쪽 경계 다듬기(PRD 6.7)에만 쓴다. 긴 세로·파노라마·글 많음·PDF 쪽에만.
- `lowRes`: 짧은 변 < 800px.

**소리 (`media/audio.ts`)**: `music-metadata`로 형식·길이 확인. MP3는 ID3v2·ID3v1·APE 태그를 떼고 저장(MP3 프레임에는 다른 메타데이터가 없다, 표지 그림만 `cover`로 꺼냄). M4A·WAV는 macOS 기본 `afconvert`로 AAC(m4a, 160kbps)로 다시 인코딩한다 — 아이폰 녹음 M4A에는 위치 정보 상자가 들어갈 수 있어, "다시 인코딩한 것만 저장"(ADR-004)을 소리에도 지킨다. 다시 인코딩한 파일에 메타데이터가 남지 않는지는 P1-5a에서 `music-metadata`로 확인한다.
- **소리 분석**(투어·배경음악용, ADR-046): `afconvert`로 22.05kHz 모노 PCM을 임시로 만들어 50ms 창마다 RMS를 잰다. `audibleStartMs`·`audibleEndMs` = 처음·마지막으로 `AUDIO_SILENCE_DBFS`(−45dBFS)를 넘는 창(Suno 곡 끝의 긴 무음을 뺌), `loudnessDb` = −50dBFS 넘는 창들의 평균 에너지(LUFS 근사). asset `analysis`에 저장.

**성능**: 대기열 동시 1(`PROCESS_CONCURRENCY`), sharp 스레드 2(`SHARP_THREADS`), 입력 화소 상한 1.2억(`SHARP_LIMIT_INPUT_PIXELS`), `sips`·`afconvert` 시간 제한 20초(`TOOL_TIMEOUT_MS`) — 맥미니의 다른 작업(아바타 빌드)과 겹쳐도 수업 중 학생 응답이 밀리지 않게. 처리 시간 목표: 그림 1장 1초 이하, 웹툰 3초 이하.

- PDF·여러 쪽: 첫 쪽 형태를 따르고 모서리에 쪽 수 표시.

### 5.6 쪽 나눔 계획기 (`domain/pages/planImagePages.ts`, 기기에서, ADR-007)

PRD 6.7의 읽기 배율 s = (그려지는 크기) ÷ (원본 크기)는 **원본 해상도에 따라 결과가 바뀐다**(같은 A4라도 300dpi 스캔이면 데스크톱에서도 나뉨, C3). 그래서 기준을 "화면에서의 글자 크기"로 바꾼다.

0. **대상**: 긴 세로·파노라마·글 많음 작품·PDF 쪽만. 그 밖의 그림은 나누지 않고 contain + 두 번 누르기·손가락 확대(PRD 6.7-3).
1. 줄 간격 기준: `linePitchPx`가 있으면 화면 줄 간격 = linePitchPx × 배율(CSS px). 읽힘 조건: ≥ `READ_LINE_PITCH_MIN_PX`(18px ≈ 글자 13px).
2. 없으면 기준 폭으로 바꿔 계산: s' = 그려지는 폭 ÷ min(원본 폭, 기준 폭). 기준 폭: 긴 세로 720px(웹툰 화면 폭), 그 밖 1240px(A4 150dpi). 읽힘 조건: s' ≥ `READ_SCALE_MIN`(0.6).
3. 판단:
   - 화면에 다 넣은 크기(contain)에서 읽힘 → **한 장**.
   - 짧은 축을 화면에 맞춘 크기에서 읽힘 → 긴 축으로 나눈다. 배율은 **읽히는 가장 작은 배율**(짧은 축 맞춤을 넘지 않음)로 정해 한 쪽에 가장 많이 담는다 — 그래서 같은 웹툰이 데스크톱에서는 쪽이 적고 휴대폰에서는 많다(PRD 6.7 "휴대폰 4쪽, 데스크톱 2쪽"의 취지). 구현 `packages/core/src/domain/pages/planImagePages.ts`. 원본 px로 L = 긴 축 길이, V = 화면 긴 축에 들어가는 원본 길이, O = ⌈`PAGE_OVERLAP`×V⌉이면 쪽 수 k = max(1, ⌈(L − O) ÷ (V − O)⌉). 겹침을 빼지 않으면 마지막 내용이 빠진다(Codex 지적).
   - 짧은 축에 맞춰도 안 읽힘(예: 휴대폰 세로의 A4) → 짧은 축 맞춤으로 나누고(나눠서 나아질 때만) **손가락 확대(최대 3배)를 글 작품에도 허용** + 한 번만 "가로로 돌리면 더 크게 보여요" 안내(C4, ADR-047).
   - 긴 세로·파노라마는 항상 긴 축으로 나눈다(PRD 6.7-1).
4. 경계 다듬기: 쪽 i의 끝 자리 e_i = i·(V − O) + V 근처 ±`CUT_SEARCH_RATIO`(8%)·V 안에서 `lineProfile`이 가장 낮은 칸(가장 비어 있는 줄)으로 옮긴다. 다음 쪽 시작 = 옮긴 e_i − O. 옮긴 결과 쪽 길이가 V의 60% 아래이거나 V를 넘으면 옮기지 않는다.
   - **덮기 불변식**(시험): 첫 쪽 start = 0, 마지막 쪽 end = L, 이웃 쪽은 최소 O만큼 겹치고, 모든 쪽 길이 ≤ V.
5. 결과: `{ pages: [{ start, end }](원본 px), fit: 'contain'|'short-axis', allowPinch }`. 회전·크기 변경 때 다시 계산하고 지금 보던 위치에 가장 가까운 쪽으로 간다.
- 교사의 `한 장으로 보기`면 1~3을 건너뛰고 contain + 손가락 확대.

### 5.7 글 카드 (`domain/pages/planTextPages.ts`, PRD 6.8)

- 저장은 글자(`text_body`)만. 파일을 만들지 않는다(ADR-038).
- 벽: 기기에서 캔버스로 종이 카드(템플릿 종이 질감 + 제목·본문 앞부분·작가)를 그려 텍스처로 쓴다. 글꼴은 `document.fonts.load(…, 실제 글자)`로 부분집합을 먼저 받은 뒤 그린다(R8).
- 줌: HTML 글자. 최소 글자 크기 휴대폰 18px·태블릿 20px·데스크톱 22px, 한 줄 32자 안팎(`max-width: 32em`이 아니라 측정한 폭).
- 쪽 나눔은 둘로 나눈다(domain 순수성, Codex 지적).
  - **측정**(`apps/web/src/viewer/zoom/measureText.ts`, DOM): 화면 밖 측정 상자에 같은 CSS로 문단(연)마다 높이와 줄 높이를 잰다. 너무 긴 문단은 문장 끝(`다.` `요.` `?` `!` `.`)으로, 그래도 길면 줄로 쪼갠 조각의 높이도 잰다.
  - **계획**(`domain/pages/planTextPages.ts`, 순수 함수): 측정값 배열과 쪽 높이를 받아 앞에서부터 쪽에 담는다. 시는 연 단위(연이 쪽보다 길 때만 줄 단위).
- 판별: 줄 시작이 짧고 빈 줄이 반복되면 시(연 단위), 아니면 산문(문단 단위). 교사 패널의 형태에서 바꿀 수 있다.

## 6. 3D 관람 엔진 (`apps/web/src/viewer`, PRD 4·8·10장)

### 6.1 장면 설정

- `<Canvas frameloop="demand">`, WebGL2만(ADR-008). `gl = { antialias: tier.msaa, alpha:false, stencil:false, powerPreference:'high-performance' }`, `dpr` = 단계별 상한(§6.10).
- 톤 매핑 AgX(밝은 스포트가 하얗게 날아가지 않음), `outputColorSpace = SRGB`. P1-3에서 ACES와 화면 캡처로 비교해 고른다.
- 장면 묶음: `TemplateWorld`(모듈) · `Frames`(액자·매트·작품면) · `LightPools`(빛 웅덩이) · `ContactShadows`(접촉 그림자) · `Labels`(작은 명판) · `Fixtures`(이름판 받침·소개 글판·벤치·화분·소리 명판) · `Signage`(입구 사인·출구 사인). 모두 관(part) 단위로 붙였다 뗀다(§6.6).
- **장면 어둡게** 값 `uDim`(0~1)을 모든 템플릿 재질에 셰이더 조각으로 넣어 한 번에 바꾼다(줌의 "주변 밝기 70%", PRD 8.2). 액자·매트는 관마다 한 기하로 합쳐져 있으므로 정점 속성 `aArtworkIndex`와 uniform `uFocusIndex`로 "줌 대상만 어둡게 하지 않기"를 셰이더에서 가른다(작품 면은 판마다 자기 uniform). 빛 웅덩이 세기도 같은 방식(Codex 지적).
- 색 공간: 작품 WebP·캔버스 텍스처·기본색 = `SRGBColorSpace`, 구운 빛·노멀·거칠기 = `NoColorSpace`(선형).

### 6.2 모듈 조립

- 모듈 종류마다 `InstancedMesh` 하나(관 안의 모든 같은 조각을 한 번에 그림). 벽 길이는 2m 단위라 4m 조각을 먼저 채우고 남는 2m를 쓴다.
- 바닥은 관마다 평면 하나(타일 UV) + 벽을 따라 놓는 "벽 아래 그늘 띠"(인스턴스). 천장은 2×2m 우물천장 조각 인스턴스.
- 구운 빛은 **조각 종류마다 하나**다. 같은 조각은 어디에 놓여도 같은 빛을 갖도록 표준 조명틀로 굽는다(ADR-013, §13.3). 그래서 같은 UV·같은 질감을 쓰는 인스턴싱과 구운 빛이 함께 된다.
- 구운 빛은 glTF 표준 칸 **`occlusionTexture`(texCoord 1)**에 넣는다(회색조 "세척광 × AO"). three `GLTFLoader`가 `aoMap`(channel 1)으로 붙이고, gltf-transform이 참조된 질감으로 보존한다(이름 규칙으로 따로 잇는 방식은 `prune`이 지울 수 있음 — Codex 지적). `aoMap`은 간접광(반구광·환경맵)만 깎으므로 **모듈은 직접광을 받지 않고 반구광 + 환경맵으로만 밝힌다**. 색이 있는 구운 빛이 꼭 필요하면(P1-3 관문) glb 밖 KTX2 라이트맵 + `manifest.json` 목록 + `lightMap.channel = 1`로 바꾼다.
- glTF는 meshopt 압축 + KTX2(ETC1S 기본색·구운 빛, UASTC 노멀) — 로더는 `GLTFLoader` + `MeshoptDecoder` + `KTX2Loader`. Basis 변환기(wasm 약 527KB·js 58KB, 압축 전, F-8)는 판을 고정해 자체 배포하고 템플릿 핵심 예산에 넣는다.

- 줌: `uDim` 1 → 0.7, 대상 빛 웅덩이 세기 ×1.35, 0.8초에 함께.

### 6.4 액자·매트·명판·글자

- 액자: 템플릿의 테 단면(2D 선)을 바깥 사각형을 따라 쓸어 만든다(모서리 45° 맞춤). 관마다 액자 전부를 한 기하로 합친다(그리기 1회). 매트는 판 하나씩을 합쳐 정점 색(밝은/어두운 매트)으로(그리기 1회). 둘 다 정점마다 `aArtworkIndex`를 넣어 줌 대상·마우스 올림을 셰이더에서 가린다.
- 작품 면: 작품마다 판 하나(텍스처가 달라서). 투명 작품은 매트 색 위에 알파로 그려진다(§5.4).
- 긴 세로: 두루마리 액자 창에 `wall`(위쪽 부분)을 걸고, 아래 끝에 "이어서 보기" 작은 띠.
- 여러 쪽(PDF): 모서리에 `1/5` 같은 작은 쪽 수 딱지.
- 작은 명판(액자 옆 제목·작가): 관마다 캔버스 아틀라스 하나에 그려 판 하나로(그리기 1회). 실제 박물관 벽 라벨처럼 보이게 하는 마감 요소다.
- 이름판 받침·입구 사인·출구 사인·소개 글판: 캔버스 텍스처(템플릿 세리프 글꼴, 황동·나무 질감 위). 글꼴 부분집합을 `document.fonts.load()`로 먼저 받고 그린다.
- 3D 안 글자는 모두 캔버스 텍스처다. troika(SDF 글자)를 쓰지 않는다(ADR-017): 한글 글꼴 파일이 크고, 글자는 배치 때 정해져 바뀌지 않기 때문이다.
- 전시실 소개 글(200자)은 3D 글판에도 보이지만, 소개 정지 지점에서는 캡션 카드 자리에 HTML로도 보여 준다(읽을 수 있게).

### 6.5 텍스처 상주 관리자 (`textures/residency.ts`, ADR-015)

- 원하는 집합 = 보이는 관의 모든 작품 `thumb` + 지금 관에서 현재 정지 지점 앞뒤 창 안의 `wall`(높음: 뒤 3·앞 6, 보통: 뒤 2·앞 3, 낮음: 뒤 1·앞 2이고 `wall-lo`) + 진행 중인 이동의 도착 지점.
- 예산(작품 텍스처만): 높음 140MB · 보통 90MB · 낮음 30MB(`TEX_BUDGET_MB_*`). 크기 추정 = 폭×높이×4×1.33.
- 받기: 미디어 캐시 → `createImageBitmap(blob, { premultiplyAlpha: 'premultiply', colorSpaceConversion: 'none' })`(워커에서 디코드) → `Texture`. `ImageBitmap`은 `Texture.flipY`·`premultiplyAlpha`가 무시되므로(Codex 지적, three 문서) **작품 판 기하의 UV를 위아래 뒤집어** 맞추고 재질은 `premultipliedAlpha = true`.
- 올리기 일정: 올릴 것이 줄에 있으면 정지 상태에서도 "올리기 박자"가 한 프레임에 하나씩 `renderer.initTexture` → `invalidate()`를 하고, 줄이 비면 멈춘다. 이동 중에는 도착 지점 것만 올린다(끊김 방지).
- 바꿔 끼우기: 썸네일 → 벽용 순서(PRD 10.3). 벽용이 올라가면 0.2초 동안 섞어 바꾸고, 그 0.2초 동안만 매 프레임 그린다(번쩍임 방지).
- 내보내기: 원하는 집합 밖이고 예산을 넘으면 오래 안 쓴 것부터 `dispose()` + `ImageBitmap.close()`.
- `MAX_TEXTURE_SIZE < 2048`인 기기는 모두 `wall-lo`.
- 개발 표시(HUD, `?perf=1`): fps·그리기 호출·삼각형·`renderer.info.memory`·우리 추정 MB·단계.

### 6.6 그리는 범위

- 붙이는 관: 지금 관 + 이웃(높음: 앞·뒤, 보통: 앞, 낮음: 없음) + 그 사이 회랑·홀 조각. 나머지는 장면에서 뗀다(관별 액자 기하·명판 아틀라스·텍스처 해제, 템플릿 공용 기하·재질은 남김).
- 회랑 끝 25m 밖은 템플릿 색 안개로 가린다(떼어 낸 관이 보이지 않게).
- 이웃 관을 미리 붙이는 것은 이동이 끝나고 정지했을 때 한다. 이웃을 붙이지 않는 '낮음'은 관 이동이 **시작될 때** 도착 관을 붙이고(공용 기하·재질이라 가볍다) 그 관의 썸네일을 이동 중에 올린다(정지 시 올리기 규칙의 예외).

### 6.7 카메라 리그 (`camera/CameraRig.ts`, ADR-009)

- 상태: `idle` · `moving` · `zooming` · `zoomed` · `unzooming` · `touring`. 둘러보기(끌기)는 `idle`의 덧붙임.
- 명령: `goToStop(i)` · `zoomTo(artworkId)` · `unzoom()` · `flyToArtwork(id, {zoom:true})`(모아 보기) · `goToPart(partId)`(지도) · `look(dx, dy)` · `release()`.
- 규칙
  - `moving`·`zooming` 중의 `‹ ›`·스와이프·키보드는 **버린다**(쌓지 않음, PRD G-02).
  - `zooming` 중 닫기·Esc → 지금 진행률에서 거꾸로 돌린다(튀지 않게, PRD 8.1).
  - 이동 중 둘러보기 끌기는 무시, 줌 상태에서는 끌기가 HTML 층(손가락 확대)의 것이다.
- GSAP 타임라인 하나가 진행률 0→1을 움직이고, 매 갱신에서 곡선 위치·시선 보간·화각을 정한 뒤 `invalidate()`. 시간·곡선은 §4.8.
- 먼 곳으로 가기(모아 보기·지도에서 지금 관이나 이웃 관이 아닌 곳): 길게 날아가지 않고 0.3초 어둡게 바꿔 그 정지 지점으로 옮긴 뒤(그동안 그 관을 붙이고 썸네일을 올림) 줌 0.8초. 같은 관·이웃 관이면 경로로 이동.
- 둘러보기: 끌기 거리 0.25°/px, 좌우 ±20°·위아래 ±8°, 놓으면 0.6초에 제자리(`power3.out`). 데스크톱 휠: 앞으로 최대 0.6m만, 2초 쉬면 제자리.
- 화면 크기·방향 변경: 지금 상태의 자세를 애니메이션 없이 다시 맞추고, 줌이면 HTML 층 자리와 쪽을 다시 계산한다(PRD 9.5, 15.5).

### 6.8 줌인 HTML 층 (`zoom/`, ADR-016)

- **시간표(0.8초)**: 0~0.8초 카메라가 줌 자세로 + `uDim` 0.7 + 빛 강해짐. 캡션 카드는 0.55~0.8초에 아래에서 올라온다(카메라가 가장 느린 마지막 구간과만 겹침). PRD 8.2 "0.25초 늦게"와 15.1 "0.8초 안에 캡션"을 함께 지키는 해석이다(C19).
- 0.8초: 작품 네 모서리를 화면에 투영한 사각형에 HTML 층을 정확히 겹치고, 3D 작품 면 → HTML 그림을 120ms 동안 섞어 바꾼다. 줌 그림(`zoom`)은 이동 시작 때 받기·`img.decode()`를 시작해 두고, 늦으면 `wall`을 먼저 보이고 준비되면 바꾼다.
- 쪽(`ImagePager`): 띠·쪽 그림을 쌓은 상자 위의 창. 쪽 넘김 0.35초 미끄러짐. 글 카드(`TextPager`)는 종이가 옆으로 밀리며 살짝 그늘이 지는 넘김.
- 손가락 확대: 1~3배(`ZOOM_MAX_SCALE`), 끌기 범위 제한, 두 번 누르면 1↔2배(누른 자리 기준). 1.5배를 넘으면 `zoom-hi`를 받는다. **배율 > 1.05인 동안 좌우 넘기기·아래로 쓸어 닫기·빈 곳 눌러 닫기를 막는다**(Antigravity 지적).
- 닫기: `닫기`·Esc·빈 곳 누르기·아래로 80px 이상 쓸기 → HTML 120ms 사라짐 → 카메라 0.6초 물러남.
- 마지막 쪽에서 `›`: 같은 관의 다음 작품이면 줌 상태로 옆으로 미끄러지듯(1.0초) 바로 다음 줌. 관의 마지막 작품이면 줌을 풀고 다음 관 소개로.
- 소리 명판: 표지 + 재생·멈춤 + 진행 막대 + 길이. 재생하면 배경음악을 낮춘다(§8).
- 캡션 카드: `제목 · 작가` / 한 줄 설명 / `더 보기`(긴 설명, 카드 안에서 스크롤, 최대 화면 높이 40%) / `반응 남기기`(켰을 때). 데스크톱은 아래 가운데 최대 폭 720px, 태블릿 가로는 아래 가운데, 태블릿 세로는 아래 전체 폭, 휴대폰 세로는 아래 시트(접힌 한 줄 → 펼침), **휴대폰 가로는 오른쪽 좁은 패널**(PRD 9.5). 줌 맞춤(§4.7)은 캡션이 차지하는 자리를 빼고 계산한다.
- 접근성: 줌 층은 `role="dialog"`, 초점이 들어오고 Esc로 닫힘, ← →는 쪽, 쪽이 바뀌면 `aria-live`로 "2/3쪽".

### 6.9 입력 (`input/gestures.ts`)

- 포인터 이벤트 하나로(PRD 9.5). 누르기 = 10px·300ms 안. 한 손가락 끌기는 PRD에서 **스와이프(이전·다음)와 둘러보기 두 뜻**이라 놓는 순간에 가른다(B21): 가로 50px 이상 + 가로가 세로의 1.5배 이상 + 놓을 때 속도 ≥ 0.5px/ms(`SWIPE_*`) → 스와이프, 아니면 둘러보기(끄는 동안 이미 고개가 돌아가 있고, 놓으면 제자리). 스와이프로 판정되면 돌아간 자세에서 바로 다음 정지 지점으로 이어 간다.
- 작품 고르기: 작품 면 레이캐스트, 안 맞으면 화면에서 24px 안에 있는 액자. 지금 정지 지점이 아닌 다른 액자를 누르면 그 정지 지점으로 가서 줌.
- 키보드: ← → 정지 지점(줌이면 쪽), Enter 줌, Esc 닫기, Tab으로 위 버튼·캡션 카드.
- 브라우저 동작 막기: 캔버스와 줌 층의 **작품 영역**만 `touch-action: none`, 캡션 카드·긴 설명은 `touch-action: pan-y`(안에서 스크롤, Codex 지적). 문서 `overscroll-behavior: none`, iOS `gesturestart` 막기, 캔버스 길게 누르기 메뉴 막기.
- 끌기는 `setPointerCapture`로 잡고, `pointercancel`·`lostpointercapture`가 오면 끌기를 취소하고 둘러보기를 제자리로 돌린다(전화·알림·시스템 손짓에 끊길 때).

### 6.10 품질 단계 (`quality/`, ADR-035)

| 단계 | 배율 상한(데스크톱/태블릿/휴대폰) | MSAA | 작품 텍스처 | 작은 움직임 | 이웃 관 |
|---|---|---|---|---|---|
| 높음 | 2 / 1.5 / 1.25 | 배율 < 1.5일 때 | `wall` 창 넓게 | 켬 | 앞·뒤 |
| 보통 | 1.25 | 끔 | `wall` 창 좁게 | 적게 | 앞 |
| 낮음 | 1.0 | 끔 | `wall-lo` | 끔 | 없음 |

- 시작 단계: `RendererCaps`(WebGL2, `MAX_TEXTURE_SIZE`, GPU 이름, 코어 수, `deviceMemory`, 화면 화소)로 고른다. 데스크톱 → 높음, iPad → 보통, iPhone → 보통, Android는 GPU 이름이 Adreno 6xx 이상·Mali-G7x 이상이면 보통 아니면 낮음, 모르면 보통. 이 기기에서 지난번에 내린 단계가 있으면 그 단계로 시작한다(기기 저장).
- 내리기: 정지 상태는 그리지 않으므로 **이동하는 동안**의 프레임으로 잰다. 이동 두 번 연속 중앙값이 기준 아래면 한 단계 내린다(데스크톱 50fps, 태블릿 40fps, 휴대폰 28fps). 학생에게 알리지 않는다(G-19). 수업 중 올리지는 않는다.
- drei `PerformanceMonitor`는 쓰지 않고 이 규칙을 직접 짠다(정지 시 프레임이 없어 일반 감시기가 잘못 판단한다).

### 6.11 다시 그리지 않기

- `invalidate()`를 부르는 곳은 카메라 타임라인, 올리기 박자(줄이 빌 때까지), 바꿔 끼우기 0.2초, 크기 변경, 작은 움직임 구간, 데스크톱 마우스 올림 빛(0.2초)뿐이다.
- 시험(P6-4): 정지 지점에서 10초 동안 `renderer.info.render.frame`이 늘지 않는다(PRD 15.5).

### 6.12 컨텍스트 손실과 2D 대체 화면 (ADR-019, G-22)

- `webglcontextlost` → 기본 동작 막기 → 템플릿 분위기의 "잠시만 기다려 주세요" → 복구되면 캔버스를 다시 붙이고 같은 정지 지점으로.
- **2D로 바꾸는 때**: WebGL2를 만들 수 없음 / 60초 안에 컨텍스트 손실 두 번 / '낮음'에서 이동 세 번 연속 중앙값 20fps 미만. 그 전시 동안 2D로 남고 다음 방문에 3D를 다시 시도한다.
- 포스터의 `입장하기`는 3D 준비(템플릿 핵심 + 첫 관)를 기다린다. WebGL2를 만들 수 없다고 판정되면(포스터가 뜨는 순간 확인) 기다리는 대상을 2D 준비(첫 전시실 썸네일)로 바꿔 버튼을 연다.
- 2D 화면: 같은 상태 저장소와 같은 줌 층·캡션·반응·소리를 쓴다. 위에 전시실 탭, 가운데 액자 하나(템플릿 벽 질감 배경 위 액자 그림), `‹ ›`·스와이프로 작품을 넘긴다. 추가 코드가 작아 v1에 넣는다.

### 6.13 자동 투어 (`tour/`, G-16, ADR-046)

**시간 기준 (사용자 결정 2026-11-11: 노래 길이에 맞춤)**
- 전시실마다 그 방 배경음악의 **들리는 길이**(앞뒤 무음을 뺀 길이, §5.4 소리 분석의 `audibleStartMs`~`audibleEndMs`)가 그 전시실 투어 시간이다. 곡이 없는 전시실은 `TOUR_SECONDS_PER_ROOM`(40초).
- 교사 설정 "자동 투어 시간"(접힌 `더 설정하기`, G-16 "설정에서 바꿈"): `노래 길이에 맞춤`(기본) / `전시실마다 ○초`(PRD 방식, 기본 40). 투어 버튼 옆에 미리 계산한 길이 "약 12분 · 전시실 5곳".
- 안전 상한 `TOUR_MUSIC_MAX_SEC`(360초): 실수로 올린 긴 파일이면 상한에서 페이드아웃.
- 최소 시간: 이름판 4초 + 작품당 `TOUR_MIN_SEC_PER_ARTWORK`(5초)를 못 채울 만큼 곡이 짧으면 그 최소 시간을 쓰고, 곡은 끝에서 페이드아웃한 뒤 남은 몇 초는 조용히 간다(곡을 되풀이하지 않음 — 노래가 처음부터 다시 나오면 어색하다).
- 나뉜 전시실(1관·2관): 한 곡이 관들을 이어서 덮는다. 곡 시간을 관의 작품 수 비율로 나누고, 관 사이 이동 중에도 곡은 끊기지 않는다.

**카메라 일정** (`domain/tour/tourSchedule.ts`, 순수 함수)
- 입구 홀 5초(검은 화면에서 2초 페이드인) → 전시실마다 [이름판 장면 4초 → 작품 구간 × n → 문 통과 2초] → 출구 5초(마지막 곡 페이드아웃과 함께 3초 페이드아웃).
- 작품 구간 = (전시실 시간 − 4 − 2) ÷ n. 한 구간 = 다가가기 2.5초 + 머무르기(나머지). 머무르는 동안 아주 천천히 3% 다가가며 옆으로 살짝 흐르는 움직임(가만히 멈춘 화면이 되지 않게). 한 작품에 30초를 넘게 머무르면 중간에 한 번 1.2배까지 가까이 갔다가 물러난다.
- 경로: 작품 정지 지점들을 거리 ×1.25로 이은 둥근 꺾은선(§4.8 `pathClear` 통과), 호 길이로 같은 속도. 전체가 GSAP 타임라인 하나이고 전시실마다 이름표(label)가 있다.

**소리 이음 — 자동 페이드인·페이드아웃** (`audio/TourSoundtrack.ts`, §8)
- 전시실 시작: 그 곡을 `audibleStartMs`로 맞춰 재생, 음량 0 → 목표를 `TOUR_FADE_IN_SEC`(2.5초) 동안 등전력 곡선(equal-power)으로.
- 전시실 끝: `audibleEndMs`보다 `TOUR_FADE_OUT_SEC`(4초) 앞에서 페이드아웃 시작. 곡의 원래 끝맺음 위에 부드럽게 겹치고, 이 4초가 마지막 작품에서 떠나 문을 지나는 구간과 맞물린다.
- 다음 곡: 이전 곡이 30% 아래로 줄어든 때 시작해 `TOUR_SONG_OVERLAP_SEC`(1초)만 겹친다 — 소리가 비지도, 두 곡이 부딪치지도 않는다.
- 화면도 같은 박자: 문을 지나는 동안 노출을 15% 낮췄다가 다음 방 이름판에서 되돌린다(아주 약한 시각 페이드, 동작 줄이기면 끔).
- 곡 크기 맞추기: 서버가 잰 곡 크기(`loudnessDb`)로 목표(`AUDIO_TARGET_LOUDNESS_DB` −16) 쪽으로 이득을 준다(±6dB 제한). 모둠마다 Suno 곡 크기가 달라도 개막식 소리가 고르다. 학생 관람 배경음악에도 같은 이득을 쓴다.
- 조작과 소리: Space·화면 누르기 = 0.4초 페이드아웃 후 멈춤, 다시 = 0.6초 페이드인 · → = 지금 곡 1.2초 페이드아웃 + 바로 다음 전시실(새 곡은 페이드인) · Esc = 1.5초 페이드아웃 뒤 관리 화면.
- 시험(단위): 노래 5곡(150~180초)·곡 없는 전시실·나뉜 전시실·아주 짧은 곡에서 시간표 합계, 페이드아웃 구간이 문 통과 구간을 덮는지, 겹침 ≤ 1초, 조작별 소리 상태.

**그 밖**
- 화면: UI 없음, 아래 2px 진행 막대, 커서는 1초 뒤 숨김, 시작 버튼을 누를 때 전체 화면 요청, Wake Lock(화면 복귀 때 다시 요청, F-12). 투어 중에는 연속으로 그린다(`frameloop` 바꿈).
- 텍스처: 투어는 쉬지 않고 움직이므로 상주 관리자가 경로 앞쪽 8점의 `wall`을 미리 올린다(정지 시 올리기 규칙의 예외, 한 프레임에 하나는 그대로). 투어 버튼 옆에 "수업 전 미리 불러오기를 먼저 하면 끊김이 없어요" 한 줄.
- 학생 기기와 연결하지 않는다. 같은 관람 엔진에 정해진 경로만 재생한다(PRD `[고정]`).

### 6.14 동작 줄이기 (PRD 8.4)

- `prefers-reduced-motion: reduce`이면 이동·줌은 0.3초 페이드 바꾸기(검은 덮개 투명도), 쪽 넘김은 0.15초 페이드, 작은 움직임·스티커 튀기 끔.

## 7. 화면 (PRD 9장)

### 7.1 경로

| `/` | 첫 화면: 입장 코드 숫자 키패드 + 작은 `선생님이세요?` | 학생 |
| `/{6자리}` | 포스터 → 관람(같은 경로 안의 상태) / 막 내림 / 준비 중 | 학생 |
| `/t` | 선생님 첫 화면: 최근 전시 카드(최대 5) + `PIN으로 들어가기` + 주요 버튼 `새 전시 만들기` | 교사(지연 로드) |
| `/t/new` | 새 전시 만들기 | 교사 |
| `/t#{교사토큰}` | 선생님 링크. 토큰은 **주소 조각(#)**이라 서버·CDN·기록에 가지 않는다(ADR-044). 열면 기기에 저장 → 조각을 지움(`replaceState`) → `GET /api/teacher/me`로 전시 ID → `/t/e/{id}` | 교사 |
| `/t/e/{id}` | 전시 관리(작품 탭·반응 탭) | 교사 |
| `/t/e/{id}/tour` | 자동 투어 | 교사 |
| `/t/e/{id}/print` | 전시 도록(v1.1) | 교사 |
| `/privacy` | 개인정보처리방침 | 공통 |

- 교사 화면·pdf.js·QR·끌어 옮기기는 학생 묶음에 들어가지 않는다(경로 단위 나누기, §2.5).

### 7.2 상태 (Zustand)

- `visitorStore`: `phase`(`poster`·`entering`·`viewing`·`closed`·`notReady`·`fallback2d`), `exhibition`, `layout`, `stopIndex`, `zoom`(작품·쪽·배율), `soundOn`, `pendingUpdate`, `myReactions`.
- `uiStore`: **덮개 칸 하나**(`overlay: null | 'collection' | 'map' | 'reaction' | 'consent' | 'menu' | …`). 하나를 열면 이전 것은 닫힌다 — "동시에 열린 창 하나 이하"(PRD 9.6, 15.7)를 구조로 지킨다. 토스트는 덮개가 아니다.
- `teacherStore`: 전시·전시실·작품 목록, 처리 상태, 선택, 미리 보기 배치(기기 계산), 저장 대기 명령.

### 7.3 학생 화면

**첫 화면 `/`**: 템플릿 중립 박물관 안내판 스타일. 숫자 6칸 + 키패드(`inputmode="numeric"`), 6자리가 차면 바로 이동. 아래 작은 글자 버튼 `선생님이세요?`.

**포스터 (G-01)**: 포스터 이미지(없으면 템플릿 기본 포스터에 전시 이름 조판, §12.4) · 전시 이름 · 한 줄 소개 · (켰을 때) 학교·학급 · 주요 버튼 `입장하기` · 구석에 작게 "{날짜}까지 열려요". 미리 불러오기 진행이 필요하면 버튼 아래 가는 진행 막대(첫 방 준비 전에는 버튼이 "준비하고 있어요"로 잠김).
- 인앱 브라우저(카카오톡·네이버·인스타그램 등 UA) 감지 시 포스터 아래 한 줄: "소리가 안 나면 Safari나 Chrome으로 열어 주세요"(막지 않음, Antigravity 지적).
- 막 내림: "이 전시는 막을 내렸어요" + `처음으로`. 준비 중(DRAFT): "아직 준비 중인 전시예요" + `처음으로`.

**관람 (9.1)**: 위 줄 = 전시 이름(왼쪽) · `모아 보기` `지도` `소리`(오른쪽, 아이콘+글자, 휴대폰은 아이콘만). 아래 가운데 = `‹  {위치 표시}  ›`. 이동 중 위 줄 투명도 0.5, 3초 입력 없으면 0.35(`IDLE_DIM_SEC`). 출구 정지 지점에서는 출구 벽 3D 사인 + HTML 버튼 `모아 보기`·`처음부터 다시 보기`.
- 전시 바뀜(ADR-027): 지금 관이 그대로면 다음 이동 때 조용히 새 배치로, 아니면 위에 작은 띠 "전시가 새로 바뀌었어요 `새로 보기`"(지금 보던 작품으로 다시 감).

**모아 보기 (G-04)**: 전체 화면 시트. 위 전시실 탭(가로로 밀기, 관이 나뉜 전시실은 하나로), 썸네일 격자(태블릿 4열·휴대폰 3열·데스크톱 6열), 글 카드·소리는 HTML 작은 카드. 누르면 시트가 닫히며 `flyToArtwork(id, {zoom:true})`. `닫기`.

**지도 (G-05)**: 가운데 카드에 지도 SVG(§4.9), 현재 위치 점(살짝 맥박, 동작 줄이기면 정지), 전시실 이름. 전시실을 누르면 그 관 입구로 `goToPart`.

**반응 시트 (G-07)**: 아래에서 둥근 시트(0.3초). 스티커 4개(하나 선택, 누르면 작게 튐), 한 줄 메모(60자, 안내 "새로 알게 된 것을 적어요", 글자 수 표시), (평가 켰을 때) `사실 정확성` `전달력` 각 1~3(별 대신 칸 3개), `남기기`. 이미 남겼으면 값이 채워져 열리고 버튼은 `고치기`. 위에 작게 "{별명}으로 남겨요 `바꾸기`"(별명 방식일 때, 오타·실명을 고칠 수 있게).
- 보내기 실패: 시트를 닫지 않고 값 유지, "잠깐 연결이 끊겼어요. 연결되면 자동으로 보낼게요". 반응은 기기의 **보내기 줄**(IndexedDB, 반응 ID로 멱등)에 넣고, 연결이 돌아오면(`online`·화면 복귀·60초 확인 때) 자동으로 다시 보낸다. 줄에 남은 것이 있으면 반응 버튼에 작은 점(ADR-049).
- 반응 꺼짐·전시 닫힘이면 `반응 남기기`가 보이지 않는다.

**공개 반응 표시** (교사가 공개를 켰을 때만, G-07): 캡션 카드 아래 한 줄에 스티커별 수(아이콘 + 숫자, 0은 숨김)·평가 평균(소수 한 자리). `더 보기` 안에 교사가 고른 메모(별명 또는 `익명`, 다섯 개 + `더 보기`). 집계는 `ExhibitionView`에 들어 있고 버전 확인(ADR-027) 때 새로 받는다. 공개가 꺼져 있으면 자기 반응만 시트에 보인다.

**별명·동의 (13.2)**: 처음 반응할 때만, 별명 방식일 때만. PRD 13.2 문구(공개 설정이 '모두에게'를 포함하면 "다른 친구들도 볼 수 있어요"로). 별명 1~12자, 욕설 걸러내기, `알겠어요` 체크 뒤 `시작하기`. 익명 방식이면 이 화면 없이 짧은 안내 한 줄만 시트 위에.

### 7.4 교사 화면 (9.4)

**선생님 첫 화면 `/t`**: 최근 전시 카드(썸네일·이름·상태 점·삭제 예정일), 누르면 바로 관리. `PIN으로 들어가기`(숫자 키패드 시트). 주요 버튼 `새 전시 만들기`. 기기에 기억한 전시가 없으면 카드 자리에 짧은 안내 한 줄.

**새 전시 만들기 (G-09)**: 보이는 것 4가지 — 전시 이름(필수, 40자) · 템플릿 카드 5개(미리 보기 그림 + 이름 + 한 줄 설명, 준비 안 된 것은 `준비 중` 딱지·누를 수 없음) · 한 줄 소개(선택, 60자) · 선생님 PIN(숫자 키패드, 6~8자리, ADR-024). 접힌 `더 설정하기`: 포스터 이미지, 학교·학급 표시, 반응 설정(G-07 표), 자동 투어 시간(`노래 길이에 맞춤`(기본) / `전시실마다 ○초`, ADR-046). 주요 버튼 `전시 만들기` → 바로 작품 탭. 만든 직후 토스트 "이 전시는 오늘부터 30일 동안 열 수 있어요".
- PIN 중복: 칸 아래 "이미 쓰이는 PIN이에요"만. 이 확인도 PIN 실패 칸으로 센다(ADR-024).
- 시작 코드(ADR-048, 기본 켬): 이 기기에서 처음 만들 때만 PIN 아래에 한 칸 더(숫자 키패드). 한 번 맞으면 기기에 기억해 다음부터 보이지 않으므로 평소 화면은 4가지 그대로다(G-09).

**전시 관리 · 작품 탭 (G-10~G-13)**
- 위: 전시 이름(눌러서 고침) · 상태 점(`준비 중`·`열림`·`닫힘`) · 작은 글자 "{날짜}에 지워져요"(G-18) · `···` · 전시실 칩 줄(끌어서 순서, 끝에 `+`).
- 점검 줄(문제가 있을 때만): "제목이 없는 작품 2개 · 흐린 작품 1개" → 누르면 해당 카드로 스크롤·깜빡임.
- 가운데: 작품 카드 격자(썸네일·제목·상태 점·알림 딱지만). 카드 제목 누르면 바로 입력, 끌어서 순서, 전시실 칩 위로 끌어 옮김(`@dnd-kit`, ADR-032). 길게 누르기·Shift로 여러 장 → 아래 띠에 `숨기기` `게시` `전시실 옮기기`만.
- 빈 상태: 큰 놓기 영역 "작품 파일이나 폴더를 여기에 놓아요" + 주요 버튼 `작품 올리기` + 작은 `글 붙여넣기`. 작품이 있으면 놓기 영역은 격자 위 얇은 띠로 줄고 화면 어디에 놓아도 받는다.
- 오른쪽(데스크톱 1280px 이상): 3D 미리 보기(같은 관람 엔진, 품질 '보통', 미리 보기 모드에서 작품을 누르면 그 작품 패널). 태블릿·휴대폰은 `미리 보기` 버튼 → 전체 화면.
- 주요 버튼: 작품이 없으면 `작품 올리기`, 게시 작품이 1개 이상이면 `전시 열기`. 게시 작품이 0이면 `전시 열기`·`자동 투어`는 잠기고 "게시한 작품이 있어야 열 수 있어요"(Antigravity 지적).

**작품 패널 (G-11)**: 데스크톱 오른쪽 패널(미리 보기 자리를 잠시 덮음), 휴대폰 아래 시트. 항상: 제목. 접힘: `작가 더하기`, `설명 더하기`(한 줄 + 긴 설명). **글 작품은 `글 고치기`(본문, 5,000자)**(G-11에 빠진 것, Antigravity 지적). 자동값(펼칠 때만): 전시실, 형태·액자, 쪽 나눔 `자동 / 한 장으로 보기`, `글이 많은 작품`, `대표작`. 아래: `숨기기` / `삭제`.
- 저장은 입력이 멈추고 0.6초 뒤 자동(버튼 없음). 실패하면 칸 옆에 다시 시도.
- 삭제 → 바로 사라지고 토스트 "삭제했어요 `되살리기`" 10초(`UNDO_DELETE_SEC`). 파일은 24시간 뒤 지움.

**전시실 시트 (G-12)**: 칩을 누르면. 이름판(필수, 30자), 소개 글(200자), 배경음악(파일 올리기·바꾸기·빼기, 재생 미리 듣기), `이 전시실 지우기`(작품이 있으면 "작품 {n}개는 전시실 1로 옮겨져요" 확인).

**전시 열기 시트 (G-14)**: `전시 열기` → 반응 설정 한 줄 요약("반응: 스티커·메모 · 별점 꺼짐 `바꾸기`", 수업 전에 평가 켜기를 잊지 않게, Antigravity 지적을 4가지 규칙을 지키며 반영) → 주요 버튼 `열기` → QR · 짧은 주소 · 입장 코드 · `QR 크게 띄우기`(전체 화면, 주소·코드도 크게). 열린 뒤 `···`에 `전시 닫기`·`다시 열기`.

**반응 탭 (G-15)**: 작품별 한 줄(스티커별 수 · 메모 수 · 평가 평균). 누르면 메모 목록(별명 또는 `익명`, 시각), 메모마다 `숨기기`·(공개 '고른 것만'일 때) `모두에게 보이기`. 주요 버튼 `내려받기`(CSV, §9.5).

**`···` 메뉴**: 자동 투어 · 수업 전 미리 불러오기(진행률·저장한 MB) · 템플릿 바꾸기(v1.1) · 전시 도록 저장(v1.1) · 선생님 링크 복사(이 기기에 링크가 있을 때만, 경고: "학생에게 보이지 않게 하세요") · 선생님 링크 새로 만들기(§11.1) · 전시 닫기 · 지금 삭제(확인 시트 + 3초 뒤 눌리는 버튼, G-18).

### 7.5 반응형 (9.5)

- 학생 관람은 PRD 9.5 표대로. 높이는 `100dvh`, 가장자리는 `env(safe-area-inset-*)`.
- 교사 관리: 1280px 이상 = 격자 + 오른쪽 미리 보기, 768~1279px = 격자만(미리 보기 버튼), 767px 이하 = 2열 격자 + 아래 시트 패널.
- 회전: 관람 엔진이 즉시 다시 맞춤(§6.7). 교사 화면은 일반 반응형.
- 터치 영역 44×44px 이상, 버튼 사이 8px 이상.

### 7.6 문구

- 모든 문구는 `copy/ko.ts`. 위 화면의 따옴표 문구와 PRD 문구를 그대로 쓰고, PRD에 없는 문구(오류·빈 상태·확인)는 P4·P5에서 쓰고 Antigravity가 초5 눈높이로 두 번째로 본다.
- 학생 문구에는 기술 용어(서버, 동기화, 브라우저, 업로드, 오류 코드, 에러)를 쓰지 않는다. 인앱 브라우저 안내의 "Safari나 Chrome"은 앱 이름이라 예외.

## 8. 소리 엔진 (`apps/web/src/audio/AudioEngine.ts`, G-06, ADR-011)

### 8.1 구성

```
<audio> BGM-A ─ MediaElementSource ─ Gain A ─┐
<audio> BGM-B ─ MediaElementSource ─ Gain B ─┼─ Duck Gain ─ Master Gain(소리 켬/끔) ─ destination
<audio> 작품   ─ MediaElementSource ─ Gain W ─┘ (Duck을 거치지 않음)
```

- 곡은 **미디어 요소로 스트리밍**하고(통째로 디코드하지 않음 — 4분 곡은 PCM으로 수십 MB), 볼륨은 Web Audio `GainNode`로 바꾼다. iOS는 `audio.volume`을 무시하기 때문이다(F-2). Howler는 쓰지 않는다(2023-09 이후 배포 없음, F-13).
- 미디어는 같은 출처라 CORS 문제가 없다. `crossOrigin="anonymous"`는 다른 출처로 옮길 때를 위해 붙여 둔다.

### 8.2 동작

- 전시실(원래 전시실) 경계를 넘을 때: 쉬는 쪽 요소에 다음 곡을 넣고 재생 → Gain 교차 페이드 1.5초(`BGM_CROSSFADE_SEC`). 같은 전시실의 관이 바뀔 때는 이어서 튼다. 곡 끝나면 처음부터 반복.
- 곡마다 크기 맞추기 이득(서버의 `loudnessDb`로 −16 쪽, ±6dB 제한)을 요소의 Gain에 곱한다. 곡은 `audibleStartMs`부터 재생해 앞 무음을 건너뛴다. 자동 투어의 페이드인·페이드아웃 규칙은 §6.13.
- 소리 작품 재생: Duck Gain을 0.3초에 0.2로(`BGM_DUCK_LEVEL`), 끝나거나 멈추면 0.6초에 1로.
- `소리` 버튼: Master Gain 0/1(0.2초), 값은 기기에 기억(PRD G-06).
- 배경음악이 없는 전시실: 이전 곡을 1.5초에 줄이고 조용히.
- 곡은 모두 `preload="none"`. 첫 곡은 `입장하기` 순간 스트리밍으로 시작한다(첫 화면 예산 §2.5 밖, Codex 지적). 다음 전시실 곡은 그 전시실 마지막 작품에 도착했을 때 `metadata`만 받아 둔다.

### 8.3 잠금 풀기 (iOS·Android 자동 재생 제한)

- `입장하기` 누름 안에서: `AudioContext` 만들기·`resume()` → 요소 셋에 자체 배포 무음 파일(`/assets/silence-…mp3`)을 넣고 `muted`로 `play()`를 **기다린 뒤** `pause()`(각 요소가 사용자 동작으로 한 번 재생된 상태가 됨). `play()` 약속이 거절되면 그 요소는 잠금 실패로 표시하고 `소리` 버튼을 꺼짐 모양으로 둔다 — 학생이 `소리`를 누르면 그 누름에서 다시 잠금 풀기 → `navigator.audioSession.type = 'playback'`(있을 때만, Safari 16.4+, 무음 스위치를 켜 둔 iPad에서도 들리게 — iOS 17+에서 확인됨, F-2).
- 화면 잠금·앱 전환 뒤 돌아오면 `AudioContext.state`가 `interrupted`·`suspended`일 수 있다 → `visibilitychange`와 다음 누름에서 `resume()`.
- 교사 투어도 시작 버튼 누름에서 같은 잠금 풀기.

### 8.4 시험

- P1-6 실기기 관문: iPad(무음 스위치 켬/끔)·iPhone·갤럭시탭·Android 폰에서 교차 페이드·낮추기·끄기·잠금 뒤 복귀. 하나라도 안 되면 그 기기에서는 교차 페이드 대신 "줄이고 멈춘 뒤 새 곡"(볼륨이 안 바뀌면 낮추기 대신 배경음악 잠시 멈춤)으로 바꾸고 ADR에 남긴다.

## 9. 서버 (`apps/server`, ADR-001·003·039)

### 9.1 시작과 끝

- **멱등**(Codex 지적): 만들기는 모두 기기가 만든 ID(전시·전시실·작품·쪽)가 키다. 반응은 따로 ID를 보내지 않고 (방문자 토큰 해시, 작품)이 키다(PUT이라 같은 작품에 다시 보내면 고치기, 2026-11-12 서버 코드에 맞춤). 같은 ID로 다시 오면 저장해 둔 요청 해시(`create_hash` = 본문 SHA-256, 파일은 내용 해시)가 같을 때 처음 결과를 그대로 돌려주고(전시 만들기면 같은 입장 코드, PIN 중복 검사도 자기 자신은 건너뜀), 다르면 `E_CONFLICT`. 학교 와이파이가 끊겼다 이어질 때 다시 보내기가 안전하다.
- **고치기 충돌**: 전시·전시실·작품 행마다 `rev`. PATCH·DELETE는 `If-Match: {rev}`, 어긋나면 `E_CONFLICT` → 화면이 새로 불러옴. 순서 바꾸기는 위처럼 집합 비교. 동시에 올리기 3개가 서로의 `rev`를 막지 않도록 만들기는 `rev` 검사를 하지 않는다.
- **대표작 규칙**(한 트랜잭션): 대표작으로 고르면 같은 전시실의 기존 대표작을 먼저 푼다. 대표작을 다른 전시실로 옮기면 대표 표시가 풀린다. 지운 대표작을 되살릴 때 그 전시실에 이미 대표작이 있으면 표시 없이 되살린다.
- **전시 경계**(Codex 지적): 모든 교사 요청은 "토큰의 전시 = 대상 행의 전시 = 참조하는 행(전시실·작품·asset)의 전시"를 공통 검사(`assertSameExhibition`)로 확인하고 어긋나면 `E_NOT_FOUND`(있는지 알려 주지 않음). DB 복합 외래키가 뒤를 받친다(§10.2). 시험: 전시 A 토큰으로 B의 작품·전시실·반응 ID를 넣은 요청이 모두 거절.
- 교사 응답에서 받는 쪽 화면이 쓰는 미디어 주소는 `/assets/g/m/{exhibitionId}/{assetId}/{variant}.{ext}`.

### 9.3 미들웨어

`requestId` → 보안 머리(§11.4) → 본문 크기 제한(JSON 64KB, 업로드 경로만 스트리밍 26MB·소리 21MB) → zod 검증 → 속도 제한 칸 → 처리 → 오류 봉투. 로그에는 별명·메모·PIN·토큰·IP 원문을 남기지 않는다(§9.8).

### 9.4 업로드 받기와 처리 (`media/`)

0. **본문을 읽기 전에**(Codex 지적): 인증 → 전시 경계·상태(지우는 중·만료면 거절) → 속도 칸 → 동시 수신 칸(전시당 3, 전체 `UPLOAD_SLOTS_GLOBAL` 6, 넘으면 `E_BUSY`) → `Content-Length` 필수(없거나 한도를 넘으면 바로 `E_FILE_TOO_LARGE`) → **공간 예약**(받을 크기 × 3 = 임시 + 파생 여유를 전시·전체 한도에서 미리 잡고, 끝나면 실제 크기로 정산, 실패·끊김이면 풂).
1. 이 경로는 Hono 본문 파서를 쓰지 않고 Node 요청(`c.env.incoming`)을 `busboy`에 바로 넘긴다(한 스트림을 두 번 읽지 않게). 한도: 파일 1·필드 1(`meta`)·부분 3·파일 크기. `limit`·`truncated`면 끊고 `E_FILE_TOO_LARGE`, 연결 끊김·120초 무응답이면 임시 파일을 지우고 예약을 푼다. `TMP_DIR`에 쓴다.
2. `file-type`으로 매직 바이트 확인. 확장자·선언 형식과 다르면 매직 바이트를 믿고, 받지 않는 형식이면 `E_FILE_TYPE`/`E_VIDEO_UNSUPPORTED`.
3. 공간 한도(0번 예약이 지키는 값): 전시당 합계 `EXHIBITION_MAX_MB`(800MB), 미디어 폴더 전체 `MEDIA_DISK_MAX_GB`(40GB), 디스크 남은 공간 `DISK_FREE_MIN_GB`(10GB) → 넘으면 `E_QUOTA`.
4. 같은 내용 해시가 그 전시의 지우지 않은 작품에 이미 있으면 `E_DUPLICATE`(기기가 먼저 걸러 주지만 서버도). 지운 작품과 같은 파일은 다시 올릴 수 있다.
5. 대기열(동시 `PROCESS_CONCURRENCY`=1, 대기 30개 넘으면 `E_BUSY` 재시도 가능) → HEIC면 `sips`(시간 제한 20초) → sharp(§5.4) → 파생 파일을 `MEDIA_DIR/exh/{exhibitionId}/{assetId}/`에 쓰고(임시 이름 → 이름 바꾸기로 원자적) → 한 트랜잭션으로 asset·artwork 행 → `layout_dirty=1` → 임시 파일 지움.
6. 실패: 작품은 `FAILED` + 사유 코드(카드에 한 줄), 파일 정리.

### 9.5 반응 CSV (G-15)

- 열: 작품, 전시실, 스티커, 메모, 사실 정확성, 전달력, 별명, 시각(한국 시각 `YYYY-MM-DD HH:mm`), 숨김(예/아니오). 반응 하나가 한 줄.
- UTF-8 BOM + CRLF(엑셀 한글), 모든 칸 따옴표 처리, 수식 주입 막기(`=`·`+`·`-`·`@`·탭·CR로 시작하면 앞에 `'`).
- 파일 이름 `반응_{전시 이름}_{YYYYMMDD}.csv`(RFC 5987 `filename*`).

### 9.6 정적 파일·캐시 머리 (ADR-028)

| 경로 | `Cache-Control` | 비고 |
|---|---|---|
| `/assets/g/*` (앱 JS·CSS·글꼴·템플릿 3D, 해시 이름) | `public, max-age=31536000, immutable, stale-if-error=604800` | 바뀌면 이름이 바뀜 |
| `/assets/g/m/*` (작품 미디어) | `public, max-age={min(30일, 남은 기간)}, s-maxage={min(1일, 남은 기간)}, stale-if-error={min(1일, 남은 기간)}` + `ETag`·`Accept-Ranges` | 삭제 뒤 CDN 사본은 길어야 1일, 브라우저 사본은 보관 기간을 넘지 않음 |
| `/`, `/{code}`, `/t/*` (HTML) | `no-cache` | |
| `/sw.js` | `no-cache` | |
| `/api/*` | `no-store` | |

- CloudFront 동작을 새로 쓰지 않고 다른 앱과 경로가 겹치지 않게 캐시할 것은 모두 `/assets/g/` 아래에 둔다(ADR-002). `stale-if-error`로 맥미니가 잠시 멈춰도 CDN이 이미 가진 사본을 계속 내준다(ADR-049).
- **오류 응답과 CDN**(2026-11-12, AWS 문서 "How CloudFront processes HTTP 4xx and 5xx status codes" 확인): CloudFront는 404를 "오류 캐시 최소 TTL"(기본 10초)과 원본의 `max-age`·`s-maxage` 중 긴 쪽만큼 엣지에 두며, 캐시를 막는 머리가 붙은 4xx는 그 대상에서 뺀다. 서버는 미디어·정적 404와 416에 `no-store`를 붙인다(P3-7). 최악이어도 404가 한 엣지에 10초 — 작품 주소는 처리가 끝난 뒤에야 알려지고 지운 전시는 404가 맞으므로 문제없다. 416은 CloudFront가 캐시하는 코드가 아니다. P7-2 콘솔 작업 때 오류 캐시 최소 TTL을 0으로 둘지 본다(U-01).
- **끝내기와 흘려보내기**(2026-11-12): 요청은 응답 본문이 다 나가거나 받는 쪽이 끊어야 끝난 것으로 센다(`http/lifecycle.ts`) — 큰 미디어를 보내는 도중에 끝내기 대기가 먼저 풀리지 않게. 끝내기 시간(`SHUTDOWN_WAIT_SEC`)이 지나면 그대로 닫는다.
- "지금 삭제" 뒤 CDN에 남은 사본은 주소(무작위 UUID)를 아는 사람만 받을 수 있고 1일 안에 사라진다. CloudFront 무효화 호출은 AWS 키가 서버에 필요해 기본으로 쓰지 않는다(`CDN_INVALIDATE_ENABLED`, U-01 하위 결정).
- **기기 쪽 사본**(Codex 지적): Cache API는 HTTP 머리로 만료·삭제되지 않고, 꺼진 기기에서 만료 시각에 코드를 돌릴 수도 없다. 그래서 서비스 워커가 전시별 `{exhibitionId, expiresAt}` 목록(IndexedDB)을 들고 ① 활성화 ② 앱 시작 ③ 화면 복귀 ④ 그 전시 미디어 요청 때마다 지난 전시의 캐시를 지운다. `GET /api/e/{code}`가 `E_NOT_FOUND`면 그 전시 캐시를 바로 지우고, 미디어 응답이 404·410이면 캐시하지 않고 그 전시 캐시를 지운다.
- **서버가 멈췄을 때**(ADR-049): 서비스 워커는 앱 껍데기·템플릿·그 전시 미디어를 캐시 우선, `GET /api/e/{code}`는 네트워크 우선(3초)에 마지막 응답을 대신 쓴다. 한 번 들어온 학생은 맥미니가 멈춰도 관람·줌·소리를 계속하고, 반응은 기기 보내기 줄(§7.3)이 나중에 보낸다.
- **보장 범위**(처리방침에 그대로): 서버 원본은 만료 시각에 바로 접근할 수 없고 60초 안에 지워짐 / CDN 사본은 길어야 1일(주소를 아는 사람만) / 기기 사본은 그 기기에서 앱을 다음에 열 때 지워짐.

### 9.7 작업 (`jobs/`)

- **보관 정리**(60초)와 "지금 삭제"는 같은 함수(`application/deleteExhibition.ts`). 순서(Codex 지적: 행을 먼저 지우면 폴더 삭제가 실패했을 때 다시 할 근거가 사라짐):
  1. `deleting = 1`(행과 함께 남으므로 재시작해도 이어서 함). 그 뒤 모든 쓰기·새 업로드 거절, 학생·미디어 요청은 `E_NOT_FOUND`.
  2. 진행 중인 업로드·처리는 최대 30초 기다리고, 넘으면 취소(임시 파일 삭제).
  3. 미디어 폴더 삭제 — 멱등(이미 없으면 성공). 실패하면 다음 주기에 다시.
  4. 폴더가 없어진 것을 확인한 뒤에만 한 트랜잭션으로 행 삭제(연쇄) → 개수만 기록 → `wal_checkpoint(TRUNCATE)`.
- **만료는 정리 주기를 기다리지 않는다**: 모든 API·미디어 요청이 `expires_at <= now` 또는 `deleting = 1`이면 그 자리에서 없는 전시로 다룬다(60초 틈을 막음). 미디어 요청은 전시 상태를 메모리 캐시(10초)로 확인한다.
- **지운 작품 정리**(1시간): `deleted_at`이 24시간(`PURGE_DELETED_HOURS`) 지난 작품의 파일과 행. 어느 작품에도 붙지 않은 asset 2시간 지난 것. 임시 폴더 1시간 지난 것.
- 시험용: 개발에서만 `RETENTION_TEST_MINUTES`로 보관 기간을 분 단위로(PRD 15.6). 운영에서 켜져 있으면 시작 거부.

### 9.8 기록·감시

- JSON 한 줄 기록(시각·수준·requestId·경로·상태·ms·exhibitionId), 날마다 회전·7개 보관. 별명·메모·PIN·토큰·IP 원문 없음.

## 10. 데이터 모델 (`store/migrations/0001_init.sql`, PRD 11장)

### 10.1 규칙

- SQLite `STRICT` 표. ID는 UUID 문자열, 시각은 UTC 밀리초 정수, 상태값은 대문자 + CHECK, 이름은 snake_case(쌤유니버스·글방과 같음, PRD 11.4 Postgres로 옮길 때 `uuid`·`timestamptz`·`jsonb`로 바꿈).
- 바뀔 수 있는 길이·개수 한도는 SQL CHECK에 넣지 않고 zod와 `config.ts`에서 막는다(PRD `[고정]` 설정 한 곳).
- 만료 전시는 행을 지우므로 "만료되지 않은 전시 사이에서 유일"은 그냥 `UNIQUE`로 지켜진다.

- PRD 11.1과 다른 점: `teacher_token_hmac` 칸 대신 `teacher_sessions`(링크·PIN 세션을 하나로, 링크 새로 만들기가 쉬움), `Visitor.device_id` 대신 기기가 만든 토큰의 해시(위조·추측 방지), 쪽 표, `rev`·버전 칸. `Room` 분할은 PRD대로 저장하지 않는다.

### 10.3 파일

- `MEDIA_DIR/exh/{exhibitionId}/{assetId}/{variant}.{webp|mp3|m4a}` (PRD 11.2 키와 같은 모양). WAV·M4A 원본은 AAC(m4a)로 다시 인코딩하므로 `.wav` 파생은 없다(core `MediaVariantSchema`와 같음, 2026-11-12 바로잡음). 한 번 쓴 파일은 바꾸지 않는다. 지울 때는 `exh/{exhibitionId}/` 통째로.
- `DATA_DIR`·`MEDIA_DIR`은 Time Machine·백업에서 뺀다(30일 삭제 약속, §19).

## 11. 보안·개인정보 (PRD 13장)

### 11.1 토큰 (ADR-025)

- 선생님 링크 토큰·PIN 세션 토큰·방문자 토큰은 **기기가 만든 256비트**(`crypto.getRandomValues`, base64url). 서버는 SHA-256만 저장하고 토큰을 돌려주지 않는다. 같은 요청을 다시 보내도 결과가 같다(글방 ADR-049와 같은 방식).
- 선생님 링크는 `https://{도메인}/t#{토큰}`. 주소 조각은 브라우저가 서버로 보내지 않으므로 CloudFront·Cloudflare·서버 기록에 토큰이 남지 않는다(PRD G-17의 `/t/{교사토큰}` 형식을 보안 때문에 조각으로 바꿈, ADR-044, U-11). 열면 기기 저장 → `history.replaceState`로 조각을 지움 → `Referrer-Policy: no-referrer`.
- 링크 복사는 `···` 안에만, 경고 문구와 함께, **이 기기가 링크 토큰을 갖고 있을 때만** 보인다. PIN으로 들어온 기기는 해시만 있는 링크를 되살릴 수 없으므로 `선생님 링크 새로 만들기`만 보인다("이전 링크는 더 이상 열리지 않아요" 확인).
- `선생님 링크 새로 만들기`: 기존 LINK 세션 전부 삭제 후 새 해시 등록. PIN 세션은 그대로.

### 11.2 PIN (ADR-024, G-17)

- 6~8자리 숫자(글쓰기 앱과 같게 — G-17 `[고정]` "글쓰기 앱과 같은 방식"). 안내 "6자리 이상이면 더 안전해요"는 "8자리면 더 안전해요"로.
- 쉬운 PIN 막기: 같은 숫자 반복, 연속(123456·654321), 흔한 것(목록 50개) → "쉬운 번호예요. 다른 번호로 정해 주세요". PIN 하나로 전시 관리 권한을 얻으므로 필요하다(Antigravity 지적: 전역 PIN 무차별 대입).
- 저장: `HMAC-SHA256(PIN_HMAC_SECRET, pin)`. 만료로 행이 지워지면 PIN도 사라진다.
- 기기 구분: 기기가 처음 열 때 만든 무작위 UUID를 `X-Device-Id`로 보내고, 서버는 `HMAC(RATE_KEY_SECRET, 값)`을 칸 키로 쓴다(원문 저장 안 함). 머리가 없거나 형식이 틀리면 그 IP의 "이름 없는 기기" 칸 하나로 묶어 기기 칸 기준(5회)을 그대로 적용한다 — 머리를 빼서 기기 칸을 피하지 못하게.
- 실패 칸 세 개(`rateBuckets.ts`): ① 기기 5회/10분 → 10분 잠금(PRD 값) ② IP 30회/10분 → 그 IP의 PIN 입력만 10분 잠금(학교 공유 IP를 고려해 높게) ③ 전역 100회/10분 → 모든 PIN 응답 2초 지연. **전시 만들기의 "이미 쓰이는 PIN" 확인도 실패로 센다**(PIN이 있는지 캐내는 길).

### 11.3 남용 막기

- 전시 만들기: 기기 5개/일, IP 30개/일, 전체 200개/일. 시작 코드(ADR-048, 기본 켬): 그 기기 첫 만들기에만.
- 저장 공간: 전시당 800MB, 전체 40GB, 디스크 남은 공간 10GB(§9.4).
- 업로드 횟수(P3-4, 2026-11-12): 기기 600/10분·IP 2,000/10분(`UPLOAD_RATE`) — 폴더째 올리기를 막지 않는 높이. 동시 수신 칸(전시당 3·전체 6)이 실제 부담을 막는다.
- **사용자 IP**(Codex 지적): 서버는 `127.0.0.1`에서만 듣고(터널만 들어옴) 머리 하나만 믿는다. CloudFront 경로면 viewer-request 함수가 `event.viewer.ip`로 **덮어써 넣는** `x-gw-viewer-ip`(시청자가 같은 이름을 보내도 함수가 덮음, 무료 요금제는 직접 만든 원본 요청 정책을 못 써서 `CloudFront-Viewer-Address`를 넘길 수 없음), Cloudflare 직접이면 `CF-Connecting-IP`. `X-Forwarded-For`의 첫 값은 믿지 않는다. 설정 `CLIENT_IP_HEADER`, 운영에서 그 머리가 없으면 거절. IPv6는 /64로 묶어 센다.
- 반응·입장 조회: §9.2 표. IP 칸은 늘 기기 칸보다 높게(교실 30대가 공인 IP 하나).

### 11.4 머리(headers)

- `Content-Security-Policy`: `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:; img-src 'self' blob: data:; media-src 'self' blob:; connect-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'`. (wasm = KTX2 변환기, 인라인 style = R3F·부품 위치 계산)
- `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), fullscreen=(self), screen-wake-lock=(self)`, HSTS(쌤유니버스 상위 도메인 HSTS가 `includeSubDomains`라 하위 도메인도 반드시 HTTPS).
- 외부 출처를 하나도 쓰지 않는다(글꼴·변환기·아이콘 모두 자체 배포). 그래서 학생 기기가 제3자에게 요청을 보내지 않는다.

### 11.5 개인정보

- 수집: (반응을 남긴 경우) 별명·반응·기기 토큰의 해시·시각 / (교사) 학교·학급 이름(선택). 실명 받는 칸 없음. 작품 메타데이터(위치 등)는 서버가 다시 인코딩하며 버린다(원본 저장 안 함).
- 동의 문구는 PRD 13.2. 버전(`CONSENT_VERSION`)을 저장하고, 공개 설정에 '모두에게'가 하나라도 있으면 "다른 친구들도 볼 수 있어요" 판으로 바뀐다.
- 공개를 나중에 켜도 메모는 교사가 고른 것만 보이고(PRD 선택지 자체가 그렇다), 스티커·별점은 집계(수·평균)만 보여 개인이 드러나지 않는다.
- 처리방침 `/privacy`: 항목은 PRD 13.3, 운영자 정보·시행일은 U-10. 제3자 제공·외부 AI 없음. CDN(CloudFront·Cloudflare)은 전송만 맡는다는 문장을 넣는다.
- 보관 30일 뒤 자동 파기, 백업하지 않음.

### 11.6 욕설 걸러내기 (`domain/reactions/profanity.ts`)

- 별명·메모에 적용. 정규화: NFKC → 소문자 → 공백·특수문자·반복 글자 줄이기 → 초성 변형(ㅅㅂ 등)도 같은 목록과 비교.
- 목록은 최소로(흔한 욕설·비하어 수십 개 + 초성 변형). 시험은 가상 문자열로만. 걸리면 저장하지 않고 "다른 말로 적어 볼까요?"(`E_MEMO_BLOCKED`, 학생 문구, 무엇에 걸렸는지는 말하지 않음, 쓴 글은 칸에 남김). 교사는 숨길 수 있다(G-15).

## 12. 디자인 체계 (PRD 9.6, ADR-012)

### 12.1 원칙

- 파스텔이 아니다. 공간의 재질과 빛이 분위기를 만들고, 화면 위 UI는 작고 단단한 **박물관 안내판**이다(PRD `[고정]`).
- 학생 화면·관람·미리 보기는 **템플릿 테마**, 교사 관리 화면은 **"전시 준비실" 중립 테마**(따뜻한 회백 종이 바탕, 짙은 잉크 글자, 템플릿 강조색 하나) — 오래 보는 관리 화면의 가독성을 위해. 3D 미리 보기 안은 템플릿 그대로.
- 스타일: CSS Modules + `tokens.css` + `themes/{templateId}.css`(`[data-theme]`로 CSS 변수만 바꿈). Tailwind·Radix는 쓰지 않고 Base UI(`@base-ui/react`)를 우리 토큰으로 꾸민다(쌤유니버스·글방과 같은 체계).

### 12.2 토큰

- 색(테마마다): `--plate-bg` `--plate-ink` `--plate-ink-sub` `--plate-edge`(황동·나무 테 같은 1px 선) `--accent` `--accent-ink` `--scrim`(줌·시트 뒤) `--danger` / 지도 `--map-paper` `--map-ink` / 로딩 `--loader-*`. 순검정·네온 금지, 글자 대비 AA(4.5:1)를 토큰 단계에서 계산해 맞춘다.
- 글꼴: `--font-ui`(Pretendard), `--font-display`(템플릿 세리프). 글자 크기 단계 7개, 줄 간격 2개.
- 간격 4px 단위, 모서리 `--r-plate`(2~4px, 안내판처럼 각이 살아 있게) `--r-sheet`(16px, 아래 시트만 둥글게 — PRD "둥근 시트").
- 그림자: 안내판의 짧고 단단한 그림자 하나(`--shadow-plate`), 시트용 하나. 유리 효과(`backdrop-filter`)·그라데이션 덩어리 금지.
- 움직임: PRD 8.2 시간을 변수로(`--t-sheet: 300ms` 등)와 곡선 2개.

### 12.3 부품 (`ui/components`)

Button(주요·보조·조용한) · IconButton · Plate(안내판 상자) · TopBar · PositionIndicator · Sheet(아래 시트, 끌어 닫기 훅) · SidePanel · ConfirmDialog(3초 뒤 눌리는 버튼 포함) · Toast(하나만, 행동 버튼 하나) · Tabs · ChipRow(끌기 가능) · Keypad · PinDots · InlineText(눌러서 바로 고치기) · TextArea(글자 수) · Switch · Segmented · Menu(`···`) · ProgressLine · StickerPicker · ScoreRow · QrCode · DropZone · ArtworkCard · EmptyState · Icon.
- 아이콘: Phosphor에서 쓰는 것만 골라 `icons.generated.tsx`(쌤유니버스와 같은 생성 방식), 굵기 Regular 하나(안내판 선 느낌). 화면은 `<Icon name>`만.

### 12.4 템플릿별로 함께 만드는 화면 요소 (PRD 7.2)

- 기본 포스터: 배경 그림 1~2장(생성) + HTML 조판(전시 이름 세리프 큰 글자·소개·기간·학교). 포스터 이미지를 올리면 그 이미지를 쓰고 글자는 아래 안내판에.
- 로딩 화면: 근대 역사관은 호두나무 바탕 위 황동 가는 선 진행률 + 전시 이름.
- 지도: 종이 질감 + 잉크 선 + 세리프 이름(§4.9).
- 근대 역사관 세리프 후보(모두 OFL): Hahmlet · Noto Serif KR · MaruBuri. P1-6 시안에서 고르고 U-07에서 확인.
- 글꼴은 자체 배포: Pretendard는 npm `pretendard` 동적 부분집합(글방과 같음), 세리프는 쓰는 글자 범위로 나눈 woff2(unicode-range).

## 13. 3D 에셋 제작 (PRD 7장, ADR-013·034)

### 13.1 규격 (`tools/assets/spec/modules.md`)

- 단위 m, glTF Y-위, 벽 안쪽 면이 +Z, 기준점은 벽 시작 쪽 바닥. 길이 2m·4m, 높이 4.0m, 두께 0.3m, 문 2.0×2.8m.
- UV0 = 세계 크기 타일(1 UV = 1m), UV1 = 굽기용 아틀라스(겹침 없음, 1024 기준 여백 4px). 굽기 해상도 128px/m.
- 이름 `mh_wall_4m`처럼 `{템플릿 약자}_{종류}_{치수}`. 재질 칸 이름도 고정(`M_Panel`·`M_Plaster`·`M_Molding`·`M_Floor`·`M_Ceiling`·`M_Brass`).
- 삼각형 예산: 벽 4m ≤ 1,200, 문 ≤ 2,000, 천장 조각 ≤ 800, 벤치 ≤ 3,000, 화분 ≤ 5,000, 템플릿 고유 합계 ≤ 60,000.
- 근대 역사관 v1 조각(16종): 벽 2m·4m, 문 있는 벽, 안·바깥 모서리, 바닥 판(관 크기로 늘림), 천장 2×2(우물천장 + 황동 레일 조명), 입구 홀 묶음(전시 이름 사인 벽 포함), 출구 벽, 회랑 문틀(관 입구 테두리), 이름판 받침, 소개 글판, 벤치, 화분, 차단봉(선택), 소리 명판 받침.

### 13.2 만들기 (Blender 스크립트, 원본 파일 없이 다시 만듦)

- `tools/assets/blender/build.py --template modern-history`: 매개변수(치수·단면 곡선)로 조각을 만들고(징두리 판벽·몰딩·걸레받이·천장 몰딩은 단면 곡선 + 돌출, 모서리 경사), 재질을 붙이고, UV1을 펴고, 굽기 장면을 꾸미고, 굽고, glb로 내보낸다.
- Blender는 설치 시점에 배포 7일이 지난 5.x 안정판(2026-11-11 최신 5.3.0은 11-10 배포라 5.2 계열 또는 11-17 이후 5.3.0, F-11). KTX-Software `ktx` 4.4.x(`toktx`만 있으면 gltf-transform 4.5가 거부, F-11). 설치는 U-04.
- 무거운 작업이라 `resource-guard run --profile build -- blender -b …`로 한 번에 하나.

### 13.3 굽기 (ADR-013)

- **표준 조명틀**(ADR-051): 천장 아래(z 3.86) 벽에서 1m씩 물러난 넓은 확산광(천창) + 어두운 환경광. x 방향으로 변하지 않아 어느 벽 조각이든 같은 빛을 받고, 벽 0.5~3m가 거의 고르다(가장 밝은 곳 = 작품 띠). 작품 스포트는 굽지 않는다(§6.3).
- **이웃과 함께 굽기**: 벽 조각은 양옆 8m를 같은 조각 사본으로(문은 4m 벽 사이), 위아래에 바닥·천장, 8m 앞에 맞은편 벽. 천장·안쪽 모서리는 8×8m 방, 바깥 모서리는 ㄱ자 공간. 경계에서 보는 주변이 늘 같아 이어 붙여도 이음새가 보이지 않는다.
- Cycles(Metal), 표본 512(천장 ×4) + 위치·법선 길잡이 결합 양방향 걸러내기(잡음 제거), 결과 = 세척광 × AO의 밝기를 **모든 조각 공통 노출**(4m 벽 작품 띠 → 0.62)과 곡선 `1 − e^(−x)`로 회색조 한 장(8비트 선형)에. glTF `occlusionTexture`(texCoord 1)로 내보내고(glTF에 lightMap 칸이 없음, F-11) three에서 `lightMap` channel 1로 옮겨 읽는다(ADR-051). 색이 있는 굽기가 필요해지면 glb 밖 KTX2 + `manifest.json`(§6.2).
- 시험: 벽 조각을 이어 붙인 화면 캡처(`/dev/seam`: 4m·2m·문·4m·4m)에서 경계 ±8px 밝기 차 < 2%, 회반죽·판벽 띠 각각, 조각 한가운데 대조 포함(`tools/assets/pipeline/seamCheck.mjs` + `tests/e2e/seam.spec.ts`).

### 13.4 재질과 소품

- 재질은 CC0만: ambientCG·Poly Haven(호두나무 판벽, 회반죽, 대리석, 황동, 우물천장 나무). 받은 곳·날짜·라이선스를 `tools/assets/LICENSES.md`에. 원본은 `.local/art/sources/`.
- 소품은 먼저 Blender 스크립트로(벤치·받침·글판은 단순한 형태라 모서리 경사와 재질로 충분). 화분·조각상처럼 유기적인 것은 Poly Haven CC0 모델을 줄여 쓰거나 Tripo 유료 플랜(U-03)으로 만들어 면 수를 줄인다.
- 그림(포스터 배경·지도 종이·로딩 장식)은 Codex 그림 생성 또는 Higgsfield(U-03), 시안은 `.local/art/`, 승인된 것만 `apps/web/src/tpl/…`.

### 13.5 최적화 (`npm run assets:build -- modern-history`)

```
Blender → glb → gltf-transform: dedup → prune → weld → resize(질감 2048 상한, 굽기 1024)
       → ktx2 (기본색·라이트맵 ETC1S, 노멀 UASTC) → meshopt → budget.mjs → apps/web/src/tpl/modern-history/ + manifest.json
```

- `budget.mjs`: 템플릿 핵심 합계 ≤ 2.5MB(변환기 포함), 파일마다 삼각형·질감 크기, 이름 규칙, 재질 칸 이름. 넘으면 실패.
- `verifyOutput.mjs`(최적화 **뒤** 산출물 검사): 조각마다 `TEXCOORD_1`이 남아 있는지, `occlusionTexture.texCoord = 1`이 붙어 있는지, 질감이 KTX2인지, 조각 치수가 `manifest.json`·엔진 템플릿 정의와 같은지. `prune`·`weld`·양자화가 UV1이나 구운 빛을 지웠으면 실패(Codex 지적).
- `manifest.json`: 조각 목록·치수(엔진의 템플릿 정의와 대조 — 치수가 다르면 빌드 실패).

### 13.6 검수 (U-07)

- Blender 미리 보기 그림 + 앱 안 캡처(정해진 정지 지점 8곳 × 데스크톱·태블릿 가로·휴대폰 세로).
- Antigravity 디자인 비평 기준: 실제 미술관 사진 같은가 / 이음새 / 질감 반복 티 / 크기 감각(사람 눈높이·문 높이) / 빛 번짐 / 액자가 벽에 붙어 보이는가(접촉 그림자) / UI 안내판과 공간이 어울리는가.
- 사용자 승인: P1 끝 1차(입구 홀 + 관 하나 + 작품 6점 + 줌), P6 끝 최종.

### 14.1 정적 검사 (`tools/check`)

화면·부품 파일의 한국어 문자열(문구는 `copy/ko.ts`만) · CSS의 hex 색(토큰·테마 파일 밖) · 층 위반(`ui`/`viewer` → `adapters`) · 기본 `<select>`·이모지·`backdrop-filter`·그라데이션(3D 셰이더 제외) · `config.ts` 밖 수치(도메인 배치·쪽 나눔 폴더의 숫자 리터럴, 0·1·2 제외) · 의존성 허용 목록.

### 14.2 단위 (Vitest)

배치(§4.11) · 형태 분류 경계값 · 제목 정리(`03_하늘고래_호외.png`, `1919_3.1운동.png`, `01.png`, `.DS_Store`) · 폴더 규칙 · 쪽 나눔(A4 휴대폰 세로·가로·태블릿·데스크톱, 웹툰 800×20000 세 기기, 고해상도 A4가 저해상도보다 더 쪼개지지 않음 — C3 회귀 시험) · 줄 간격 추정(합성 줄무늬 그림) · 글 쪽(시 연 단위, 긴 문단 문장 단위) · 반응 공개 규칙(설정 조합 전부) · 욕설 · 보관 계산·한국 시각 표시 · 투어 일정(5×40, 나뉜 관 최소 20초) · 화면 맞춤 거리 · 상주 관리자(예산·내보내기 순서) · 소리 엔진 상태(가짜 AudioContext).

### 14.3 서버 통합 (임시 SQLite + 임시 미디어 폴더)

- 시험 파일은 모두 합성: GPS EXIF가 들어간 JPEG(지워졌는지), 투명 PNG(알파 유지), 800×20000(띠 개수·폭), 299px(막힘)·799px(경고), 25MB 초과, 비율 31, HEIC(맥에서 `sips`로 만들어 시험, 아니면 건너뜀), ID3·표지가 있는 MP3(태그 지워짐·표지 추출), 11분 WAV(8kHz 무음, 막힘), 깨진 파일.
- 흐름: 만들기(PIN 중복·쉬운 PIN·실패 칸 잠금) → 올리기 각 형식 → 배치 다시 계산·버전(해시 같으면 안 올림) → 반응 멱등·공개 걸러내기 → CSV 모양·BOM·수식 막기 → 지우기·되살리기·24시간 정리 → 보관 만료(가짜 시계) 뒤 행·폴더 없음 → 공간 한도 → 캐시·보안 머리.

### 14.4 화면 (Playwright, Chromium + WebKit)

- 학생: 입장 → 모든 정지 지점(버튼·스와이프·키보드, 연타해도 한 칸) → 줌 0.8초 안 캡션 → 쪽 넘김 → 닫기 → 모아 보기 → 날아가 줌 → 지도 이동 → 반응(동의·별명 바꾸기·끊김 뒤 다시 보내기) → 출구. 키보드만, 동작 줄이기, 2D 대체(`?force2d=1` 개발 깃발), 막 내림·준비 중.
- 교사: 만들기 → 폴더 5개 올리기(`setInputFiles` 폴더) → 전시실 5개·제목·순서·배경음악 자동 → 제목 바로 고치기·끌어 순서·전시실 옮기기 → 삭제·10초 안 되살리기 → 열기 → QR → 반응 탭·CSV → 투어 Space·→·Esc → 다른 브라우저에서 링크·최근 전시·PIN으로 들어가기 → PIN 5번 틀려 잠김.
- 화면 크기 5개(1440×900, 1180×820, 820×1180, 390×844, 844×390)에서 DOM UI 캡처 비교(허용 오차 있음). 3D 화면은 캡처를 남겨 사람이 본다(픽셀 비교로 막지 않음).
- "정지 상태에서 다시 그리지 않음": 시험용 훅으로 `renderer.info.render.frame`을 읽어 10초 동안 그대로인지.

### 14.5 성능·부하 (`tools/perf`)

- 첫 화면 양: 입장 흐름을 돌려 "관람 준비됨"까지 받은 바이트 합(§2.5 표와 비교). 빌드 산출물 크기 예산.
- 프레임: 정해진 정지 지점 순회를 돌며 이동 중 프레임 백분위(p50·p5)·그리기 호출·삼각형·텍스처 MB를 `docs/perf.md` 표로.
- 부하(서버·CDN 증명): Node 스크립트로 21·30 동시 입장(빈 CDN·데운 CDN 두 경우)의 응답 시간·오류율. **이것만으로 첫 관람 4초를 증명할 수 없다**(기기 디코드·그리기·공유 와이파이가 빠짐, Codex 지적).
- 첫 관람(기기 증명, 별도 끝 조건): 브라우저 성능 기록으로 `입장하기` → "관람 준비됨"까지 시간과 그 전까지 받은 전체 바이트(음악 포함)를 잰다. ① 대역 제한(20Mbps·40ms) 한 기기 ② 같은 와이파이의 태블릿 여러 대(U-05·U-16). PRD 15.5 "21대 동시 입장"은 ②로만 통과 처리한다.
- 실기기(U-05): iPad·갤럭시탭·보급형 Android 폰·iPhone + 학교 태블릿. 프레임·메모리(Safari 웹 속성 보기 / Chrome 원격 디버깅)·첫 관람 시간·소리·손짓·회전.

## 15. 단계(phase)와 작업

### 15.1 순서 원칙

1. 제품을 바꿀 수 있는 위험을 먼저 본다: **3D 품질(에셋·조명)**, iPad 메모리·프레임, iOS 소리, 웹툰·A4 읽기, 한국 회선 첫 화면.

5. 다른 에이전트 작업은 동시에 둘까지, 같은 파일은 한 명.

## 19. 운영·배포 (글방 PLAN §15와 같은 틀)

- **서비스**: 전용 서비스 계정 `gwsvc`, launchd 데몬 `com.ssamuniverse.gallery`(Node 프로세스 하나, 컨테이너 없음 — 쌤유니버스 Colima 정지 기록 때문), `ProcessType Interactive`. 포트 4520(운영)·4521·4522(개발), 터널 메트릭 20243. 설치 전에 `lsof`로 다시 확인.
- **터널**: 이 앱 전용 cloudflared 터널, 원본 주소 `origin-gallery.ssamuniverse.com`, Cloudflare WAF가 원본 비밀 머리 없으면 403(쌤유니버스·글방과 같은 방식).
- **앞단**(ADR-002): 기본안이면 글방 배포에 대체 도메인 `gallery.ssamuniverse.com` + us-east-1 ACM 인증서(Cloudflare DNS 검증) + 갤러리 원본(`origin-gallery.ssamuniverse.com`) 추가 + viewer-request 함수에 Host 분기·`x-gw-viewer-ip` 넣기(글방 기본 `*`과 `/assets/*` 동작 모두에 연결) + Cloudflare DNS `gallery` CNAME. 글방이 아직 운영 전이라 지금 "쌤유 앱 공용 입구"로 함수를 설계하는 비용이 가장 작다. 함수 코드는 두 앱 시험(호스트별 경로 표)을 거쳐 게시하고, 되돌리기는 이전 함수 판 다시 게시. 쌤유니버스 배포는 건드리지 않는다.
- **배포**(ADR-060): 공개 저장소 `djqanrudgns12/gallerywalk`의 `main`을 서비스 계정이 HTTPS로 받는다(git bundle 안 씀). launchd가 1분마다 확인해 CI `verify`를 통과한 커밋을 자동 배포한다(pull 방식, self-hosted 러너 없음) → 빌드 → 사전 검사(운영 DB 사본에서 포트 4523으로 새 릴리스, 스키마가 같으면 이전 릴리스도 시작) → 링크 교체·재시작 → 건강 확인 → 실패하면 이전 릴리스 폴더로 바꿔 치기. 마이그레이션은 서버가 시작할 때 앞으로만 한다. 지금 `migrate()`는 더 새 스키마에서 이전 코드 시작을 거부하므로 스키마가 바뀐 릴리스는 자동으로 되돌리지 않는다(ADR-060). 명령은 `sh ops/gw.sh`, 순서는 `docs/runbook.md`.
- **백업**: 하지 않는다(30일 삭제 약속). `DATA_DIR`·`MEDIA_DIR`을 Time Machine에서 뺀다.
- **감시**: 1분마다 `/api/health` + 디스크 + 대기열, 실패 3번이면 알림(쌤유니버스 감시 방식). 수업 시간(평일 08~16시)에는 배포·재부팅·고부하 작업 금지.
- **되돌리기**: 릴리스 폴더 두 개를 남겨 심볼릭 링크로 바꿈. DB는 앞으로만 바꾸므로 이전 릴리스가 새 스키마에서 돈다는 시험이 관문이다.
