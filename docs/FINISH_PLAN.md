## 2. 목표와 하지 않을 것

**목표**
1. PRD MUST(G-01~G-19, G-22)와 15장 완료 기준을 모두 "자동 시험" 또는 "사용자 확인 대기"로 만든다. "코드만 있음"과 "없음"은 남기지 않는다.
2. 첫 수업 전에 실기기·학교망·리허설을 사용자가 할 수 있게 도구와 절차를 준비한다.
3. 1~2를 **가장 적은 실행으로** 한다(§6).

**하지 않을 것(이 계획 동안)**
- 새 템플릿 4종, 도록, 템플릿 바꾸기(P3, v1.1)
- 영상 작품(G-23 MAY)
- 새 의존성. 꼭 필요하면 보고한다.
- 유료 생성 도구 결제(U-03 = 0원)
- 운영 콘솔·launchd·sudo 작업. 이것은 사용자 몫이다(runbook).

## 6. 실행 규약 — 중복 호출·무한 루프·지나친 검증 막기

> 이 절은 실제로 있었던 낭비를 막으려고 만든 것이다(§7 사례). AGENTS §5, 계정 검증 예산 스킬, `verify-guard` 훅과 함께 적용하고, 겹치면 더 엄격한 쪽을 따른다.

### 6.1 위임과 호출 예산

1. **동시 실행 상한**: 브리지 에이전트(Codex·Antigravity) 2 + Claude 서브에이전트 2. `resource-guard status`가 `allowed:false`면 새 위임은 읽기 전용만 보낸다.
2. **보내기 전 확인은 1회**: `agent-bridge status`(같은 작업 ID가 처리 중이면 보내지 않음) + `resource-guard status`. 한 phase 시작 때 한 번 보고, 위임마다 되풀이하지 않는다.
3. **작업 ID당 브리프 1개, 호출 1회**
   - 같은 브리프를 다시 보내지 않는다.
   - 실패하면 원인(등급·한도·범위)을 고친 뒤 **딱 1회** 다시 보낸다. 두 번째도 실패하면 그 에이전트를 이번 phase에서 빼고 Claude 서브에이전트나 Claude 본인이 한다.
4. **쓸 수 없는 에이전트는 바로 뺀다**
   - 답에 `usage limit`, `credits`, `RESOURCE_EXHAUSTED`, `model … not recognized`가 있으면 다시 시도하지 않는다.
   - 다시 쓸 수 있는 시각을 이 문서 §1에 적는다.
   - 지금: Codex 11/16 15:44까지 빠짐, Antigravity 빠짐(`trivial`만 모델이 맞음).
5. **등급은 실제로 되는 것만**: Codex는 검토·보안 `deep`, 구현·시험 `standard`, 정리 `light`. Antigravity는 고칠 때까지 `trivial`(읽기·짧은 의견)만.
6. **서브에이전트 브리프에 꼭 넣을 것**
   - 고칠 파일 목록과 건드리지 말 파일(지금 다른 줄이 고치는 파일)
   - 끝 조건과 돌릴 명령(L 단계)
   - "넓은 검사는 하지 말고 L1·L2까지만" 한 줄
7. **대조·탐색은 한 번에 나눠서**: 저장소 전체 대조는 범위를 겹치지 않게 서브에이전트 2개로 한 번만 한다. 결과는 핵심 주장 3~7개를 직접 확인한 뒤 쓴다(동료 보고 원칙).
8. **위임 결과 받기**: 완료 알림을 기다린다. 그동안 출력 파일을 읽거나 상태를 묻지 않는다(폴링 금지). 받은 뒤 확인은 PLAN §16.4대로 diff → 끝 조건 명령 1회 → 화면이면 캡처 1장.

### 6.2 기다림과 되풀이 — 루프 금지

1. **`resource-guard` 75**
   - 같은 검사는 `--wait-seconds 560`(도구 호출 10분 안)으로 **최대 2회**만 시도한다. 그래도 75면 "미실행(자원 대기)"으로 적고 다음 일로 간다.
   - 75 직후 바로 같은 명령을 다시 내지 않는다. 사이에 읽기·설계·문서 같은 다른 일을 한다.
2. **상한 없는 루프 금지**: `until`·`while sleep`·주기 확인을 쓰지 않는다. 기다림은 백그라운드 실행 + 완료 알림, 또는 상한 있는 단일 대기만 쓴다.
3. **같은 실패**: 2회째에는 가설을 바꾼다. 3회째에는 멈추고 시도·가설·증거를 보고한다(AGENTS §5).
4. **실패한 명령은 고치기 전에 다시 돌리지 않는다.** 환경 문제(포트·서버·권한)는 코드로 고치려 하지 말고 "실행 불가"로 적는다.
5. **CI 기다리기**: push 뒤 `gh run watch <id> --exit-status` 한 번을 백그라운드로 돌린다. `gh run list`를 되풀이하지 않는다. push는 사용자가 시킬 때만 한다.
6. **브리지 `--wait` 상한**: 보통 1800~3000초 1회. 시간이 넘으면 `bridge_thread`로 한 번 확인하고 보고한다.

### 6.3 검증 사다리 — 필요한 만큼만, 끝낼 때 한 번

| 단계 | 언제 | 명령(예) | 비용(이번 세션에서 잰 값) |
|---|---|---|---|
| L0 | 편집 직후, 내 판단이 필요할 때만 | `npx tsc --noEmit -p apps/web/tsconfig.json` 또는 `npx tsc -b`. 형식은 **바꾼 파일만** `npx prettier --write <파일들>` | 수십 초 |
| L1 | 항목을 끝낼 때 | `npx vitest run --project <web\|server\|core> <바꾼 파일의 시험 파일>` | 1초 안팎 |
| L2 | 한 줄(여러 항목)을 끝낼 때 | 바꾼 폴더 단위 vitest + `node tools/check/index.mjs` | 수 초~1분 |
| L3 | 화면·3D 흐름을 바꾼 항목을 끝낼 때 | `resource-guard run --profile test --wait-seconds 560 -- npx playwright test <spec> -g "<그 시험>" --workers=1` | 1~5분(학생 spec 5.1분, 자유 관람 5.3분, 교사 미리 보기 38초) |
| L4 | **phase 끝 1회** | 전체 단위 `npx vitest run --maxWorkers=1` + 그 phase가 건드린 spec 묶음 1회 + `npm run check` | 15~20분 |
| L5 | push 뒤(사용자가 push할 때) | CI `verify`(check·단위·빌드, macOS). **로컬 운영 빌드는 돌리지 않고 CI 결과를 인용한다.** 예외: V-30 prod e2e를 돌릴 때만 로컬 빌드 1회 | 3~13분, 맥미니 자원 0 |
| L6 | phase F6 | 실기기·학교망·리허설(사용자) | — |

**바뀐 것 → 끝낼 때 돌릴 단계**

| 바뀐 것 | 단계 |
|---|---|
| 문서(`*.md`)만 | 없음(링크·표만 눈으로) |
| 문구(`ko.ts`)만 | L1(그 문구를 쓰는 화면 시험) + `check:rules` |
| `config.ts` 값 | L2(그 값을 쓰는 패키지) |
| 순수 함수·도메인(`packages/core/src/domain/**`) | L1 → phase 끝 L4 |
| 서버 경로·작업 | L1(그 경로 시험) |
| 화면 부품(DOM) | L1(jsdom) |
| 3D·걷기·크게 보기(`viewer/**`, `app/visit/**`) | L1 + L3(`walk-dev` 또는 `student`의 한 시험) |
| 교사 흐름 | L1 + L3(`teacher`의 한 시험) |
| 서비스 워커·캐시 | L1 + phase 끝 V-30 prod spec |
| 의존성·빌드 설정 | L4 + L5 |

**재사용 규칙**
- 같은 작업 트리(§6.4 지문이 같음)에서 통과한 검사는 다시 돌리지 않고 인용한다. `verify-guard` 훅이 막으면 따른다.
- L3에서 통과한 시험은 같은 phase의 L4 묶음에서 빼도 된다. 단, 그 뒤 같은 파일을 고쳤으면 넣는다.
- phase 끝 L4가 찍은 캡처를 비평·보고에 그대로 쓴다. 따로 캡처 스크립트를 만들지 않는다.

**시험 만들기 규칙**
- 새 시험은 **구현 전에** 써서 실패를 본다. 이미 구현했다면 자기가 고친 추적 파일만 `git stash push -- <경로>`로 잠시 빼서 보고 바로 되돌린다.
  - 다른 작업자의 파일을 사본으로 바꿔치기하지 않는다(§7 사례 5).
- e2e는 PRD 15장 기준을 직접 보는 것만 만든다. 새 spec 파일을 만들지 말고 기존 spec(`student`·`teacher`·`walk-dev`)에 단계를 더한다. 예외는 `prod.spec.ts`(V-30) 하나다.
- 기대값을 맞추려고 단언을 약하게 하지 않는다. 동작이 PRD대로 바뀌어 기대값을 바꾸면 근거(PRD 절)를 주석에 적는다.
- 일회용 검증 스크립트를 만들지 않는다.

### 6.4 검증 원장(가볍게)

- 지문 = `git rev-parse --short HEAD` + `{ git diff HEAD -- . ':!*.md'; git ls-files --others --exclude-standard -- . ':!*.md' | xargs cat; } | shasum | cut -c1-8`. 문서(`*.md`)만 바뀐 것은 지문을 바꾸지 않는다(§6.3: 문서만 바뀌면 검사 없음).
- 보고에 "실행"으로 적는 검사마다 `[지문] 명령 → 결과(통과 수/실패)` 한 줄을 남긴다. 위치는 그 phase의 PLAN 진행 줄 또는 보고문이다.
- 다음 사람(다음 세션·서브에이전트)은 같은 지문이면 그 줄을 인용하고 다시 돌리지 않는다.

### 6.5 파일·형식 위생

- `prettier --write`는 **내가 고친 파일 경로만**. 폴더 전체(`apps/web/src`)에 쓰지 않는다. 다른 줄이 고치는 중인 파일까지 바뀐다.
- `ko.ts`처럼 여럿이 더하는 파일은 고치기 직전에 다시 읽고, 작은 Edit로만 고친다.
- ADR 번호는 쓰기 직전에 `grep -n "^## ADR-" docs/decisions.md | tail -3`으로 마지막 번호를 본다(겹친 사례: ADR-060 둘).
- 문서 갱신(PLAN 진행·ADR)은 항목마다가 아니라 phase 끝에 1회 한다.
- 파일·의존성을 지우기 전에 `git grep -n <이름>`으로 저장소 전체를 찾는다(`apps/web/dev/`·`tools/`·`ops/` 포함). 지운 뒤 L0 타입 검사를 바로 한다.

### 6.6 제품 성능 규약(새 코드마다)

- 3D에 새로 그리는 것: 그리기 호출 증가를 적는다. 학생 e2e 예산 단언(120/160, 삼각형 30만)이 통과해야 한다.
- 정지 상태 다시 그리기 0을 지킨다. 새 애니메이션은 "움직이는 동안만 `invalidate()`" 패턴(`ZoomDim` 참고)을 쓰고, 끝나면 멈춘다.
- 무거운 화면·도구는 지연 로드한다(3D 엔진은 관람·미리 보기·투어 묶음에만, pdf.js·dnd-kit은 교사 묶음에만). 학생 첫 JS gzip은 143KB에서 +10%를 넘으면 보고한다.
- 텍스처는 상주 관리자로만 올린다. 실패 다시 받기는 `RESIDENCY_RETRY` 상한을 지킨다(무한 재시도 금지).
- 네트워크 다시 시도는 모두 상한이 있다(올리기 `UPLOAD_RETRY_MAX`, 반응 보내기 줄 `REACTION_OUTBOX_MAX`·만료, 서비스 워커 시간 제한). 새 재시도를 만들면 `config.ts`에 상한을 둔다.

### 6.7 보고

- 한국어로 쓴다. 바꾼 파일, 실행한 검사(지문·명령·결과), 미실행과 그 까닭, 사용자 몫을 적는다.
- 질문은 보고 끝 "사용자 몫" 목록으로 모은다. 기본값이 있는 것은 기본값으로 진행하고 그 사실을 적는다.
- 동료가 보고한 수치·해시를 그대로 옮기지 않는다. 직접 확인한 것만 쓴다.
