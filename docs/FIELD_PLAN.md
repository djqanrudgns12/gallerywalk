## 1. 피드백과 진단

### 1.1 학교 와이파이로 들어오지 못함

**결론 먼저**: rollingthunder에는 학교망을 우회하는 특별한 코드가 없다. 학교에서 되는 이유는 **환경 차이**(오래된 도메인·가벼운 학생 화면·한 출처)로 보인다. 그래서 "그 로직을 옮기기"는 ① 연결 진단 페이지, ② 시간 상한 뒤 가벼운 경로로 내려가기, ③ 이미 학교에서 통한 도메인을 대체 입구로 쓰기, 이 세 가지로 옮긴다.

**rollingthunder와 비교(Claude 서브에이전트 조사, 아래 표시한 것은 Claude가 직접 다시 확인)**

| 항목 | rollingthunder | gallery | 차이가 원인일 가능성 |
|---|---|---|---|
| QR 주소 | `origin + /arena/join/{코드}` (`ArenaHostDashboard.tsx:495-502`, 확인) | `origin + /{입장 코드}` (`teacher/shared/links.ts`, 확인) | 없음(같은 방식) |
| 앞단 | CloudFront 서울(ICN57), HTTP/2·h3·HSTS·IPv6 | 같음(같은 POP, 다른 IP 묶음) | 거의 없음 |
| 도메인 나이 | `rollinthunder.net` 2026-07-14 등록, **2026-09-04 소유자 학교 Wi-Fi 실측 기록** 있음 | `ssamuniverse.com` **2026-10-18 등록(26일째)**, `gallery` 인증서 11-12·공개 11-13 (whois 확인) | **높음**: 학교 필터는 흔히 "신규 등록 도메인·미분류"를 막는다 |
| 학생 첫 화면 | 서버 렌더 조작판, 첫 응답 약 7KB | 입장 전에 glb 3개(약 2.4MB)·wasm 0.5MB·3D 묶음 0.33MB·캐릭터 약 1MB를 받아야 함 | **높음**: SSL 검사 프록시·MIME 필터(`model/gltf-binary`, `application/wasm`)가 큰 파일을 붙잡으면 입장 못 함 |
| 준비 시간 상한 | P2P가 8초 안에 안 되면 Supabase로 내려감(`HybridArenaTransport.ts`, `defaults.ts:223`) | **상한 없음**. `requestEnter()`는 `progress.ready`일 때만 받고(`visitorStore.ts:257`), ready는 템플릿 조각이 하나라도 올라와야 온다(`VisitorScene.tsx:124-127`). `loadAsync`가 멈추면 단추가 영원히 잠긴다(확인) | **높음**: 원인이 무엇이든 "들어와지지 않음"으로 보이게 만드는 고리 |
| 연결 유지 | 워커 타이머로 15초 하트비트(`supabase/client.ts:39-42`, 확인), 재연결 ±30% | 메인 스레드 `setTimeout` 30초, 재연결 ±20% | 낮음(함께 관람만 영향) |
| 진단 도구 | `/arena/p2p-test`로 학교망에서 실측해 설계를 정함(위키 기록 확인) | 없음 | — (가져올 것) |
| 빌드 대상 | — | `es2022`(`vite.config.ts:132`, 확인). 3D 묶음에 class static block → Safari 16.4 미만에서 해석 실패 | 중간: 학교 iPad가 오래된 iPadOS면 |
| WAF·IP 한도 | IP당 5분 20,000건, "30대 × 35요청 전부 200" 실측 | 글방 배포의 같은 한도 | 낮음 |

**그 밖의 후보**
- **ADR-069 고장(망과 무관)**: 운영 CSP가 KTX2 변환기를 막아 glb가 끝없이 기다리던 문제는 `04f49d0`(2026-11-13 13:19 KST 커밋, CI 13:23)에서 고쳤다(확인). **수업이 그 전이었다면 학교망과 상관없이 입장 단추가 풀리지 않았을 수 있다.** 수업 시각을 사용자에게 묻는다(U-25).
- **수업 중 자동 배포 재시작**: ADR-068로 금지창이 없다. 11-13에 CI 성공이 여섯 번 있었고, 성공마다 서버가 다시 시작한다. 그때 입장 중이던 기기는 실패를 본다.
- **틀린 입장 코드 IP 잠금**: `badCodeIp` 60회/10분을 넘으면 그 IP 전체가 10분 동안 조회되지 않는다(`config.ts` `PUBLIC_RATE`, 확인). 학교는 공인 IP 하나를 함께 쓰므로, QR이 안 돼서 여러 학생이 코드를 손으로 치면 학교 전체가 막힐 수 있다.
- **함께 관람 IP 칸**: `LIVE_CONNECT_PER_IP_MIN` 120. 여러 반이 같은 IP로 끊겼다 다시 붙으면 걸릴 수 있다(웹 조사 지적). 혼자 관람은 그대로라 입장 실패는 아니다.
- **WebSocket 차단**: 가능성 낮음. 실패해도 혼자 관람으로 이어진다(`socket.ts`).

**아직 모르는 것(사용자에게 물음, U-25)**: 수업 시각, 학생 화면에 무엇이 보였는지(학교 차단 안내 화면 / 포스터는 떴는데 `입장하기`가 안 눌림 / 흰 화면·무한 로딩), 같은 와이파이의 교사 기기는 됐는지, 학생 기기 종류·OS 판.

**사용자 답(2026-11-13, 일부)과 좁힌 것**
- **랜선 데스크톱은 들어가졌다**. 학생 기기는 **학교 와이파이의 갤럭시탭**이었다. 학생 화면 모습은 나중에 다시 확인한다.
- **도메인은 바꾸지 않는다**(U-28 결정 — 대체 입구 HW-03·HW-04 하지 않음).
- 좁힘: 같은 때 랜선 데스크톱이 들어갔다면 ADR-069(모든 기기 공통)는 아니다. 남는 갈래는 둘이다.
  - **(가) 학생 와이파이 쪽 필터**(새 도메인·파일 종류·HTTPS 검사): 학교가 허용해야 풀린다 → 점검 화면(HW-00)으로 확인하고, 허용 요청서(HW-07)를 보낸다.
  - **(나) 태블릿 쪽**: 3D 준비가 끝없이 기다림(HW-01), 3D 묶음을 받지 못해 화면 전체가 내려감(오류 경계 없음 → `LoadGuard`), 갱신이 멈춘 삼성 인터넷이 `Object.hasOwn`(Chromium 93+)에서 멈춤(HW-05 보강), 저가 GPU(Mali-G52 등)에서 느림.
  - (나)는 코드로 막고, (가)는 점검 화면으로 가린다.

### 1.2 실시간 접속 때 조금 렉이 걸림

**확인한 것(코드)**
- 함께 관람 허브(`apps/server/src/live/hub.ts`)는 이미 가볍게 짜여 있다.
  - 전시마다 방 하나, 초당 5번(`LIVE_BROADCAST_HZ`) 묶어 보내고, 바뀐 사람만 보낸다. `perMessageDeflate`는 꺼져 있다.
  - 기기도 초당 5번까지, 바뀌었을 때만 보낸다(`adapters/live/socket.ts`).
  - 다른 관람객은 캐릭터 종류마다 `InstancedMesh` 하나로 그린다(`viewer/live/Peers.tsx`). 사람 수가 늘어도 그리기 호출은 거의 그대로다.
- 그래도 남은 비용이 있다.
  1. **위치 글이 길다**: 좌표를 반올림하지 않고 JSON 숫자 그대로 보낸다(`WalkView.tsx:450`). 한 사람 조각이 약 100바이트다.
  2. **받는 사람마다 글을 새로 만든다**: `tick()`이 받는 사람마다 "자기 것 뺀" 문자열을 따로 만든다. 30명 방이면 한 차례에 30번 이어 붙이고 30번 UTF-8로 바꾼다.
  3. **느린 기기 보호가 없다**: `ws.bufferedAmount`를 보지 않는다. 와이파이가 막힌 기기 쪽 보낼 줄이 서버 메모리에 쌓인다.
  4. **모두에게 모두를 보낸다**: 휴대폰은 몸을 6명까지만 그리는데(`LIVE_VISIBLE_MAX`), 80명 방이면 79명 위치를 초당 5번 받는다.
  5. **다른 사람이 움직이면 내 기기가 계속 그린다**: `Peers.tsx:472`가 누가 움직이는 동안 매 프레임 `invalidate()`한다. 30명이 돌아다니면 사실상 쉬지 않고 그린다. 저가 태블릿이 뜨거워지고 끊긴다.
  6. **받은 메시지마다 zod 검사**: 초당 5번, 사람 수만큼 배열을 zod로 검사한다(`socket.ts`). 저가 기기에서 작지 않다.
- 계산(추정, 반올림 없는 지금 형식): 30명 방이면 학생 한 명이 받는 양은 29명 × 약 100B × 5회 ≈ **14KB/초**, 서버가 내보내는 양은 약 **0.4MB/초**다. 80명이면 각 37KB/초, 서버 약 **3MB/초(24Mbps)**다. 학교 AP 하나를 함께 쓰는 반에서는 이 양이 그대로 와이파이를 차지한다.
- **재지 않은 것**: 서버 이벤트 루프 지연, 터널 지연, 학생 기기 fps. 지금은 로그에 1분마다 연결 수만 남는다. 그래서 "렉"이 서버·네트워크·기기 그리기 중 어디서 왔는지 아직 모른다. → **H0에서 계측부터 한다**(HS-00).

### 1.3 교사 화면이 복잡하고 한눈에 들어오지 않음

**확인한 것(코드: `apps/web/src/app/teacher/manage/*`)**
1. **한 번에 전시실 하나만 보인다**: 작품 격자는 고른 전시실 칩의 작품만 보여 준다(`ManageExhibition.tsx` `inRoom`). 전시 전체 구성을 보려면 칩을 하나씩 눌러야 한다.
2. **고친 결과가 공간에서 어떻게 보이는지 같은 화면에 없다**: 3D 미리 보기는 전체 화면 층으로 따로 열린다(ADR-057에서 오른쪽 미리 보기 칸을 없앰). 순서·전시실을 바꿔도 "어느 벽, 몇 번째"인지 격자에서 알 수 없다.
3. **숨은 조작이 많다**
   - 전시실 고치기는 "한 번 더 누르면"(`roomEditHint`)이다.
   - 여러 장 고르기는 길게 누르기·Shift뿐이다.
   - 형태·쪽 나눔·대표작은 `자동으로 정한 것`을 펼쳐야 보인다.
   - 자동 투어·미리 불러오기·전시 닫기·선생님 링크가 모두 `···` 안에 있다.
4. **위쪽이 네 겹이다**: 이름·상태·삭제일·미리 보기·주요 버튼·`···` / 전시실 칩 줄 / 점검 줄 / 탭. 작품 카드가 화면 아래로 밀린다.
5. **수업 중에 볼 화면이 없다**: QR은 열기 시트, 투어는 `···`, 반응은 탭에 흩어져 있다. 지금 몇 명이 들어왔는지는 어디에도 없다(서버 허브는 알고 있음).
6. **알림이 흩어져 있다**: 올리기 목록·토스트·점검 줄·카드 딱지가 각각 다른 자리에 뜬다.

**바로 쓸 수 있는 것**
- 교사 묶음(`ExhibitionTeacher`)에 배치 결과 `layout`이 이미 들어 있다. 학생 지도 좌표 변환 `viewer/map/mapView.ts`를 그대로 쓰면 3D 없이 평면도를 그릴 수 있다.
- 끌어 옮기기는 `@dnd-kit`(ADR-032)이 이미 있다. 여러 줄 사이 옮기기도 같은 도구로 된다.

## 2. 목표·하지 않을 것·성공 지표

**목표**
1. 학교 와이파이에서 QR로 **들어오지 못하는 일이 없게** 한다. 막히는 망이면 어디서 막혔는지 교사가 1분 안에 알게 한다.
2. 한 반 30명 + 교사, 같은 시간 세 반(약 90명)까지 함께 관람해도 **움직임이 끊기지 않고 서버가 밀리지 않게** 한다.
3. 교사가 **전시 전체를 한 화면에서 보고**, 작품 조정을 끌기 한 번·누르기 한두 번으로 끝내게 한다. 수업 중에는 **한 화면(수업 탭)**만 보면 되게 한다.

**하지 않을 것**
- 유료 플랜·서버 증설·새 유료 서비스(PRD 0.2-3 `[고정]`).
- 함께 관람 기능 자체를 빼거나 학생 화면 디자인(F8)을 다시 뒤집는 일.
- 새 의존성은 꼭 필요할 때만 보고 뒤 Claude가 판 고정·7일 규칙으로 넣는다(uWebSockets.js 같은 교체는 이번 범위가 아님, §4 HS-11 참고).
- 학교망 장비(방화벽·필터) 설정을 우리가 바꾸는 일. 학교 정보 담당에게 요청할 문서만 만든다.

**성공 지표(PRD 15.9가 완료 기준)**

| 지표 | 지금 | 목표 |
|---|---|---|
| 학교망 입장 성공 | 실패 사례 있음 | 같은 학교망 태블릿 3대 모두 포스터까지(대체 주소 포함) |
| 3D 준비가 막힐 때 | `입장하기`가 끝없이 잠김 | 20초 안에 가벼운 화면(2D)으로 들어감, 교사 진단 페이지가 막힌 단계 표시 |
| 위치 받는 양(30명 방, 학생 1명) | 약 14KB/초(추정) | 4KB/초 이하 |
| 서버 이벤트 루프 지연 p99(90명, 10분) | 미측정 | 30ms 이하 |
| 다른 사람만 움직일 때 학생 기기 그리기 | 매 프레임 | 초당 `LIVE_PEER_REDRAW_FPS`(기본 20) 이하 |
| 교사 과업 5개(§5 HT-00) 누름 수 | H0에서 잼 | 기준의 절반 이하 |

## 5. 갈래 HT — 교사 작업 화면 개편

> 원칙: PRD 9.4 "버튼 최소·편의성" `[고정]`과 9.6 디자인 언어를 지킨다. 새로 더하는 것은 **보이는 정보**이지 버튼이 아니다. 숨은 조작은 꺼내고, 겹친 층은 줄인다.

### 5.1 새 화면 구조(추천안 A — U-26에서 사용자가 고름)

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ ‹  S.O.S. 연대기 전시관 ✎   ● 열림 ▾     [ 작품 | 수업 | 반응 ]   [미리 보기] [전시 열기] ··· │  ← 한 줄
├───────────────────────────────────────────────────┬──────────────────────────┤
│ 확인할 것 2  (제목 없음 1 · 흐림 1)       보기: 크게 | 작게 │  평면도(배치 결과)         │
│ ┌ 1 을사늑약과 의병 ✎ ♪ 8점 ───────────────────────┐ │  ┌───┬───┐                 │
│ │ [1][2][3][4][5][6][7][8]   + 여기로 끌어 놓기    │ │  │ 1 │ 2 │  ●3 고른 작품    │
│ └──────────────────────────────────────────────────┘ │  └───┴───┘                 │
│ ┌ 2 3·1 운동 ✎ ♪ 12점 ────────────────────────────┐ │ ─────────────────────────│
│ │ [1][2][3] … [12]                                 │ │  작품 살펴보기(고른 것)   │
│ └──────────────────────────────────────────────────┘ │  제목·작가·설명           │
│ ┌ 3 … ┐                                            │  걸기: 전시실·순서 3/12·  │
│ + 전시실 더하기                                     │  형태·대표작·게시         │
│                                                   │  [3D로 보기]  ‹ 이전 다음 › │
└───────────────────────────────────────────────────┴──────────────────────────┘
```

- **전시실 줄 보드**: 모든 전시실을 위에서 아래로 줄로 늘어놓고, 줄 안에 작품을 관람 순서대로 왼쪽 → 오른쪽으로 놓는다. 전시 전체가 한 화면에 들어온다. `작게` 보기면 1440×900에서 전시실 5개·작품 40점이 스크롤 없이 보인다.
- **평면도**: 배치 결과를 2D로. 고른 작품의 자리가 빛난다. 평면도의 자리를 눌러도 그 작품이 골라진다.
- **작품 살펴보기**: 지금 오른쪽 작품 패널을 다시 짠 것. 접힌 칸이 없다. `‹ 이전 · 다음 ›`으로 닫지 않고 다음 작품을 고친다.
- **모드 세 개**: `작품`(꾸미기) · `수업`(새) · `반응`. 전시가 열려 있으면 처음 들어올 때 `수업`이 열린다.

**대안 B(시안에서 함께 보임)**: 평면도를 가운데 크게 두고 벽 위 작품 자리에 직접 끌어 놓는 방식. 공간 감각은 더 좋지만 배치 엔진이 자리를 자동으로 다시 정하므로 "놓은 자리 ≠ 계산된 자리"가 생기고, 휴대폰에서 쓰기 어렵다. 그래서 A를 추천한다.

## 6. Phase 순서

```
H0 진단·계측(1일) ─┬─▶ H1 학교망 접속 보강(1.5일, 최우선) ──────────────┐
                    ├─▶ H2 실시간·서버 성능(2일) ─────────────────────────┤
                    └─▶ H3 교사 화면 시안 → U-26 ─▶ H4 교사 화면 구현(3일) ─┴─▶ H5 현장 검증(사용자)
```

| phase | 줄 | 담당 | 할 일 | 끝 조건 |
|---|---|---|---|---|
| H0 | ① | C | HW-00 진단 페이지 · HS-00 계측 | 진단 페이지가 개발 서버에서 단계별 결과를 보임, 서버 1분 기록에 지연·보낸 양이 찍힘 |
| H0 | ② | Cs | HT-00 기준선(교사 과업 누름 수·캡처) | §10에 표 |
| H0 | ③ | X(11/16 뒤) | HS-01 부하 기준선 실측 | `.local/perf/live-load.jsonl` |
| H1 | ① | C | HW-01 → HW-02 → HW-06 → HW-05 → HW-09 → HW-07 (HW-03·HW-04는 U-28 뒤, HW-04는 HT-07 다음) | §3 H1 끝 조건, L1·L2, 학생 e2e 한 시험 L3 |
| H1 | ② | X(11/16 뒤) | HW-08 자동 배포 미루기(U-30) | 스크립트 시험 |
| H2 | ① | C | HS-02~HS-06(허브·프로토콜·기기 그리기) | §4 끝 조건, 같은 부하로 HS-01 다시 재어 비교 |
| H2 | ② | X | HS-07~HS-10(이벤트 루프·정적·터널·한계) | 같음 |
| H3 | ① | C | HT-01 시안 → U-26 | 사용자 선택(없으면 A로 진행) |
| H4 | ① | C | HT-02~HT-09 | §5 끝 조건 |
| H4 | ② | Cs | HT-10 좁은 화면 | 캡처 |
| H4 | ③ | X·A | HT-11 검토·비평 | 반영 기록 |
| H5 | — | U | §7 현장 검증 | PRD 15.9 체크 |

- **순서 이유**: 학교망은 다음 수업을 막는 문제라 먼저 한다. 성능은 재야 고칠 수 있어 계측을 H0에 둔다. 교사 화면은 사용자 선택이 필요해 시안을 일찍 내고 기다리는 동안 H1·H2를 한다.
- **겹침 규칙**: `copy/ko.ts`·`config.ts`·`ports/index.ts`는 C만 고친다(Cs·X는 "더할 것"으로 보고). 서버 `live/*`는 H2 ① C, 서버 `http/routes/static.ts`·`upload/*`·`tools/load/*`는 H2 ② X.
- **다른 세션이 끝낸 작업**: 앱 빌드 파일 미리 압축(`apps/web/scripts/precompress.ts`, `static.ts`의 br/gzip 응답)은 다른 세션이 `edb6287`로 커밋했다. 대상은 `.js·.mjs·.css·.html·.svg·.json·.wasm·.webmanifest`이고 glb는 빠져 있다. HS-08은 CloudFront 캐시 키 확인과 glb 포함 여부 판단만 더한다.
- **검증**: 줄 끝 L1·L2, 화면 흐름 L3 한 시험, phase 끝 L4 1회, push 뒤 L5(CI 인용). 학교망·실기기는 L6(사용자, §7).

## 7. 현장 검증 (사용자, H5)

1. **학교망 진단(5분)**: 학교 와이파이에 붙은 태블릿 1대로 진단 주소(HW-00)를 연다. 결과 화면을 사진으로 남긴다. 실패 단계가 있으면 그 화면을 Claude에게 보여 준다.
2. **QR 입장(5분)**: 갤럭시탭 포함 태블릿 3대로 QR → 포스터 → 입장. 3D가 늦으면 "가벼운 화면으로 먼저 볼게요"로 들어가지는지 본다. 포스터조차 안 뜨면 그 화면을 사진으로 남기고(학교 차단 안내인지) 점검 결과를 정보 담당께 보낸다.
3. **함께 관람 리허설(10분)**: 태블릿·휴대폰 가능한 만큼 + 교사 노트북 수업 탭. 들어온 학생 수가 맞는지, 움직임이 끊기지 않는지, 기기가 뜨거워지지 않는지 본다. 학생 기기 한 대는 주소 끝에 `?perf=1`을 붙여 열고 숫자판(fps·받는 양)을 사진으로 남긴다(HS-00).
4. **교사 과업 5개(10분)**: §5 T1~T5를 새 화면으로 해 보고 "한눈에 보이는가"를 판정한다(U-27).
