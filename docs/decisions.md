## ADR-001 · 호스팅: 맥미니 자체 호스팅

- **결정**: 서버·DB·작품 파일을 쌤유니버스가 도는 맥미니에 **별도 서비스**(전용 서비스 계정, launchd 데몬, 전용 터널, Node 프로세스 하나)로 둔다. PRD 12.2의 Cloudflare Workers + R2 + D1을 쓰지 않는다.
- **이유**
  1. 한국 회선 지연: 쌤유니버스·rollingthunder 기록에 Cloudflare 무료 경로가 KT 이용자를 미국 거점으로 보내 166~306ms, workers.dev 첫 응답 0.89초가 실측돼 있다(정찰: `rollingthunder/wiki/decisions/입구-구조-CloudFront-터널.md:106-127`). R2 사용자 도메인도 같은 경로일 가능성이 크다. 첫 관람 4초(PRD 10.1)가 위태롭다. 지금도 그런지는 공식 근거가 없어(F-7) P1-8에서 다시 잰다.
  2. Workers 무료 CPU 10ms 때문에 PRD가 모든 처리를 브라우저로 보냈는데, 브라우저 처리는 Safari WebP 인코딩 불가(F-1)·큰 웹툰·iPad 메모리에서 막힌다. 맥미니면 sharp로 서버에서 처리할 수 있다(ADR-005).
  3. R2 무료 10GB는 원본 보관 시 금방 찬다(Antigravity). 맥미니 디스크는 한도 문제가 없다.
  4. 같은 사용자의 글방(writeessay ADR-037)·쌤유니버스와 같은 운영 틀이라 스크립트·감시를 그대로 쓴다. 비용 0원(PRD 0.2-3 `[고정]`).
- **버린 대안**: Cloudflare Workers·R2·D1(위 1·2), 쌤유니버스 컨테이너에 넣기(Colima 정지 기록 1시간 45분, 쌤유니버스 백업에 섞이면 30일 삭제 약속이 깨짐 — 글방 ADR-039).
- **되돌리기**: 저장은 `AssetStore`·저장소 포트 뒤에 있어 S3 호환·Postgres로 바꿀 수 있다(PRD 11.4). 처리는 서버에 있지만 순수 함수 부분(분류·쪽 계획)은 공용 패키지다.

## ADR-002 · 주소와 앞단

- **주소**: 쌤유니버스 서브 URL이 아니라 **별도 하위 도메인 `gallery.ssamuniverse.com`**. 서브 URL이면 쌤유니버스 세션 쿠키(`cp_session`)와 같은 출처가 되어 갤러리 결함이 번질 수 있고, CSP·배포·백업이 쌤유니버스에 묶인다(정찰 6번, 글방 ADR-047과 같은 이유). 주소 이름은 어느 앞단·어느 AWS 계정을 쓰든 그대로다(DNS가 Cloudflare에 있음).
- **확인한 사실 (2026-11-11, AWS 공식 문서)**
  - Free 요금제: 계정당 **3개, 늘릴 수 없음**. 요금제 하나 = 배포 하나 + 상위 도메인 하나(같은 상위 도메인의 하위 주소는 여럿 가능). 한도(월 100만 요청·100GB)를 넘어도 **추가 요금 없음**, 오래 크게 넘으면 속도 조정. 캐시·원본 요청 정책은 **관리형만**(직접 만든 정책은 Business 이상). CloudFront Functions 포함.
  - 지금 세 자리: 쌤유니버스(`E1VKUXOJAO8KBE`) · rollingthunder(`E3DFFMH3173961`) · 글방(`E3TFCRGRU1HG1Q`).
  - 요금제 없는 종량제 배포도 같은 계정에 둘 수 있고, 상시 무료 한도(월 1TB 전송·1천만 요청·함수 200만 회, 한국 첫 1TB 무료)가 있다. 넘으면 과금되고 상한이 없으며, 종량제에서는 WAF가 유료다.
  - AWS 무료 이용 약관은 "추가 혜택을 받으려고 여러 계정을 만들면 혜택 대상이 아니다"라고 쓴다. Free 요금제를 직접 언급하지는 않지만, 계정당 3개 상한을 일부러 두었다.
- **선택지와 판단**

| 순위 | 안 | 비용 | 판단 |

## ADR-003 · 저장: SQLite 파일 하나

- **결정**: `better-sqlite3` + SQLite(WAL) 파일 하나, `STRICT` 표. SQL은 Postgres로 옮길 수 있게 쓴다(UUID 문자열·UTC 밀리초·대문자 상태값, PRD 11.4). 백업하지 않는다.
- **이유**: 실시간이 필요 없고 쓰기가 적다(수업당 반응 수백 건). 컨테이너 없이 돌아 재부팅 복구가 빠르다. 30일 자동 삭제 약속 때문에 백업하지 않는다(글방 ADR-039와 같음).
- **버린 대안**: 쌤유니버스 Postgres 공유(백업·운영 결합), D1(ADR-001).

## ADR-004 · 파일: 맥미니 디스크, 원본 저장 안 함

- **결정**: `MEDIA_DIR/exh/{exhibitionId}/{assetId}/{variant}` (PRD 11.2 키 모양). **받은 원본은 처리 뒤 지우고**, 서버가 다시 인코딩한 파생 파일만 남긴다. 소리도 같다: MP3는 태그(ID3·APE)를 떼고, M4A·WAV는 macOS `afconvert`로 AAC로 다시 인코딩한다(아이폰 녹음 M4A의 위치 상자 대비). 한 번 쓴 파일은 바꾸지 않는다.
- **이유**: 위치 정보 등 메타데이터 삭제(PRD 6.4·13.1)를 가장 확실하게 지키는 길이다(C17). 저장 공간도 크게 준다. Antigravity도 같은 추천(사용자 결정 5번)을 냈지만 PRD 취지 안의 일이라 에이전트가 정한다.
- **되돌리기**: `AssetStore` 포트 뒤라 S3 호환으로 바꿀 수 있다.

## ADR-005 · 작품 처리 분담

- **결정**: 교사 기기 = 형식·크기·치수·쪽 수·길이 사전 검사 + PDF → 쪽 그림(pdf.js 6.5, CMap·표준 글꼴 포함). 서버 = 매직 바이트 재확인 + HEIC → JPEG(macOS `sips`) + sharp(회전·sRGB·메타데이터 버림·파생·분석). PRD 6장 "브라우저 Web Worker에서 처리"를 바꾼다(`[추천]`).
- **이유**: Safari는 WebP 인코딩이 안 되고 PNG로 바뀐다(F-1). sharp 기본 바이너리는 HEIC를 못 읽고(F-5) Chrome·Edge·Samsung Internet도 못 읽는다(F-4) — 맥미니의 `sips`는 Apple 코덱이라 추가 설치·라이선스 문제가 없다. 큰 그림·고해상도도 기기 메모리와 상관없이 같은 품질로 나온다. PDF만은 원본을 서버에 남기지 않으려고 기기에서 그림으로 바꾼다.
- **버린 대안**: 전부 브라우저(위 이유), WASM WebP·HEIC 인코더(번들 수 MB, libheif LGPL), PDF를 서버에서 렌더(PDF 원본이 서버에 옴).

## ADR-006 · 파생 규격

- **결정**: `thumb` 512 · `wall` 1600 · `wall-lo` 1024 · `zoom` 2048 · `zoom-hi` 4096(원본이 클 때만) · 긴 세로·파노라마는 짧은 변 1440 이하로 맞춰 긴 축 2048px **띠**로 저장 · PDF 쪽 2048 · 소리 표지 512. 모두 WebP(알파 유지). 긴 세로·파노라마의 `thumb`·`wall`은 벽에 보이는 창 부분만 잘라 만든다.
- **이유**: PRD 6.6 "줌: 원본 최대 4096"을 긴 축에 적용하면 800×20000 웹툰이 164×4096이 된다(C2, Antigravity도 같은 지적). WebP는 한 변 16,383px 한계가 있어 띠가 필요하다(F-5). 쪽은 기기마다 달라야 하므로(PRD 6.7) 미리 자른 "쪽 조각"이 아니라 고정 띠 위에서 기기가 창을 정한다. 투명 배경은 파일에서 채우지 않고 화면에서 매트 색 위에 그린다 — 템플릿을 바꿔도 다시 처리할 필요가 없다(C10).

## ADR-007 · 쪽 나눔 기준

- **결정**: 읽힘 판단을 "원본 픽셀 대비 배율"에서 **"화면에서의 글 줄 간격"**(`linePitchPx` × 배율 ≥ 18 CSS px)으로 바꾼다. 줄 간격을 못 찾으면 기준 폭(긴 세로 720px·문서 1240px)으로 배율을 계산한다. 짧은 축을 맞춰도 안 읽히면(휴대폰 세로의 A4) 나눠서 나아질 때만 나누고 **손가락 확대를 글 작품에도 허용** + "가로로 돌리면 더 크게 보여요" 한 번 안내. 자세한 규칙 PLAN §5.6.
- **이유**: PRD 6.7의 s는 같은 A4라도 고해상도로 올리면 더 쪼개진다(C3, Antigravity도 지적). 휴대폰 세로에서 A4는 폭이 제한이라 세로로 나눠도 글자가 커지지 않는다(C4) — PRD 15.1 "A4가 휴대폰 세로에서 쪽으로 나뉨"은 의미 있는 결과를 내지 못한다.
- **보강(Codex 검토)**: 대상은 긴 세로·파노라마·글 많음·PDF 쪽만(그 밖의 그림은 나누지 않음, PRD 6.7-3). 줄 간격은 원해상도 활동 배열에서 구하고, 경계용 배열만 8px 칸으로 줄인다. 쪽 수 k = ⌈(L − O)/(V − O)⌉(겹침 O 반영), 경계를 옮긴 뒤에도 "첫 쪽 0 · 마지막 쪽 L · 이웃 겹침 ≥ O · 쪽 길이 ≤ V" 불변식을 시험한다. 글 카드는 DOM 측정(웹)과 담기 계획(순수 함수)으로 나눈다.
- **확정**: 6.7 `[고정]`의 해석은 사용자 위임(2026-11-11)으로 ADR-047에서 정했다.

## ADR-013 · 조명

- **결정**: 벽·천장·바닥은 **표준 조명틀**(2m마다 같은 세기의 천장 세척광)로 **조각마다 한 번** 구운 빛(세척광 × AO, 회색조)을 쓰고, 이웃 조각과 함께 굽는다. 구운 빛은 glTF 표준 `occlusionTexture`(texCoord 1) → three `aoMap` channel 1로 싣고, 모듈은 직접광 없이 반구광 + 환경맵으로만 밝힌다(최적화 도구가 지우지 않는 표준 경로, Codex 지적). 색이 있는 굽기가 필요하면 glb 밖 KTX2 라이트맵으로 바꾼다. 작품 스포트는 굽지 않고 **빛 웅덩이 판**(가산)과 **접촉 그림자 판**(곱하기)을 액자에 딸려 놓는다. 액자·황동은 작은 환경맵 + 반구광. 액자 옆 작은 명판을 둔다. 먼지 입자·빛 흔들림은 이동 중과 도착 후 2초까지만.
- **이유**: 모듈 인스턴싱과 구운 빛을 함께 쓰려면 같은 조각이 어디서나 같은 빛을 받아야 한다. 액자 위치는 전시마다 달라 스포트를 구우면 빈 벽에 빛이 맺힌다(Antigravity도 같은 지적). 실시간 그림자 없이(PRD 10.2) 액자가 벽에 붙어 보이려면 접촉 그림자가 필요하다. 정지 시 다시 그리지 않음(PRD 10.1·15.5 `[고정]`)과 상시 먼지 입자(8.3 `[추천]`)가 부딪치는 곳은 `[고정]`이 이긴다(C18).
- **관문**: P1-3 이음새 시험, G1 실기기 프레임·U-07 1차 의견.
- **고침(ADR-051)**: 표준 조명틀은 천창(넓은 확산광), 노출은 모든 조각이 하나, 뷰어는 구운 빛을 `aoMap`이 아니라 `lightMap`으로 읽는다.
- **고침(2026-11-13, F9 C1)**: 먼지는 점 묶음 하나(그리기 1회, 움직일 때와 도착 뒤 `MICRO_MOTION_SETTLE_SEC`까지만, 높음 90·보통 40·낮음 0), 빛 흔들림은 빛 웅덩이 `uBoost`에 곱하는 ±5%(작품마다 위상이 다름). 실내에서만, '낮음'·동작 줄이기에서는 끈다. 아주 약한 가장자리 어둡게는 후처리 단계 대신 맨 마지막에 그리는 화면 판 하나(높음·보통 0.2, 낮음 끔, 장면을 그릴 때만 함께 그려 정지 시 다시 그리기 0 유지). 마우스 올림은 그 작품 빛 웅덩이를 `T_HOVER` 동안 `HOVER_POOL_BOOST`배로, 크게 보기는 `ZOOM_POOL_BOOST`배로 올린다. 수치는 `config.ts` `MICRO_MOTION`·`VIGNETTE`·`HOVER_POOL_BOOST`.

## ADR-021 · 동선 방향·순서 보존·자동 대표작

- **결정**
  1. 방 크기 S·M·L이 쓰는 벽을 정했다(S = 대표 벽 + 왼쪽, M = + 오른쪽, L = + 문 사이). 다른 벽은 소개 글판·벤치로 채운다(PLAN §4.4).
  2. 회랑 오른쪽 방은 시계 방향, 왼쪽 방은 거울상(반시계). 방을 나오면 늘 회랑 진행 방향으로 이어진다.
  3. 대표작보다 순서가 앞인 작품은 첫 벽, 뒤인 작품은 그다음 벽들 — 걷는 순서 = 교사가 정한 순서.
  4. 대표작이 지정되지 않으면 관 순서의 가운데 1/3 중 가장 큰 작품, 같으면 순서가 빠른 것.
  5. 한 벽이 16m를 넘으면 크기를 한 단계 올린다(그래도 넘으면 관을 나눔). 나눌 때마다 관이 작아져 반드시 끝난다.
  6. (Codex 검토) 모든 관을 하나의 **논리 좌표계**(N 아래·F 위·L 왼쪽·R 오른쪽)에서 계산하고, 회랑 왼쪽 관의 거울상은 세계 좌표로 옮길 때만 생긴다. S 크기는 대표 뒤 작품을 F의 대표 오른쪽에 건다. 한쪽 벽이 길어도 작품을 반대편으로 넘기지 않는다(순서 보존이 이김, 빈 곳은 설비로).
- **이유**: PRD 5.2·5.3이 "벽 2면", "정면 끝 벽 = 대표 벽", "입구 왼쪽부터 시계 방향"을 말하지만 어떤 벽인지·왼쪽 방에서 방향이 거꾸로 되는 문제·대표작이 순서를 깨는 문제·큰 액자 묶음의 넘침이 남아 있었다(C12, C20, Antigravity 지적).

## ADR-022 · 전시실 나누기는 고르게

- **결정**: 관 수 = ⌈n/12⌉, 작품을 고르게(13 → 7·6). 배경음악은 원래 전시실 곡을 이어서.
- **이유**: 12·1로 나누면 1점짜리 방이 생겨 휑하다(PRD 5.3 "휑한 벽 금지" 취지).

## ADR-023 · 입장 코드: 숫자 6자리

- **결정**: 숫자 6자리(100000~999999), 첫 화면은 숫자 키패드. PRD G-01의 "6자리, 헷갈리는 글자 제외"를 숫자로 좁힌다(`[추천]`).
- **이유**: 학생이 주소를 직접 칠 때 태블릿 한/영 전환이 없다. 헷갈리는 글자 문제도 사라진다. 글방(ADR-016)과 같다. 90만 가지라 겹칠 일이 거의 없고 틀린 코드 조회는 IP 60회/10분으로 막는다.

## ADR-024 · PIN

- **결정**: 6~8자리 숫자, 쉬운 PIN(반복·연속·흔한 50개) 막기, HMAC 저장, 실패 칸 셋(기기 5회/10분 잠금 · IP 30회/10분 · 전역 100회/10분 → 2초 지연), 전시 만들기의 중복 확인도 실패로 셈.
- **이유**: G-17 `[고정]`이 "글쓰기 앱과 같은 방식"이고 글방은 6~8자리다(글방 U-05). PRD의 4~8은 `[추천]`이라 바꿀 수 있다. PIN이 전역이라 4자리는 무차별 대입과 "이미 쓰이는 PIN" 응답으로 캐내기에 약하다(Antigravity 지적). 학교는 공인 IP 하나를 함께 써서 IP만 세면 학생 장난으로 교사가 막힌다(글방 ADR-018).
- **바꾼 문구**: "6자리 이상이면 더 안전해요" → "8자리면 더 안전해요".

## ADR-025 · 토큰

- **결정**: 선생님 링크·PIN 세션·방문자 토큰 모두 기기가 만든 256비트, 서버는 SHA-256만. 링크를 열면 기기에 저장하고 주소창에서 지움, `Referrer-Policy: no-referrer`, 링크 복사는 `···` 안에서 경고와 함께, `선생님 링크 새로 만들기`.
- **보강**: 링크 형식은 ADR-044(주소 조각). PIN으로 들어온 기기는 링크를 되살릴 수 없어 `선생님 링크 새로 만들기`만 보인다. 링크만 가진 새 기기는 `GET /api/teacher/me`로 전시를 찾는다.
- **이유**: 서버가 토큰을 돌려주지 않으므로 응답이 사라져도 기기는 이미 토큰을 안다(글방 ADR-049). 프로젝터·방문 기록·Referer로 새는 길을 줄인다(Antigravity 지적). 쿠키로 바꾸는 안은 CloudFront 캐시 키·CSRF를 따로 다뤄야 해서 쓰지 않는다.

## ADR-026 · 배치 계산 위치

- **결정**: `computeLayout`은 `packages/core`의 순수 함수. 서버가 원본(바뀌면 `layout_dirty`, 읽을 때 계산, 결과 해시가 다를 때만 버전 올림, 최근 2판 보관). 교사 화면은 같은 함수로 즉시 미리 보기. 좌표는 1mm로 반올림. 카메라 정확한 위치는 저장하지 않고 기기가 화면 비율로 계산.
- **이유**: PRD 5.3 결정적 계산과 G-13 "교사와 학생이 같은 공간"을 지키면서 미리 보기가 서버를 기다리지 않는다. 올리기가 몰릴 때 매번 계산하지 않는다. 같은 결과면 학생에게 "바뀌었어요"가 뜨지 않는다.

## ADR-027 · 바뀜 확인

- **결정**: `GET /api/e/{code}/v`를 60초마다·화면 복귀 때. 지금 관이 그대로면 다음 이동 때 조용히 반영, 아니면 "전시가 새로 바뀌었어요 `새로 보기`".
- **이유**: PRD G-02 추천 그대로이고, 수업 중 학생이 보던 방이 갑자기 바뀌지 않게 한다.

## ADR-028 · 캐시와 삭제

- **결정**: 해시 이름 자산 1년, 작품 미디어는 브라우저 `max-age` ≤ 남은 보관 기간·CDN `s-maxage` ≤ 1일, 서비스 워커는 전시별 캐시를 두고 만료·삭제된 전시 캐시를 지운다. CDN 무효화 호출은 기본으로 쓰지 않는다.
- **이유**: PRD 11.2 "오래 캐시"를 그대로 하면 G-18 "만료 시 모두 삭제"가 CDN·기기 캐시에서 깨진다(C16). 무효화 호출에는 서버에 AWS 키가 필요해 U-01 하위 결정으로 둔다.
- **보강(Codex 검토)**: Cache API는 HTTP 머리로 지워지지 않으므로 서비스 워커가 전시별 만료 목록으로 네 때(활성화·앱 시작·화면 복귀·그 전시 미디어 요청)에 지운다. 보장 범위를 셋으로 나눠 처리방침에 적는다: 서버 원본(만료 즉시 접근 불가·60초 안 삭제) · CDN(최대 1일) · 기기(다음에 앱을 열 때). 서버 삭제는 `deleting` 표시 → 파일 삭제(멱등 재시도) → 행 삭제 순서.

## ADR-029 · 반응 신원: 방문자 토큰

- **결정**: PRD `Visitor.device_id` 대신 기기가 만든 방문자 토큰의 해시를 키로 쓴다. 별명은 반응 시트에서 `바꾸기` 가능.

## ADR-044 · 선생님 링크는 주소 조각(`/t#토큰`)

- **결정**: 선생님 링크를 `https://{도메인}/t#{토큰}`으로 만든다. 열면 기기에 저장하고 조각을 지운 뒤(`replaceState`) `GET /api/teacher/me`(Bearer)로 전시를 찾는다. 서버 기록은 그래도 `/t/` 뒤를 가린다.
- **이유**: PRD G-17의 `/t/{교사토큰}`은 첫 요청이 앞단(CloudFront·Cloudflare)과 서버를 지나므로, `replaceState`보다 먼저 경로가 기록·분석 화면에 남을 수 있다(Codex 지적). 주소 조각은 브라우저가 보내지 않는다. 링크·최근 전시·PIN 세 가지 길(G-17 `[고정]`)과 쓰는 법은 그대로다.
- **확인**: 형식 변경이라 U-11 목록에 올린다.

# 2차 사용자 지시 반영 (2026-11-11 오후)

> 사용자 지시: "위험하다고 판단한 것들, 문제가 될 것들은 스마트하게 판단해서 조정해" · "자동 투어 시간을 노래 길이에 맞추되, 자동으로 페이드인·페이드아웃 느낌이 들도록". 그래서 `[고정]` 해석이 필요하던 U-08과 U-02·U-09·U-11·U-15는 에이전트가 정했고, U-14는 사용자 결정으로 닫았다.

## ADR-046 · 자동 투어: 노래 길이에 맞춤 + 자동 페이드

- **결정**: 투어의 전시실 시간 = 그 방 배경음악의 들리는 길이(앞뒤 무음 제외, 서버 소리 분석). 곡이 없으면 40초. 설정에서 `전시실마다 ○초`(PRD 방식)도 고를 수 있다. 곡 시작은 2.5초 등전력 페이드인, 끝은 들리는 끝 4초 전부터 페이드아웃해 문을 지나는 카메라와 맞물리고, 다음 곡은 1초만 겹친다. 문 통과 동안 노출 15% 낮춤, 투어 처음 2초 페이드인·끝 3초 페이드아웃. 곡마다 크기 맞추기(−16 근사, ±6dB). 멈춤·다음·끝내기에도 짧은 페이드. 곡이 짧으면 최소 시간(이름판 4초 + 작품당 5초)을 지키고 곡은 되풀이하지 않는다. 안전 상한 6분. 자세히 PLAN §6.13.
- **이유**: 사용자 결정(PRD G-16의 "기본 40초"를 바꿈 — 사용자의 최신 지시가 PRD보다 우선). 개막식의 모둠 노래 5곡을 끝까지 듣게 되고, 자동 페이드로 곡 사이가 끊기지 않는다. 앞뒤 무음을 빼야 Suno 곡 끝의 긴 무음 동안 화면만 멈춰 있는 일이 없다. 곡 크기 맞추기가 없으면 모둠마다 소리 크기가 들쭉날쭉하다.
- **영향**: 개막식이 약 4분 → 약 12분(곡 길이 합). 교사는 투어 버튼 옆의 예상 길이를 보고 `전시실마다 ○초`로 바꿀 수 있다. PRD 15.4 "5×40초" 시험은 두 방식으로 나눠 한다(PLAN §14.6).

## ADR-047 · 휴대폰 세로의 글 많은 A4: 확대 + 회전 안내

- **결정**: ADR-007의 규칙 그대로 — 쪽 나눔은 글자가 커질 때만(휴대폰 가로·태블릿 세로), 휴대폰 세로에서는 짧은 축 맞춤 + 글 작품에도 손가락 확대(최대 3배) + 처음 한 번 "가로로 돌리면 더 크게 보여요". PRD 15.1의 A4 항목은 이 문장으로 시험한다.
- **이유**: 휴대폰 세로에서 A4는 폭이 제한이라 위아래로 나눠도 글자가 커지지 않는다(PRD_REVIEW C4). 좌우 두 칸으로 나누면 읽는 줄이 끊긴다. 6.7 `[고정]`의 취지("글자가 안 보이면 넘기기")는 넘기기가 실제로 도움이 되는 기기에서 지키고, 도움이 안 되는 휴대폰 세로는 확대로 같은 목표(글자가 보이게)를 이룬다.

## ADR-048 · 전시 만들기 시작 코드 기본 켬

- **결정**: 글방과 같은 숫자 "선생님 시작 코드"를 켠다(`START_CODE_REQUIRED=true`). 그 기기에서 처음 전시를 만들 때만 PIN 아래 한 칸, 맞으면 기기에 기억. 운영자가 "등록 링크"로 기기를 한 번에 등록할 수도 있다. 코드 값은 서버 비밀값(HMAC)이라 사용자가 정해 넣는다(U-17 설정 때).
- **이유**: 로그인이 없어 주소만 알면 누구나 전시를 만들고 전시당 800MB를 올릴 수 있다. 맥미니 디스크가 차면 모든 수업이 멈춘다. 교사 부담은 기기당 한 번뿐이고 평소 화면은 G-09의 4가지 그대로다.

## ADR-049 · 맥미니가 잠시 멈춰도 수업이 이어지게

- **결정**
  1. 미디어·해시 자산에 `stale-if-error` — 맥미니가 멈춰도 CDN이 이미 가진 사본을 계속 내준다.
  2. 서비스 워커: 앱 껍데기·템플릿·그 전시 미디어는 캐시 우선, `GET /api/e/{code}`는 네트워크 우선(3초) + 마지막 응답 사용. 한 번 들어온 학생은 서버가 멈춰도 관람·줌·소리를 계속한다.
  3. 반응은 기기의 **보내기 줄**(IndexedDB, 반응 ID로 멱등)에 넣고 연결이 돌아오면 자동으로 보낸다. 줄에 남은 것이 있으면 반응 버튼에 작은 점.
  4. 교사의 `수업 전 미리 불러오기`가 그 기기 캐시와 CDN 서울 거점을 함께 데운다 — 학생 21명이 동시에 들어와도 맥미니까지 가는 요청이 거의 없다.
- **이유**: 가장 큰 운영 위험은 집(KT) 맥미니의 재부팅·FileVault 잠금·아바타 빌드와 겹친 지연이다(PLAN §18 R7, 글방 ADR-037 기록). 관람은 읽기가 거의 전부라 캐시로 버틸 수 있고, 반응만 미뤄 보내면 된다.
- **한계**: 서버가 멈춘 동안 새로 들어오는 학생(첫 방문 기기)은 입장 정보를 못 받는다. 그래서 수업 전 미리 불러오기와 평일 08~16시 배포·재부팅 금지를 함께 둔다.

## ADR-050 · 에셋 도구 설치와 질감·굽기 방식 (2026-11-11)

- **설치(U-04 승인)**: Blender **5.2.3 LTS**(10-22 배포, 공식 DMG 해시·코드 서명·Gatekeeper 확인, `/Applications/Blender.app`). Homebrew가 처음에 5.3.0(11-10 배포, 7일 규칙 위반)을 깔아 내리고 바꿨다. 그때 Homebrew가 자동 정리로 자기 캐시·로그(설치 파일 캐시 약 45MB, 로그 폴더 9개)를 지웠다 — 사용자 자료·설치된 판은 아님. 앞으로 Homebrew는 `HOMEBREW_NO_INSTALL_CLEANUP=1`로만 쓴다.
- KTX-Software **4.4.2**: macOS용은 서명된 `.pkg`뿐이라(설치에 sudo 필요) Khronos 서명·Apple 공증을 확인한 뒤 **설치하지 않고 풀어서** `~/.local/opt/ktx-software-4.4.2/{bin,lib}`에 두고 `~/.local/bin/ktx`·`toktx`로 연결했다. 되돌리기: 그 폴더와 연결 둘을 지우면 끝.
- **질감**: numpy FFT 주기 잡음으로 만든다(`tools/assets/blender/textures.py`) — 이어 붙여도 이음새가 없고, 시드 고정이라 재현되며, 외부 다운로드·라이선스가 없다. 사진 같은 고해상도 CC0 질감으로 바꾸는 것은 P6-1에서 판단(U-07 1차 의견을 보고).
- **굽기 산출 형식**: 회색조 "세척광 × AO" → glTF `occlusionTexture`(texCoord 1). Blender 내보내기의 `glTF Material Output` 노드 묶음으로 넣는다. 최적화 뒤에도 남는지 `verifyOutput.mjs`가 매번 확인한다(Codex 지적 15번).

## ADR-051 · 굽기 조명틀·공통 노출·`lightMap`으로 읽기 (P1-3, 2026-11-11, ADR-013 고침)

- **발견(첫 실제 굽기)**: ① 굽기 광원(면광)이 조명 머리 상자 **안쪽**(z 3.80~3.92)에 놓여 빛이 상자 윗면으로만 새어 나갔다 — 벽 위쪽만 밝고 작품 높이·판벽은 거의 검게 나옴. ② 노출을 조각마다 98번째 백분위로 맞춰 천장은 벽의 약 7배, 문 조각은 옆 벽보다 약 12% 다르게 저장됨 → 종류가 다른 조각이 만나는 곳마다 이음새. ③ 빨강 채널만 읽음. ④ 천장(간접광만 받음)은 표본 256에서 잡음이 큼. ⑤ `aoMap`은 반구광·환경광에 **곱하는** 칸이라 반구광의 위아래 치우침(위 밝음·아래 어두움)이 구운 빛에 한 번 더 곱해짐.
- **결정**
  - **표준 조명틀 = 천창(넓은 확산광)**: 천장 아래 z 3.86에 벽에서 1m씩 물러난 큰 면광. 적분하면 벽 높이 0.5~3.0m의 조도가 0.52~0.63 안(가장 밝은 곳 약 2m = 작품 띠)이고 천장 몰딩 아래만 자연스럽게 어두워진다. **x 방향으로 변하지 않아** 어느 조각을 어디에 이어 붙여도 같은 빛이고, 벽에 스포트 무늬가 없다(§6.3 원칙 그대로). 천장 레일·조명 머리는 장식이며, 작품 스포트는 지금처럼 액자의 빛 웅덩이 판이 맡는다.
  - **이웃**: 벽 조각은 양옆 8m를 같은 조각 사본으로 채워 굽는다(모든 벽 조각이 같은 주변을 봄). 천장·안쪽 모서리는 8×8m 방, 바깥 모서리는 ㄱ자 공간.
  - **공통 노출**: 4m 벽 회반죽의 작품 높이 띠(x 0.5~3.5, z 1.3~2.3) 평균이 곡선 뒤 0.62가 되는 배율 하나를 **모든 조각**에 쓴다. 곡선은 `1 − e^(−배율·x)`(어두운 쪽은 선형, 밝은 쪽은 부드럽게 눌림). 값과 배율은 `manifest.json`의 `exposure`에 남고 `verifyOutput.mjs`가 있는지 본다.
  - **밝기만**: 흰 빛·회색 재질로 굽고 RGB 평균을 쓴다. 빛 색은 뷰어가 템플릿 장면 빛(`packages/core/src/domain/templates/look.ts`)으로 곱한다.
  - **잡음 제거**: OIDN 대신(굽기에는 Blender 잡음 제거가 없고 합성기 경로는 판마다 API가 바뀜) 위치·법선 굽기를 길잡이로 한 **결합 양방향 걸러내기**(numpy, 반지름 3px, 위치 σ 3cm, 법선 σ 0.08). UV에서 붙어 있어도 3D에서 떨어진 섬·꺾인 면은 섞이지 않는다. 표본 기본 512, 천장 ×4.
  - **뷰어는 `lightMap`으로 읽는다**: glTF에는 lightMap 칸이 없어 계속 `occlusionTexture`(texCoord 1)에 싣고, 불러올 때 `aoMap` → `lightMap`(channel 1)으로 옮긴다(`TemplateModules.tsx`). 구운 조각에는 반구광을 `hemisphereScale`(0.15)만, 환경맵을 `environmentScale`(0.35)만 더한다(셰이더 조각 주입, `materials.ts`). three 판이 바뀌어 주입할 문자열이 없으면 바로 오류를 낸다.

## ADR-052 · 공용 계약(P2-1)에서 정한 것 (2026-11-11)

- **스키마 자리**: `packages/core/src/types/*`(zod 4). 서버는 바깥 입력을, 웹은 서버 응답을 같은 스키마로 검사한다. 도메인 코드는 `import type`만(도메인은 zod를 실행하지 않음).

## ADR-053 · 배치 엔진(P2-3)에서 정한 것 (2026-11-11)

- **벽 두께**: 관의 N 벽 안쪽 면은 회랑 벽 면에서 `WALL_THICKNESS_M`(0.3m) 뒤. 논리 → 세계는 PLAN §4.6의 `X = 2 + y` 대신 `X = ±(2 + 0.3 + y)`. 문 조각의 두께 면(reveal)이 벽 두께를 그대로 채운다.
- **회랑 쪽 문틀** `mh_corridor_door_2m`(PLAN §13.1 "회랑 문틀"): 두께 면 없이 문틀만. 방 쪽 문 조각과 회랑 쪽에 같은 문 조각을 두면 두께 면이 같은 자리에 겹쳐 깜빡인다. 조각은 P6에서 만든다(그전까지 뷰어는 없는 조각을 건너뜀).
- **입구 홀 12×8m**: PLAN의 10×8m 고정 묶음(P6)이 생기기 전까지 2m 조각으로 세우므로, 회랑 4m 양옆이 2m 배수가 되게. 묶음 조각이 생기면 `templates/geometry.ts`의 `hall` 값만 바꾼다.
- **문은 N 벽의 양 끝(모서리)**: 들어가는 문 x∈[0,2], 나오는 문 x∈[W−2,W]. 그래서 N 벽 필요 길이 = 작품 줄 + 2×(문 2m + 문 옆 0.6m)이다(PLAN §4.4-2의 모서리 여백 2개는 쓰지 않음).
- **이름판**: 받침을 문 옆 바닥에 세우면 소개 정지 지점의 시야 뒤에 오거나 L 벽 작품을 가린다. 대표 벽 한가운데 위쪽 명판(대표 벽 액자 위 끝 + 0.35m, 2.4~3.45m)으로 둔다 — 소개 화면에서 대표작과 함께 보인다.
- **빈 면 채우기**: 걷는 순서(L → F → R → N)로 작품 없는 면에 소개 글판 → 벤치 → 화분 → 화분. M은 벤치가 없으면 N 안쪽 벤치, L은 가운데 벤치. 빈 면이 없으면 3D 소개 글판은 두지 않는다(소개 글은 소개 정지 지점에서 HTML로 보임, PLAN §6.4).
- **명판 자리**: "걷는 방향 뒤쪽"을 지나온 쪽으로 읽어 액자 바깥 끝에서 0.15m(명판 한가운데), 높이 1.3m. 소리 명판에는 명판을 따로 두지 않는다.
- **정지 지점 자리**: 소개·홀은 카메라를 정해진 점(문 안쪽 1.2m·홀 입구 안쪽 1.5m)에 두려고 `normal` = 그 점 쪽 단위 벡터, `maxDistance` = 그 거리, `outer`를 크게 둬 화면 맞춤이 거리 상한에 닿게 한다. 작품은 벽 법선 + 맞은편 벽까지 − 0.4m.
- **이동 경로점**: 관 사이 = 나오는 문 안쪽 1.2m → 문(벽 두께 가운데) → 회랑 쪽 1.2m → 회랑 중심선 → (다음 관) 중심선 → 회랑 쪽 1.2m → 문 → 안쪽 1.2m. 끝점(카메라)은 기기가 화면 비율로 계산한다.
- **걸을 수 있는 영역**은 배치 데이터만으로 만든다(`walkableRects`): 관 경계·홀·회랑을 0.3m 줄인 사각형 + 문(지도 `doors`의 맑은 폭 − 0.3m, 벽 두께를 건너 양쪽에 겹침). 문 `width`는 맑은 폭(2m − 문틀 2×0.1m = 1.8m)으로 기록한다.
- **반올림**: 좌표 1mm, 회전 1e-4 rad. 해시는 정규 JSON(수는 소수 셋째 자리 고정 글)의 SHA-256 앞 16자 — SHA-256은 도메인에 순수 TS로 두고 Node `crypto`와 무작위 문자열로 대조 시험.
- **겪은 일**: 섞인 형태 12점에서 큰 작품이 가운데 뒤쪽(색인 7)이면 자동 대표작이 되고, 순서 보존 때문에 앞 작품 7점이 모두 L 벽에 걸려 16m를 넘는다 → 규칙대로 둘로 나뉨(M·M). 순서 보존이 우선이라 받아들인다.
- **새 설정 키**: `ROOM_MAX_DW_RATIO` `HIGH_FRAME_LIMIT_M` `HIGH_FRAME_BOTTOM_M` `LABEL_OFFSET_M` `LABEL_HEIGHT_M` `INTRO_STOP_INSIDE_M` `HALL_STOP_INSIDE_M` `DOOR_PATH_OFFSET_M` `WALKABLE_WALL_MARGIN_M` `TEXTCARD_ASPECT`(PLAN 본문 수치를 키로). 템플릿마다 다른 값(액자 테·문틀·홀·첫 관 z·출구 앞 공간·조각 이름)은 `domain/templates/geometry.ts`.

## ADR-054 · 줄 간격 추정을 도메인으로, 배수 주기 내려가기 (P2-4, 2026-11-11)

- Codex가 서버 `media/analyze.ts` 안에 만든 자기상관 줄 간격 추정을 `packages/core/src/domain/pages/linePitch.ts`로 옮겼다(PLAN §3 자리, 서버는 `@gallery/core/pages`에서 가져다 씀). 서버의 분석값 타입은 core `ImageAnalysisWire`로 하나만.
- **배수 주기 내려가기**: "가장 높은 봉우리의 0.9배 이상인 첫 봉우리" 규칙은 두 줄마다 진하기가 40% 다른 글에서 2배 간격(80)을 고른다(40 봉우리 신뢰도 0.846 < 0.9). 줄 간격을 2배로 읽으면 쪽 계획기가 글자가 크다고 보고 덜 확대한다(글이 작게 보이는 쪽으로 틀림). 고른 간격의 절반(±5%) 근처에 `LINE_PITCH_MIN_CONFIDENCE`(0.6) 이상 봉우리가 있으면 그리로 내려간다. 글 줄 활동 배열은 절반 간격에서 음의 상관이라 우연한 절반 봉우리가 생기지 않는다. 진하기 차가 70%(40 봉우리 0.428)처럼 크면 2배 간격으로 남는다(실제로 그 주기의 무늬).
- 시험: 간격 40 ±2, 배수 주기, 간격 18~120 × 잡음 속성 시험, 줄 없음(고른 면·흰 잡음) → null·낮은 신뢰도, 3주기 미만 → null.

## ADR-056 · 서버 뼈대(P3-1)에서 정한 것 (2026-11-11)

- **맡은 곳**: PLAN은 Codex였으나 맥미니 과부하로 로컬 CLI 세션을 늘리지 않으려고 Claude 서브에이전트가 했다. Claude가 시험(서버 62개)을 다시 돌리고 개발 서버를 4521에서 띄워 건강 확인·오류 봉투·보안 머리·기록을 확인했다.
- **환경 값**(`apps/server/src/env.ts`): `loadEnv(source)` 순수 함수 — `.env`를 읽지 않는다. `NODE_ENV`·`PORT`·폴더 셋(절대 경로) 필수, 비밀값 셋 필수(32바이트 이상, hex 또는 base64, 셋이 같으면 거부), `TMP_DIR`이 데이터·미디어 폴더와 겹치면 거부. `START_CODE_HMAC`은 `START_CODE_REQUIRED=false`여도 받는다(운영 설정을 단순하게). 비밀값은 찍으면 `***`.
- **설정 덮어쓰기**: `config.ts`와 같은 이름의 환경 값 중 숫자·참거짓, 그리고 정해진 문자열(`CLIENT_IP_HEADER` = `x-gw-viewer-ip` | `cf-connecting-ip`)만. 모양이 틀리면 시작 거부, 그 밖의 문자열·배열 키는 기록만.
- **JSON 본문 64KB 초과** → `E_VALIDATION` + `fields._ = body_too_large`(`E_FILE_TOO_LARGE`의 화면 문구는 파일용). `Content-Length`가 있으면 읽기 전에, chunked면 읽으면서. 업로드 경로(작품·포스터·배경음악·쪽)의 multipart만 이 한도를 건너뛴다. **쪽 경로는 `PUT /api/teacher/artworks/{aid}/pages/{i}` 하나로 정한다**(지금 미들웨어는 두 꼴을 받음 — P3-4에서 줄인다).
- **요청 ID**는 늘 서버가 만든다(들어온 `X-Request-Id`는 믿지 않음 — 남이 넣은 글이 기록에 섞이지 않게). 끝내는 중이면 `E_BUSY`(보안 머리·요청 ID는 붙음).
- **건강 확인** `/api/health`: `ok·db·diskOk·queueLength`만. 남은 바이트 수는 공개 경로에 내지 않는다(Claude가 고침).
- **오류 봉투**: `AppError` → `errorCatalog`의 http·retryable, zod → `E_VALIDATION` + `issueFields`, 기기 전용 코드(http null)·예상 못 한 오류 → `E_SERVER`(원인은 기록에만).
- **빌드·개발**: `tsc`가 `.sql`을 옮기지 않아 서버 빌드 단계가 `src/store/migrations` → `dist/store/migrations`를 복사한다(루트 `build`에 묶음). 개발 실행기 `apps/server/scripts/dev.mjs`(`npm run dev -w @gallery/server`, `.claude/launch.json` `gallery-server-dev`): 개발 비밀값은 실제 비밀이 아니라 고정 이름표의 SHA-256 — 다시 시작해도 개발 DB의 PIN이 맞는다. 운영은 이 실행기를 쓰지 않는다.

## ADR-057 · 관람 방식 고도화: 자유 관람·미술관 외관·캐릭터·함께 관람 (U-19, 2026-11-11)

**바뀐 것(사용자 결정 U-19)**: PRD 1.4·G-02·원칙 7의 `[고정]`(정해진 동선만·아바타 없음·실시간 없음)을 사용자가 뒤집었다. 아래가 그 설계다.

- **이동 = 자유 + 안내**: 3인칭 캐릭터(어깨 뒤 카메라)로 걷는다. 휴대폰·태블릿은 왼쪽 아래 가상 조이스틱 + 화면 누르기로 그 자리까지 걷기 + 한 손가락 끌기로 둘러보기, 데스크톱은 WASD·방향키 + 마우스 끌기 + 바닥 누르기. **기존 정지 지점은 버리지 않고** `‹ ›`가 "다음 작품으로 걸어가기"(경로점 따라 자동 걷기)가 된다 — 아이들이 길을 잃지 않고, 교사 투어(G-16)와 줌 층(G-03)이 그대로 쓰인다.
- **충돌·계단**: 배치의 걸을 수 있는 영역(`walkableRects`)이 그대로 충돌 영역이다(벽 0.3m 안쪽). 계단·현관은 높이를 가진 영역(경사)으로 배치에 더한다. 물리 엔진은 쓰지 않는다(비용·결정성).
- **미술관 외관**(배치 엔진 `algoVersion` 2): 광장(첫 자리) → 넓은 계단 → 기둥 현관 + 박공 → 이름판 "{전시명} 전시관"(전시명이 이미 '전시관·미술관·박물관·전시회'로 끝나면 그대로, 문구 틀은 `copy`) → 문 → 입구 홀 → 회랑·관(지금 문법 그대로). 하늘·먼 나무는 가벼운 하늘 구와 판으로.
- **이젤**: 관마다 순서의 끝 작품 일부(S·M 1점, L 2점, 소리 명판·파노라마·긴 세로 제외)를 방 가운데 이젤에 놓는다(순서 보존, 벽이 덜 붐빔).
- **작품을 크게**: 벽 기준 크기를 1.35배(대표작 1.3배는 그대로 곱함), 작품 앞에서 누르면 화면을 크게 채우는 보기(지금 줌 층, 채움 0.85). 걸어가며 보는 기본 카메라도 작품 쪽에서는 가까이.
- **캐릭터 4종**: 학생 남·여, 선생님 남·여(학생은 들어올 때 고르고, 선생님은 교사 화면에서 고름). 아기자기한 3등신 남짓, 같은 화풍. 만들기: 개념 그림(Codex 그림 생성, 앞·옆·뒤) → Tripo 이미지→3D·자동 리깅·애니메이션(가만히·걷기·뛰기·손 흔들기) → gltf-transform 최적화. **예산(캐릭터 하나)**: 삼각형 ≤ 12,000(먼 거리 LOD ≤ 3,000), 재질 1, 텍스처 1024² KTX2, glb ≤ 1.5MB. 저품질이면 쓰지 않는다(사용자 조건) — 개념 그림·3D 결과를 캡처로 검수하고 Antigravity 비평을 받는다.
- **함께 관람**: 전시마다 웹소켓 하나(`/api/e/{code}/live`). 기기는 초당 5번 `{x, z, yaw, 걸음 상태}`를 보내고 서버는 같은 전시의 다른 사람 목록을 초당 5번 돌려준다(위치는 받은 쪽이 보간). 별명은 방문자 등록의 별명(익명 방식이면 "관람객"). 연결이 끊겨도 혼자 관람은 그대로(원칙 7의 뜻은 지킴). 서버는 위치를 저장하지 않는다(메모리에만, 기록에 없음). 동의 문구는 "다른 친구들도 볼 수 있어요" 판.
- **성능 예산 다시**: 보이는 다른 관람객은 휴대폰 6·태블릿 12·데스크톱 24명까지 전신(그 밖은 이름표 점), 15m 밖은 LOD. 그리기 호출 상한은 휴대폰·태블릿 120·데스크톱 160(캐릭터 몫 포함, 지금 100에서 올림), 정지 시 다시 그리지 않음 원칙은 **혼자이고 멈춰 있을 때**만(다른 사람이 움직이면 그린다).
- **화면 디자인 v2**: 지금 시안은 사용자 평가 "저품질·칙칙함" → 다시 만든다. 밝은 회반죽·참나무·대리석·황동을 바탕으로 깊은 감색·자주 같은 또렷한 강조색, 3D를 가리지 않는 얇은 안내판. 교사 작품 격자는 오른쪽 미리 보기를 없애고 카드 안에서 작품을 미리 보며(액자에 걸린 모습), 카드마다 형태·쪽 수·상태·경고를 적당히.

  - **계단**: 걷는 바닥이 한 줄 경사라 디딤판 앞에서는 최대 15cm 파묻히고 뒤에서는 떴다. 경사에 디딤판 수(`slope.steps`, 계단 조각과 같은 8단)를 두고 **발은 `footFloorAt`**(위 끝에서부터 단 깊이마다 평평), **카메라·투어 길은 그대로 `floorAt`**(경사 — 단마다 덜컹이지 않게). 발 바닥은 `CHAR_FLOOR_FOLLOW` 35/s로 빨리 따라간다. 배치 출력이 바뀌어 `ALGO_VERSION` 3. 걷기 엔진으로 직접 오르게 하니 디딤판 가운데 어긋남 0.8mm.
  - **걷기 빠르기 1.5 → 1.15m/s**(박물관 걸음)·걷기 배속 상한 2.0: 짧은 보폭 동작이 미끄러지던 것(떠다니는 느낌의 큰 몫)을 줄인다 — 교사는 거의 맞고 학생은 약 1.6배. 평지에서 몸 맨 아래는 땅 −0~4cm(뜨지 않음, 실측).
  - **다른 관람객이 실제로 걷는다**: LOD에 `walk`·`run`을 넣고(`idle`은 첫 키) 뷰어가 장면마다 구워 **정점 애니메이션 텍스처**(반정밀도 자리·법선, 걷기 24·뛰기 16장면, 종류당 약 2MB, 그 종류가 처음 보일 때만)에 담는다. 재질은 `withDim` 위에 꼭짓점을 `gl_VertexID`로 읽는 조각을 잇고(`gw-dim-plain-vat`), 사람마다 `aVat`(장면 A·B·섞음) 인스턴스 값만 바꾼다 — 그리기 호출은 종류마다 1회 그대로. 배속은 내 캐릭터와 같은 규칙, 서기 ↔ 걷기는 `PEER_VAT_BLEND_PER_S`로 섞는다.
  - **그늘**: 납작한 공 → 가운데 짙고 바깥으로 사라지는 원판(`blobShadowMaterial`, 키 × 0.27 반지름, 옆으로 넓게). 다른 관람객도 모두 인스턴스 하나로(+1회). 떠오르면 작고 옅어진다.
  - **사람끼리 겹치지 않게**: 걷기 엔진에 `setCrowd` — 몸 반지름(0.28m) 두 배보다 가까우면 겹친 깊이 × 18/s로 밀려나고 가는 중이면 가는 쪽 옆으로 비켜 돈다(정면으로 막혀도 지나감). 내 캐릭터는 보간된 다른 관람객 자리를, 가짜 관람객은 서로를 피한다. 실제 관람객은 각자 기기에서 같은 일을 한다. 헤드리스에서 12명 최소 간격 0.47m(반지름 0.24일 때).
  - 남은 것: 먼 이름표끼리 겹침, 디딤판 끝에서 그늘이 끊겨 보임(작음).
- **R-3 반영(2026-11-12)**: Blender 굽기(외관·설비·실내 다시 굽기)를 `build.mjs`로 최적화해 `apps/web/src/tpl/modern-history/`에 `core`·`exterior`·`fixtures.glb`를 넣었다(이전 core는 `.local/art/build/tpl-prev/`). `verifyOutput` 통과 — 외관 가장 넓은 정면 2.5만/4만 면, 늘어난 크기 1.86/2.0MB, core 0.98/2.5MB. 뷰어는 조각 glb 여러 개를 합쳐 읽고(`useTemplateModules(주소들)`), 설비는 `fixtures.glb`의 종류별 노드가 있으면 진짜 모델·없으면 임시 모형(`FixtureModels models`). 외관 조각이 들어와 개발 화면의 외관 임시 덩어리는 저절로 빠진다. 광장 장면 그리기 91·삼각형 9.5만.
- **e2e 처음 전부 돌림(2026-11-12) — 찾은 결함과 고침**: ① 개발 화면이 부품을 같은 `data-testid`(`joystick`·`near-card`) div로 한 번 더 감싸 요소가 둘 → 감싼 쪽 표시 지움 ② 휴대폰(390px)에서 작품 카드가 화면보다 14px 넘치고(카드 부품에 `box-sizing` 없음 → `border-box` 넣음, UI 부품 소유는 Antigravity) 오른쪽 뛰기·점프 단추가 "크게 보기" 위를 덮음 → 좁은 화면에서 카드를 왼쪽 정렬·단추 자리 비움 ③ 세로 휴대폰은 작품 폭을 맞추느라 더 멀리 서서 `크게 보기`가 "멀다"며 다시 걸어가기만 함 → 그 작품 정지 지점이면 거리와 상관없이 연다 ④ 도착 자리에 다른 사람이 서 있으면 밀려나 도착하지 못함 → 도착 반경을 몸 두 개만큼 넓힘 ⑤ 긴 걷기 흐름은 기본 시험 시간 30초로 들어갈 수 없어 `test.setTimeout`, 30명 장면은 헤드리스 소프트웨어 렌더링이 느려 도착 기다림 90초 ⑥ 사람이 늘 때 늘어나는 그리기 상한 +5 → +6(그늘 인스턴스) ⑦ 소리 시험이 잠금 풀기가 끝나기 전에 `unlocked`를 확인하던 시간 경쟁 → 기다림 ⑧ 이음새 판정은 ADR-058. 결과: e2e 19개 모두 통과(걷기 3크기·30명, 이음새, 관람, 소리, 배치 해시).
- **손 흔들기(R-4 끝 조건, 2026-11-12)**: Tripo `wave_goodbye_01`은 2.5~4.5초에 손을 올리지만 엉덩이까지 움직이며 웅크려(캡처로 확인) 쓰지 않는다. 대신 엔진이 오른팔을 **겨눈다**(`aimBone`: 뼈 → 자식 방향을 목표 방향으로, 동작을 적용한 뒤) — 위팔은 옆 바깥, 아래팔은 위로 세워 좌우로 흔들고, 손·손가락은 바인드 자세(곧은 손목·편 손가락)로 섞는다. 학생은 머리가 커서 손이 머리에 닿지 않게 위팔을 더 옆으로(`CHAR_WAVE.student`). 언제: 광장에 처음 서고 1초 뒤 한 번, 가만히 있을 때 다른 사람이 1.6m 안으로 새로 들어오면 한 번(15초에 한 번까지), 걸으면 바로 멈춤. 흔드는 동안은 캐릭터가 스스로 다음 장면을 부르고, 멈춤 뒤 첫 프레임의 큰 시간 간격은 0.1초로 자른다(한 프레임에 흔들기가 끝나던 결함). 개발 화면 `/dev/characters?wave=1`.
- **조각 차례 받기(R-8, 2026-11-12)**: `useTemplateModules`가 주소를 순서대로 하나씩 받고 받는 대로 그린다. 자유 관람은 외관 → 실내 핵심 순서라 광장이 먼저 서고 실내는 계단을 오르는 동안 받는다(광장 첫 화면 ≈ 3.6MB, §2.5).
- **R-3 캡처 비평(Antigravity, 2026-11-12)**: 실내(판벽·미색 벽·작품 위 은은한 빛)는 "실제 전시관 분위기". 외관은 회색 일색·접촉 그림자 없음·광장 바닥 줄눈 없음이라 게임 광장 같다는 지적(하늘은 이미 그라데이션 공 `Sky` — 건물이 화면을 채운 캡처라 안 보였던 것). 손 흔들기 주먹·꺾인 손목 지적은 위에서 고침.
  - **엔진으로 먼저 고침**: ① 포장 줄눈 — `M_Paving*` 재질에 세계 좌표 기준 엇갈린 돌판(1×0.5m) 줄눈·판마다 밝기 ±5%를 셰이더로(구운 빛·어둡게 셰이더 뒤에 이음, `PAVING_JOINT`) ② 접촉 그늘 — `ExteriorContact`: 정면 벽 밑·계단 디딤판마다 안쪽 모서리·계단 맨 아래 흐린 띠(그리기 1), 현관 기둥 밑 둥근 그늘(1). 광장 그리기 86 → 88. 다시 비평: 바닥·접촉 그림자 "대폭 개선", 계단 "개선", 줄눈 굵기·짙기 "현 상태 유지".
  - **석재 잔결(엔진)**: 기둥·외벽이 매끈한 단색이라 석고 모형 같다는 지적에, `M_Stone*`·`M_Ashlar*` 재질에 세계 좌표 값 잡음 두 겹(1.6·9 /m)으로 밝기 ±11%·거칠기 ±24%(`STONE_GRAIN`). Antigravity 전후 비교 — "차이가 분명, 석고 느낌 줄어듦, 반복·지저분한 얼룩 없음", 권한 짙기(±10~12%·±22~25%)로 올림.
  - **돌 요철·정문 차폐도 엔진으로**: 석재 잔결 높이의 화면 기울기로 법선을 기울이는 범프(three `perturbNormalArb`와 같은 방식, `STONE_GRAIN.bump` 0.6) — 법선 맵을 새로 넣으면 외관 늘어남 예산(2MB 중 1.86MB 사용)을 넘길 수 있어서. 정문 열림(폭 `DOOR_WIDTH_M` − 문틀×2 = 1.8m, 높이 `DOOR_HEIGHT_M` − 문틀 = 2.7m, Blender 현관 조각과 같은 규칙)의 위·양옆에 정면 벽 면 바로 안쪽으로 세운 흐린 띠(`ExteriorContact`, 같은 인스턴스 — 그리기 늘지 않음, 삼각형 +6).
  - **Blender로 남은 것(선택)**: 위 엔진 근사(접촉 그늘·포장 줄눈·석재 잔결·범프)를 굽기에 넣으면 실제 AO·법선 맵으로 더 낫지만, 예산을 다시 맞춰야 한다. 그때 `ExteriorContact`·`PAVING_JOINT`·`STONE_GRAIN`을 지운다.
- **벽 부딪힘·뛰기·점프(다른 계정 세션, 2026-11-11 밤)**: 벽 통과는 입구 4m 조각(`mh_entrance_4m`)·나눠떨어짐 검사·시험으로 고쳤다. 벽에 거의 정면으로 부딪히면 0.45초 멈추고 22cm 밀려나며 몸이 찌그러진다(`CHAR_BUMP_*`). 뛰기 단추·Shift, 실내에서 1.2초 넘게 뛰면 안내원 말풍선 "쉿! 미술관에서는 뛰지 않아요" 뒤 4초 걷기만, 빠르게 세 번 뛰면 "폴짝폴짝은 광장에서!". 실내는 어둡게 하고 작품 쪽 빛 웅덩이, 문을 지날 때 0.9초 눈 적응. 분위기 시안 A 저녁 미술관(기본)·B 고전 박물관·C 현대 갤러리(`?mood=a|b|c`) — 고르기는 U-19-10.
- **투어 카메라(G-16)도 설비를 돈다**: 관 사이 걷기와 같은 관 안 작품 다가가기 모두 `route(tallOnly)`를 따른다(곧은 보간이 이젤을 지나가던 결함 — 시험이 잡음). 카메라 길은 몸이 없으므로 설비 실제 바닥에서 `ROUTE_CAMERA_CLEARANCE_M`(0.15m)만 떨어지면 된다.
- **Codex 독립 검토(2026-11-11 밤) 반영**: ① 길 찾기 꼭짓점에 걸을 수 있는 사각형 모서리를 더해 홀 → 회랑처럼 영역이 꺾이는 곳을 돈다(예전에는 벽 앞에서 영원히 걸음) + 안내 중 `GUIDE_STUCK_SEC` 동안 거의 못 움직이면 안내를 끝냄 + 둥글린 길이 설비 여유로 들어가면 둥글리지 않은 꺾은선 ② 함께 관람 통로: 옛 소켓의 늦은 이벤트를 막고(지금 소켓인지 확인·떠날 때 손잡이 해제) ③ 따라가는 카메라는 키 큰 설비 앞에서 멈춤 ④ 멈춘 관람객 표본 뒤로는 늘리지 않고, 보간이 남은 동안만 다시 그림(`PeerBuffer.busy`) ⑤ 가만히 있어도 `LIVE_KEEPALIVE_SEC`(30초)마다 같은 자리를 다시 보내 서버의 쉬는 시간(90초)에 끊기지 않게 ⑥ 크게 보는 동안 걷기 잠금. 경우마다 시험을 붙였고, ①②는 고치기 전 코드로 되돌려 시험이 실패함을 확인했다(③~⑥은 그 확인을 하지 않음).

## ADR-058 · 이음새 판정: 띠마다 조각 자체의 흔들림과 견준다 (2026-11-12)

- **맥락**: 이음새 e2e(`tests/e2e/seam.spec.ts`)를 처음 돌렸다(그동안 자원 대기). 회반죽 띠는 경계 0.0~1.4%·대조 0.0~0.3%로 깨끗했다. 하지만 **판벽 띠는 경계가 아닌 조각 한가운데(대조)부터 2%를 넘었다** — 이전 core 6.0~7.8%, R-3 새 core 1.0~4.6%. 판벽은 어두운 나무(선형 밝기 0.015~0.05)라 8비트 한 단계가 이미 선형 2%를 넘고, 나뭇결·판 테두리도 있다. 고정 2%로는 경계와 무늬를 구별할 수 없다.
- **결정**: 띠마다 대조 지점들의 최대 차와 2% 가운데 큰 값을 그 띠의 경계 상한으로 쓴다(`seamCheck.mjs` `seamLimit`). 경계가 조각 자체 무늬보다 뚜렷하지 않으면 보이지 않는 것으로 본다. 고르게 칠한 회반죽 띠의 대조는 계속 2% 아래여야 한다(재는 방법이 흔들리지 않는지 확인).
- **결과**: R-3 새 core에서 판벽 경계 1.85·2.67%(그 띠 대조 최대 4.60%), 회반죽 경계 ≤ 1.37%. 단위 시험 2개(상한 규칙, 어두운 띠에서 한 단계가 2%를 넘는 근거).

## ADR-059 · 학생 관람 앞뒤 잇기(P4-1·P4-2)에서 정한 것 (2026-11-12)

- **맥락**: 빈 `<main />`이던 앱을 실제 학생 흐름으로 만들었다(`/` → `/{코드}` → 포스터 → 관람). 개발 화면(`/dev/walk`)에서 다듬은 자유 관람 엔진을 실제 서버 전시(`ExhibitionView`)에 붙이면서 정한 것을 남긴다.
- **결정**
  - **관람 화면은 포스터 뒤에서 미리 뜬다**(`VisitScreen entered={false}`).
    - 첫 자리(외관 조각)를 받는 동안 입장 단추는 "준비하고 있어요"로 잠긴다.
    - 들어오면 `entered`만 바꾼다. 다시 만들지 않는다.
    - 그 전에는 입력(키보드·누르기)·함께 관람 잇기·첫 인사 손 흔들기를 하지 않는다(`WalkView paused`).
    - 약속은 `app/visit/contract.ts` 하나다.
  - **화면 층 하나를 함께 쓴다**: 위 줄·조이스틱·안내·카드·지도·출구는 `app/visit/walkUi.tsx`에 있고, 학생 화면과 `/dev/walk`가 같은 것을 쓴다(개발 화면 전용 부품을 없앰).
  - **작품 그림 상주 관리를 붙였다**(`viewer/textures/useResidentTextures.ts`).
    - 초점 = 그리는 관 · 지금 관에서 가장 가까운 작품(1m 칸) · 안내 목적지.
    - 내린 텍스처는 1.5초 뒤에 지운다. 같은 프레임에 옛 재질이 닫힌 `ImageBitmap`을 그리지 않게 하려는 것이다.
    - 관리자는 효과 안에서 만든다. StrictMode가 효과를 두 번 돌리면 지운 관리자를 다시 쓰기 때문이다.
  - **투명한 작품**: 그림 면을 투명 섞기로 바꿔 빈 자리에 뒤의 매트가 비치게 했다. 미리 곱한 알파는 `ONE, ONE_MINUS_SRC_ALPHA`로 섞는다. 불투명으로 그리던 때는 PNG의 빈 자리가 검게 나왔다(시드 그림에서 발견).
  - **컨텍스트 손실(§6.12)**:
    - 기본 동작을 막고 "잠시만 기다려 주세요"를 덮는다.
    - 복구되면 캔버스를 새로 붙여 같은 자리·같은 정지 지점에서 이어 걷는다(`WalkView start`).
    - 새로 붙일 때 R3F가 옛 캔버스에 일부러 손실을 일으키므로, 지금 캔버스의 사건만 듣는다.
    - 60초 안에 두 번이면 2D로 바꾸는 것은 P4-10과 함께 한다.
  - **품질 단계**:
    - 시작은 기기 능력으로 정한다(`WEBGL_debug_renderer_info`, iPadOS = Macintosh + 터치).
    - 이어 그린 프레임(간격 0.1초 미만)을 움직이는 구간으로 쳐서 내린다.
    - 캔버스를 새로 붙여도 내린 단계를 잇는다. 기기에 기억하는 것은 아직 없다.
  - **함께 관람 실제 통로**: 들어온 뒤에만 잇는다. 토큰은 등록한 방문자 토큰, 별명이 없으면 기기가 만든 토큰이다(서버 등록 없음, ADR-057 R-5). 내 자리는 그린 프레임마다 넘기고, 통로가 `LIVE_POSE_HZ`로 줄인다.
  - **별명·동의는 입장 때(별명을 적었을 때만)**:
    - PRD 13.1·PLAN §7.3은 "처음 반응할 때"라고 하지만, ADR-057의 이름표는 방문자 등록 별명을 쓴다. 그래서 별명을 적고 들어가면 PRD 13.2 내용을 '다른 친구들도 볼 수 있어요' 판으로 그때 받는다.
    - 제목은 "들어가기 전에 읽어 주세요"(`copy.consent.titleEnter`)다.
    - 별명 없이 들어가면 동의 없이 익명으로 들어가고, 처음 반응할 때 받는다(P4-6).
  - **묶음 나누기**: 관람 화면(three·R3F)은 지연 로드한다. 전시를 불러오기 시작할 때 함께 받기 시작한다. 교사 화면(`/t/*`)도 지연 로드다.
  - **glTF 불러오기 도구는 renderer마다 하나**다(`viewer/scene/gltf.ts`). 템플릿 조각·설비·캐릭터가 같은 KTX2 일꾼을 쓴다. three가 경고하던 여러 일꾼을 없앴다.
  - **개발 서버의 미디어 처리**: 자식 프로세스 환경에서 `WATCH_REPORT_DEPENDENCIES`를 뺀다. `node --watch` 아래에서 그 값을 물려받은 자식이 감시용 IPC를 먼저 보내, 결과 검사가 거절하고 모든 업로드가 `E_SERVER`가 됐다(Codex가 시드 도구를 만들다 찾음, 시험 `apps/server/test/upload/process.test.ts`).
  - **규칙 검사**: 한국어 글 직접 쓰기 금지의 대상에 `apps/web/src/app/`을 더했다. 시험 자료는 `apps/web/src/dev/`에 둔다.
  - **글 작품·소리 작품(P4-4)**
    - 벽: 그리는 관의 것만 기기가 캔버스(긴 변 `TEXT_CARD_PX`)에 종이 카드로 조판하고, 관을 떼면 놓는다(`useCardTextures`). 본문 글자는 다 들어가는 가장 큰 크기다. 종이 색은 템플릿 모습 `card`다.
    - 크게 보기: HTML 종이 카드다(`TextZoom`). 최소 글자는 `TEXT_MIN_PX_*`, 한 줄은 `TEXT_LINE_CHARS`자다.
    - 쪽 나눔: 같은 CSS로 덩어리 높이를 재서 `planTextPages`로 담는다(`viewer/zoom/textPages.ts`, 재기 주입).
    - 넘기기는 `‹ ›`·좌우 키·밀기다. 좌우 키는 걷기 키보다 먼저 받아 크게 보기가 닫히지 않게 한다.
    - 소리 작품은 명판 + 재생이다(배경음악을 낮춤).
  - **배경음악(P4-7)**: 구역이 관이면 그 전시실 곡을 흘리고, 관 밖(외관·홀·회랑)에서는 줄여 끈다.
    - 잠금은 관람 중 첫 누름·키에서 푼다. 소리 엔진은 앱에 하나다.
    - `소리` 단추는 위 줄 아래 오른쪽에 있다(휴대폰은 아이콘만). 켬/끔은 학생 흐름이 기기에 기억한다(`sound` 속성).
  - **바뀜 확인(P4-9)**: `useExhibitionUpdates`(60초·화면 복귀)와 `planUpdate`로 나눈다.
    - 내용만 바뀌면 옛 배치 객체를 그대로 붙이고, 그림 받기 입력·작품 밝기 손잡이도 서명이 같으면 그대로 둔다. 글자 하나 고쳐도 텍스처를 다시 받지 않는다.
    - 배치가 바뀌면 캐릭터를 새로 만들지 않는다(`Walker.rebase`). 서 있을 수 있으면 그 자리에서 새 벽으로 이어 가고, 정지 지점은 `resumeStop`으로 잇는다.
    - 지금 관이 바뀌었으면 띠 "전시가 새로 바뀌었어요 `새로 보기`"로 미룬다.
  - **2D로 바꾸는 신호(ADR-019)**: `VisitScreen onFallback2d(reason)`을 한 번 부른다(2D 화면은 P4-10).
    - WebGL2를 만들 수 없음(미리 만들어 보고 바로 놓음, 캔버스 만들기 실패도 오류 경계로 받음)
    - `FALLBACK_2D_CONTEXT_LOSSES`(60초 안 2번)
    - '낮음'에서 `FALLBACK_2D_LOW_SEGMENTS`(3) 구간 연속 `FALLBACK_2D_FPS`(20) 미만
  - **지도**: 전시실(관)을 누르면 그 관의 첫 정지 지점으로 걸어가고 지도를 닫는다(G-05 `goToPart`).
  - **멈춤 표시(`idleFrameMark`)**
    - 멈춘 순간에 더해, 멈춘 뒤 바깥 사건(그림·글 카드가 올라옴, 다른 관람객)으로 한 번 그린 때도 그린 수를 남긴다. 도착 뒤 벽용 그림이 올라와 몇 번 다시 그리면, 태블릿 학생 e2e가 "멈춤"을 끝내 확인하지 못했다(Codex P4-12).
    - 그때 자리(`me`)는 다시 쓰지 않는다. 0.5초 기록도 실제로 움직였을 때만 쓴다. 장면이 `me`를 읽어 다시 그리기를 부르면 멈춘 채 계속 그리는 고리가 된다(첫 수정에서 세 크기 모두 실패로 확인).
    - 저절로 계속 그리는지는 e2e가 멈춘 뒤 몇 초 동안 프레임 수가 늘지 않는지로 본다(단언은 그대로).
  - **반응(P4-6) 붙이기**
    - 학생 경로(서비스가 있음)에서만 켠다. 캡션 `반응 남기기` → 덮개(`ReactionLayer`), 캡션 아래 공개 집계.
    - 덮개가 열린 동안은 걷기 키를 끈다. 크게 보기를 닫으면 덮개도 닫는다.
    - `E_REACTIONS_OFF`면 단추를 숨긴다. 보내기 줄은 관람 중 늘 살린다.
    - 서버는 반응 ID를 (방문자 토큰 해시, 작품)으로 정한다. 기기 쪽 열쇠는 (전시, 작품)이다 — PLAN §9.2의 "기기가 만든 반응 ID"는 실제와 다르다(서브에이전트 지적).
  - **모아 보기(G-04)**
    - 덮개는 한 번에 하나다. 열 때 지도·반응을 닫고, 연 동안은 걷기 키를 끈다.
    - 썸네일을 누르면 그 정지 지점으로 안내 걷기를 하고, 도착하면 바로 크게 본다. 손으로 걸어 안내가 끊기면 크게 보기도 취소한다.
    - PRD의 "날아가 줌인"은 자유 관람에서 걸어가기로 바꿨다.
  - **조사 '으로/로'**: `copy.reaction.asNickname`이 `{ro}`를 받는다(`roAfter`, 받침 없음·ㄹ은 '로'). "하늘고래으로"처럼 어색하던 것을 고쳤다.
  - **스티커 아이콘**: 마음·전구·별·물음표를 같은 선 굵기 결로 더했다. Antigravity 비평(U-07) 때 함께 본다.
  - **2D 대체 화면(P4-10)**
    - 학생 흐름에 `mode: '3d'|'2d'`를 둔다. `onFallback2d`가 오면 그 전시 동안 2D로 남는다.
    - 포스터에서 WebGL2가 없음을 알면 입장 단추를 바로 연다(첫 전시실 썸네일은 2D 화면이 먼저 깔고 벽용으로 바꿈).
    - 3D에서 넘어오면 보던 정지 지점부터 보인다. 2D의 캡션 `닫기`는 접기다.
    - 동작 줄이기면 입장 연출 단계(`entering`)를 건너뛴다. CSS로만 없애면 `animationend`가 오지 않아 멈출 수 있어서다.
  - **포스터 미리 불러오기**: 입장 단추는 3D 첫 자리 준비와 서비스 워커 미리 불러오기(§2.5)가 둘 다 끝나야 풀린다.
    - 서비스 워커가 없거나(개발·미지원) 공간 모자람·실패면 미리 불러오기를 "끝남"으로 친다. 관람은 네트워크로 그대로 된다.
    - 진행 막대는 둘의 평균이고, 미리 불러오기가 끝났으면 3D 준비 진행 그대로다.
  - **동작 줄이기(§6.14, 자유 관람에 맞춤)**: 작품 앞 도착·크게 보기·닫기 때 카메라를 날리지 않고 바로 옮긴다. 화면 층이 짧은 짙은 덮개 페이드(`--t-sheet`)로 잇고, 벽 부딪힘 흔들림을 끈다.
    - 안내 걷기 자체(캐릭터가 걷는 것)는 학생이 시킨 움직임이라 그대로 둔다.
  - **자동 시험의 fps 2D 전환**: 헤드리스 소프트웨어 그리기는 초당 1장 남짓이라, 태블릿 크기 학생 e2e가 설계대로 2D로 넘어가 3D 흐름을 볼 수 없었다(두 번 재현).
    - `navigator.webdriver`일 때만 fps 기준 전환을 끈다.
    - 전환 판정은 `TierMonitor` 단위 시험이, 2D 화면은 WebGL을 끈 확인이 본다. WebGL 없음·컨텍스트 손실 전환은 그대로 켜 둔다.
- **남은 것**
  - 포스터에서 고른 캐릭터·마지막 별명은 `localStorage`에 있다(`app/student/visitorPrefs.ts`, 포트 칸은 아직 없음). 교실 공용 기기에서는 다음 학생에게 앞 학생의 별명이 미리 채워진다. 방문자 토큰도 기기마다라 같은 기기 = 같은 관람객이다.
  - 학생이 본 전시도 기기의 최근 전시 목록에 들어간다. P5 선생님 첫 화면은 교사 토큰이 있는 것만 보여야 한다.
  - 글 작품·소리 작품은 아직 벽에 매트 색 판으로만 보인다(P4-4).
  - 바뀜 확인(P4-9)은 배치가 바뀌면 같은 자리에서 장면을 다시 붙이는 방식(`start`)으로 한다.

## ADR-060 · 운영 배포와 푸시 자동 배포 (2026-11-12, P7-1 앞당김)

- **배경**: 사용자가 GitHub 저장소 `djqanrudgns12/gallerywalk`(공개)를 쓰고, 커밋을 푸시하면 맥미니에 자동 배포되게 해 달라고 했다(rollingthunder 참고).
- **결정**
  1. **pull 방식**: launchd `com.ssamuniverse.gallery.autodeploy`가 1분마다 gwsvc로 `git ls-remote`를 돌려 GitHub `main`을 확인한다. 웹훅·self-hosted 러너는 쓰지 않는다. 맥미니는 들어오는 연결을 열지 않고, 공개 저장소라도 외부인의 PR 코드가 운영 기기에서 돌 길이 없다(rollingthunder `wiki/decisions/푸시-자동-배포.md`와 같은 판단).
  2. **CI 관문**: GitHub 호스트 macOS 러너(`.github/workflows/ci.yml`, 작업 이름 `verify`)가 `npm run verify`를 돌린다. 자동 배포는 그 커밋의 `verify` 확인이 `success`일 때만 배포한다(익명 check-runs API, 같은 SHA는 180초 간격). 운영과 같은 macOS라 `sips`·`afconvert` 시험까지 돈다.
  3. **받기**: 공개 저장소라 HTTPS 익명 읽기(배포 키·git bundle 없음). PLAN §19의 "git bundle" 기본안을 바꾼다. `main`의 후손 커밋만 배포하고, 강제 푸시·되감기는 거부한다.
  4. **배포 순서**(`ops/macmini/scripts/deploy.sh`): 금지창·부하·잠금 → `releases/<sha>`에 풀기 → `npm ci`·`npm run build`(`nice`) → **사전 검사**: 운영 DB 사본(SQLite 온라인 백업)으로 새 릴리스를 포트 **4523**에서 띄워 `/api/health` 200, 스키마가 같으면 이전 릴리스도 같은 사본에서 띄움 → `app` 링크 교체 → SIGTERM(KeepAlive가 다시 띄움) → 새 PID가 `/api/health` 200 → 실패하면 이전 릴리스로 되돌림. 릴리스는 3개를 남긴다.
  5. **금지창·부하**: 평일 08:00~15:59(KST)는 배포를 우회 없이 거부(75). 자동 배포는 기다렸다가 16시 뒤 첫 회차에 올린다. gwsvc는 소유자 홈(700)의 `resource-guard`를 볼 수 없어, 그 기준 중 두 가지(1분 부하 > 코어 × 0.75, 커널 메모리 압박이 위험(4))를 스크립트가 직접 쓴다(75). 처음엔 경고(2)도 막았으나 아바타 작업 중 늘 경고라 자동 배포가 멈춰 있어, 사용자 결정으로 위험일 때만 기다린다(빌드는 `nice`). 소유자 수동 배포는 `--now`로 바쁨 대기를 건너뛸 수 있다(수업 시간 금지는 그대로).
  6. **권한**: sudo는 처음 한 번만(`setup-host`·`install-daemons`). sudoers는 `소유자 → gwsvc`만(root 아님). 비밀값 3개(`PIN_HMAC_SECRET`·`RATE_KEY_SECRET`·`START_CODE_HMAC`)는 `init-secrets.sh`가 gwsvc 안에서 무작위로 만들고, 화면에 내지 않으며, 있으면 바꾸지 않는다.
  7. **실패 처리**: 같은 커밋이 2번 실패하면 멈춘다(`autodeploy retry`로 다시). 손으로 되돌리면 자동 배포도 멈춘다(같은 커밋을 다시 올리지 않게).
- **PLAN과 어긋나는 점(보고)**: PLAN §19는 "새 스키마에서 이전 릴리스 시작" 시험을 관문으로 두었지만, 지금 서버의 `migrate()`(`apps/server/src/store/db.ts`)는 DB가 코드보다 새 판이면 시작을 거부한다. 그래서 **마이그레이션이 든 릴리스는 자동으로 되돌릴 수 없다.** 그런 릴리스는 사전 검사(운영 DB 사본에서 새 릴리스 시작)를 통과해야 올라가고, 올라간 뒤 실패하면 자동 배포를 멈추고 고친 커밋으로 앞으로 고친다. 이전 릴리스가 새 스키마를 견디게 하려면 `migrate()`가 "더하기만 한 새 판"을 허용하도록 바꾸는 별도 결정이 필요하다.
- **버린 대안**: self-hosted 러너(공개 저장소에서 위험), 웹훅(인바운드 포트 필요), git bundle(공개 저장소라 불필요), 소유자 계정으로 실행(앱이 뚫리면 소유자 파일이 열림).
- **되돌리기**: `sh ops/gw.sh autodeploy pause`로 멈추거나 `install-daemons --remove autodeploy`로 끈다. 수동 배포(`sh ops/gw.sh deploy`)는 그대로 쓸 수 있다.

## ADR-061 · 교사 화면(P5)에서 정한 것 (2026-11-12) — 처음에 ADR-060으로 적었다가 운영 배포 ADR과 번호가 겹쳐 고침

- **나눔**
  - 교사 화면은 `app/teacher/`이고 `/t/*`로 지연 로드된다. 투어(`tour/`)는 3D라 한 번 더 따로 받는다.
  - 관리 화면 둘레 부품(열기 시트·`···` 메뉴·반응 탭)은 속성 약속(`manage/contract.ts`)으로 관리 화면 본체와 나눴다.
- **QR**: `uqr` 0.1.3(MIT, 의존성 없음, 2026-04-03 게시 — 7일 규칙 통과, 판 고정)을 넣었다. 칸 배열을 SVG 경로 하나로 그리고, 색은 테마 토큰이다(짙은 칸 · 밝은 종이). 오류 정정은 M, 여백은 4칸(표준)이다.
- **설정값**: `DELETE_CONFIRM_SEC`(3) · `TOAST_SEC`(4)를 `config.ts`로 옮겼다. 한 줄 소개 길이는 `SUBTITLE_MAX_CHARS`(80)를 따른다(PLAN의 60자를 바로잡음).
- **첫 화면 카드**: 기기의 최근 목록에는 상태·썸네일이 없다. 그래서 교사 토큰이 있는 전시만 카드마다 교사 보기를 불러 채우고(최대 5), `E_NOT_FOUND`면 기기에서도 지운다.
- **학교·학급**: 만들기 본문에 칸이 없어 만든 직후 `patchExhibition`으로 보낸다. 실패하면 알림 띠로 알린다.
- **자동 투어(P5-9)**: `VisitorScene`이 걷기 대신 카메라 조종기(`controller`)를 받는다. 투어는 교사 묶음을 관람 장면 입력으로 바꿔(`previewViewOf`, 게시 작품만) 같은 장면을 쓴다.
- **시험 기다리기**: 지연 로드 화면을 기다리는 시험은 정해진 횟수 대신 화면이 나올 때까지 기다린다(`flushUntil`). 교사 묶음이 커져 `flush(8)`로는 모자랐다.
- **패키지(P5-C)**: `@dnd-kit/core` 6.3.1·`@dnd-kit/sortable` 10.0.0·`@dnd-kit/utilities` 3.2.2(MIT, ADR-032)과 `pdfjs-dist` 6.5.438(Apache-2.0, 2026-11-01 게시)을 판 고정으로 넣었다. 모두 7일 규칙을 통과했다. pdf.js의 선택 의존성 `@napi-rs/canvas`는 Node용이라 브라우저 묶음에 들어가지 않는다. 둘 다 교사 묶음에만 들어가야 한다(학생 첫 화면 묶음 확인은 P5-C 끝 조건).
- **LAN http 해시**: 보안 연결이 아닌 `http`(맥 IP로 연 개발 주소)에는 `crypto.subtle`이 없다. 올리기 사전 검사는 해시 없이 통과시키고 기기 쪽 중복 거르기만 건너뛴다(서버가 `E_DUPLICATE`로 거름). 전에는 파일이 `E_FILE_BROKEN`으로 막혔다(서브에이전트 B 지적).
- **설정값**: 교사 관리·올리기의 `AUTOSAVE_DELAY_MS`·`LONG_PRESS_MS`·`DRAG_START_PX`·`UPLOAD_RETRY_MAX`·`UPLOAD_RETRY_DELAY_MS`·`UPLOAD_HEAD_BYTES`·`AUDIO_PROBE_TIMEOUT_MS`를 `config.ts`로 옮겼다.
- **PDF 쪽 그리기(P5-C)**
  - PLAN §5.3의 `pdfPages.worker.ts` 대신 메인 스레드의 `upload/pdfPages.ts` + `upload/pdfjs.ts`로 그린다. 문서 해석은 pdf.js 자체 워커가 하고, 캔버스 그리기는 모든 브라우저에서 메인 스레드다.
    - "Chrome만 OffscreenCanvas 워커"는 쓰지 않는다. Safari 호환이 불확실하고(F-10), 워커 캔버스에서는 `toBlob`을 쓸 수 없다.
    - 한 번에 PDF 하나, 한 쪽씩 그려 화면이 멈추지 않게 한다.
  - legacy 빌드를 쓴다(오래된 학교 태블릿 Safari). 처음 PDF를 놓을 때만 받는다(관리 화면 첫 묶음에도 없음).
  - CMap·표준 글꼴·wasm은 저장소에 복사하지 않는다. vite 플러그인이 설치된 `pdfjs-dist`에서 `/assets/g/pdfjs/{판}/`로 내보낸다(외부 주소 없음, 판 번호 경로라 오래 캐시).
- **끌어 옮기기(P5-C)**: 터치는 `LONG_PRESS_MS` 길게 누르기로 시작하고, 그 전에 `DRAG_START_PX`보다 움직이면 스크롤로 넘긴다.
  - 키보드는 M으로 집고 Space·Enter로 놓으며 Esc로 그만둔다.
  - 한 장을 칩에 놓으면 `patchArtwork({roomId})`, 여러 장이면 `batch MOVE`다.
- **편집 중 끌기 끄기**: 카드 제목을 고치는 동안 끌기만 끄고 `aria-disabled`는 붙이지 않는다. `@dnd-kit`의 `disabled`가 칸에 `aria-disabled="true"`를 붙이면, 안의 제목 칸까지 화면 읽기 프로그램·Playwright에 잠긴 것으로 알려진다(교사 e2e가 찾음).

## ADR-062 · 독립 코드 검토(P7-6) 반영 (2026-11-12)

- **누가**: Codex(deep)가 읽기만 해 9건(높음 2·보통 7)을 냈다. Claude가 코드로 하나씩 확인했고 9건 모두 맞았다. 8건은 Claude가 고쳤다. 9번은 Codex가 시험을 쓰다 사용량 한도에 걸려, 남은 시험에 맞춰 Claude가 구현했다.
- **학생 경로 속도 칸(높음)**: `GET /api/e/{code}`·`/v`·방문자 등록·별명·반응에 §9.2 학생 표의 칸을 붙였다(`PUBLIC_RATE`).
  - 교사 경로와 같은 `rate_buckets`·HMAC 주체 키를 쓴다. 방문자 칸은 토큰 해시의 HMAC(`ClientKeys.visitor`)으로 센다.
  - 틀린 입장 코드는 IP마다 세고, 한도를 넘은 IP는 창이 끝날 때까지 맞는 코드도 막는다(열린 전시 캐내기).
  - 보안 묶음이 없는 시험용 앱은 세지 않는다.
- **관람 중 사라진 전시(높음)**: 버전 확인이 `E_NOT_FOUND`면 닫힘 화면으로 간다. 알고 있는 만료 시각이 지났으면 묻지 않고 닫힌다.
  - 사라졌을 때는 보기 묶음 주소를 한 번 더 부른다. 서비스 워커가 그 "없음" 답을 보고 기기 사본을 지운다(§9.6, SW는 고치지 않음).
- **기기에 남는 개인 값**: 최근 전시 목록에서 지난 전시를 뺄 때 그 전시의 방문자 토큰·별명과 교사 세션도 지운다. 반응 보내기 줄 칸에는 전시 만료 시각을 붙여, 지나면 보내지 않고 지운다.
  - 최근 목록 상한(`RECENT_EXHIBITIONS_MAX`)을 넘겨 밀려난 전시의 값은 아직 남는다. 앱 시작 때 한 번 정리하는 것은 하지 않았다(다음 전시를 열 때 정리됨).
- **올리기 중복**: 실패·멈춘 파일의 해시는 풀어 다시 고를 수 있게 한다. 올린 파일만 계속 막는다.
- **소리**: `playRoom(null)`로 줄이는 중이면 `stopping` 상태로 둔다. 같은 곡으로 돌아오면 그 자리에서 다시 키우고, 끝까지 멈추면 요소를 쉬게 한다. 앞선 예약이 뒤의 줄이기를 끊지 않게 차례(`fadeGen`)를 센다. 잠금 풀기는 이미 풀렸으면 요소를 다시 깨우지 않는다(재생 중인 곡이 멈추던 문제).
- **작품 그림 다시 받기**: 받지 못한 그림은 `RESIDENCY_RETRY`(3번, 5초에서 배로)만큼 다시 받는다. 원하는 집합을 다시 정할 때와 `online` 때 다시 본다.
- **KTX2 일꾼**: renderer를 놓을 때(`dispose`) 그 renderer의 KTX2 일꾼도 닫는다(캔버스를 다시 붙일 때마다 쌓이던 것).
- **마치지 못한 PDF**: 쪽을 받기 시작할 때 작품 `updated_at`을 새로 한다. 정리 주기가 `PDF_INCOMPLETE_PURGE_HOURS`보다 오래된 `PROCESSING` PDF를 지운 상태로 바꾸고 내용 판만 올린다. 그 뒤는 지운 작품과 같은 길이다. 실패·숨김 PDF는 교사가 보고 지울 수 있어 대상이 아니다.

## ADR-063 · 교사 3D 미리 보기와 크게 보기 연출 (2026-11-12, P5-6·P6-2)

- **미리 보기 자리**: ADR-057이 관리 격자 오른쪽 미리 보기 칸을 없앴으므로(PRD 15.8), PRD G-13의 "학생이 보는 그대로의 3D 미리 보기"는 모든 크기에서 `미리 보기` 단추 → 전체 화면 층으로 연다. 게시 작품이 있을 때만 보인다.
  - PLAN §7.4의 "1280px 이상 오른쪽 미리 보기"는 이 결정으로 바뀐다. 오른쪽 칸은 작품 패널·전시실 시트 자리다.
- **같은 화면**: 층은 학생 관람 화면(`VisitScreen`)을 그대로 쓴다. 배치는 기기에서 다시 계산하지 않는다. 열 때 교사 묶음을 서버에서 새로 받아(읽을 때 계산한 배치, 학생 입장과 같은 길) `previewViewOf`로 바꾼다. 그래서 학생 화면과 같은 배치 해시가 된다(§15.4-4).
  - 교사 묶음이 바뀌면(고치기·게시) `AUTOSAVE_DELAY_MS` 뒤 다시 받는다. 배치가 같으면 그림을 다시 받지 않는다.
  - 3D 엔진은 단추를 누를 때 받는다(관리 화면 첫 묶음에 없음).
- **작품 누르기**: 미리 보기에서 작품을 누르면 걸어가 크게 보는 대신 그 작품 패널이 서랍으로 위에 열린다(`VisitScreenProps.onPickArtwork` → `VisitorScene.onArtworkTap`). 미리 보기에서는 반응·보내기 줄 같은 학생 일을 하지 않는다. 닫기는 소리 단추 옆 `미리 보기 닫기`와 Esc(걷는 중일 때)다.
  - 캐릭터는 `teacher-m`이다. 교사 캐릭터 고르기(U-19-11)가 생기면 그것을 쓴다.
- **쪽 그림 넘기기 빠짐 고침**: 학생 관람 화면이 PDF·긴 세로·글 많은 그림의 쪽 목록(`zoomPages`)을 만들어 놓고 크게 보기 층에 넘기지 않고 있었다. 미리 보기를 만들다 찾아 넘기게 했다.
- **크게 보기 연출(PRD 8.2)**: 자유 관람 엔진에 빠져 있던 "주변 밝기 70%"를 `ZoomDim`으로 붙였다. 크게 보는 동안 장면 밝기를 `T_ZOOM`에 걸쳐 `ZOOM_DIM`까지 낮추고, 그 작품은 1에 둔다. 닫으면 `T_UNZOOM`에 걸쳐 되돌린다. 움직이는 동안만 다시 그리고, 동작 줄이기면 바로 바꾼다.
  - 캡션 카드는 `--t-zoom-caption-delay`(0.25초) 늦게 아래에서 올라온다.
  - 카메라 다가가기는 여전히 따라가기 감쇠(`CAM_FOLLOW_DAMP`)라 정확히 0.8초 곡선은 아니다(95% 약 0.7초).
  - `ZOOM_POOL_BOOST`(액자 빛 더 밝게)는 작품과 빛 웅덩이가 밝기 손잡이를 함께 써서 아직 쓰지 않는다.

## ADR-064 · 바깥 공개: 글방 CloudFront를 공용 입구로 (2026-11-13, P7-2 앞당김, U-01 1안 재확인) — 커밋 `c59d4c1`에는 ADR-061로 적혔다가 교사 화면 ADR-061과 겹쳐 고침

- **배경**: ADR-002 1안을 고를 때는 "글방이 아직 운영 전"이었으나, 공개 시점에는 글방이 운영 중이었다. 사용자가 그 사실을 알고 1안으로 진행하라고 했다(2026-11-12).
- **결과**: `gallery.ssamuniverse.com`(Cloudflare DNS 회색 구름) → CloudFront 글방 배포 `E3TFCRGRU1HG1Q`(서울) → `origin-gallery.ssamuniverse.com`(주황 구름) → Cloudflare WAF `gw-origin-lock`(머리 `x-gw-origin-auth` 없으면 Block)·Cache Rule `gw-origin-no-cache` → 터널 `gallerywalk` → `127.0.0.1:4520`.
  - 배포 변경 한 번: 원본 `origin-gallery`(HTTPS 전용, 비밀 머리) 추가, 대체 도메인 `gallery` 추가, 인증서를 `write`+`gallery` 인증서로 교체, 세 동작의 viewer-request 함수를 `ssam-viewer-request`(= `ops/cloudfront/viewer-request.js`)로 교체. `we-viewer-request`는 지우지 않고 남겼다.
  - 공용 입구 함수는 운영 중인 `we-viewer-request`(LIVE)를 내려받아 비교한 뒤, 빠져 있던 `x-we-forwarded-host`를 넣어 글방 요청을 전과 같게 했다(test-function으로 gallery·write·기본 주소 확인).
  - 확인(2026-11-13 00:3x): gallery `/api/health`·`/` 200(ICN57, API 첫 바이트 0.055~0.084초), 작품 파일 캐시 Hit, write 200 그대로, 원본 직접·틀린 머리 403.
- **배운 것**: 소유자의 `~/.cloudflared/cert.pem`은 `rollinthunder.net` 영역 로그인이라 `cloudflared tunnel route dns`가 레코드를 그 영역에 만든다. 원본 DNS는 대시보드에서 만든다(runbook ④).
- **남은 위험(다른 저장소)**: 글방 `ops/aws/setup-ops.sh --apply`(원본 비밀값 회전 등에 씀)는 세 동작의 함수를 `we-viewer-request`로 다시 연결한다. 그 함수는 `write` 외 주소를 308로 보내므로 **돌리면 갤러리가 끊긴다.** 글방 쪽에서 공용 함수를 쓰도록 고쳐야 한다(이 저장소에서는 고치지 않음). 그 전까지 글방 `setup-ops.sh --apply`를 돌리지 않는다.
- **되돌리기**: `~/.gallerywalk-admin/rollback-config.json`(600)으로 `update-distribution`(실행 순간 ETag 사용), `gallery` CNAME 삭제.

## ADR-065 · 사용자 결정 반영: 어두운 전시관·글꼴·처음 쓰는 친구·Safari 시험 (2026-11-13)

- **실내 분위기 D(U-19-10)**: `look.ts`에 D "어두운 전시관"을 더하고 기본으로 한다.
  - 숯색 벽·짙은 바닥·낮은 방 빛(구운 빛 0.95, 반구광 0.22)을 쓴다. 작품 위 빛 웅덩이는 스포트처럼 세게 한다(불투명 0.95). 방 : 작품 ≈ 1 : 6.
  - 실시간 조명은 늘리지 않는다(AGENTS §4). "드문드문 조명·잘 꾸민 전시관"의 나머지(천장 스포트·벽등·차단봉)는 조각 작업 V-56(Blender)으로 한다.

  - 둘 다 OFL이고, 판을 고정했으며, 배포된 지 7일이 지났다(2023-11·2026-07).
  - 같은 출처에서 낸다(`font-src 'self'`). 서비스 워커 미리 저장에서는 글꼴 조각을 뺀다. 수백 개라서, 쓰는 글자의 조각만 브라우저가 받는다.
- **처음 쓰는 친구예요(U-20 나안)**: 포스터 별명 칸 아래 단추를 둔다. 누르면 이 전시의 방문자 기록(토큰·별명)과 마지막 별명을 지우고, 입장할 때 새 방문자 토큰을 만든다. 캐릭터는 그대로 둔다.
- **Safari 엔진 시험(U-22)**: Playwright WebKit 27.2를 받았다. `webkit` 프로젝트는 배치 해시와 학생 흐름 데스크톱 한 크기만 돈다. swiftshader 시작 인자는 chromium 프로젝트로 옮겼다.
- **F2-A가 정한 것(받아들임)**

## ADR-069 · 운영 CSP 안에서 KTX2 변환기·글꼴이 돌게 (2026-11-13)

- **문제**: 운영에서 캐릭터가 Tripo 리깅 모델이 아니라 임시 모형(`CharacterFigure`)으로 나왔다(사용자 화면 사진). 운영 CSP `script-src 'self' 'wasm-unsafe-eval'`이 문자열 실행을 막는다. 그런데 three가 함께 주는 Basis 변환기(Emscripten embind)는 `craftInvokerFunction`과 `__emval_get_method_caller`에서 `new Function`으로 함수를 만든다. 그래서 변환기가 시작하지 못했고, KTX2 그림이 끝없이 기다려 glb `loadAsync`가 끝나지 않았다. 템플릿 조각 glb도 같은 KTX2를 쓴다. 개발 서버와 e2e에는 이 CSP가 없어 출시 때부터 드러나지 않았다. 같은 까닭으로 빌드가 `data:`로 넣은 작은 글꼴 조각도 `font-src 'self'`에 막혔다.
- **결정**: CSP는 넓히지 않는다. `'unsafe-eval'`과 `data:` 글꼴은 허용하지 않는다(자동 권한 검사도 CSP 완화를 막았다).
  - 자체 배포 변환기의 두 곳을 같은 일을 하는 클로저로 바꾼다. Emscripten `DYNAMIC_EXECUTION=0` 경로와 같은 방식이다. 1년 immutable 캐시 때문에 폴더 이름을 `basis-r187-csp1`로 바꾼다.
  - 시험 `viewer/scene/transcoder.test.ts`가 변환기 파일에 문자열 실행이 없는지 지킨다.
  - 빌드는 글꼴을 `data:`로 넣지 않는다(`assetsInlineLimit`).
- **확인**: 운영과 같은 CSP를 거는 임시 정적 서버에서 비교했다.
  - 고치기 전: `EvalError`, glb를 읽지 못함
  - `'unsafe-eval'`을 더했을 때: 성공
  - 고친 변환기 + 원래 CSP: 성공(동작 4개, 질감 1024×1024 압축, mipmap 11단계)
- **남은 것**: 운영 빌드 e2e(`tests/e2e/prod.spec.ts`, 실제 서버 CSP)를 정기적으로 돌려 이런 운영 전용 실패를 잡는다. three를 올릴 때는 변환기를 다시 복사하고 같은 고침을 다시 적용한다(시험이 실패해 알려 준다).

## ADR-070 · 학교망 입장 보강과 실기기 반응성 재기 (2026-11-13, PRD 18장 G-24·G-25, FIELD_PLAN H0·H1)

- **배경**: 첫 수업에서 학교 와이파이의 갤럭시탭이 들어오지 못했다. 같은 학교의 랜선 데스크톱은 들어갔다. 사용자는 도메인을 바꾸지 말라고 했고(U-28), iOS·안드로이드 모두 실기기에서 반응성을 재며 강화하라고 했다.
- **결정**
  - **3D 준비 시간 상한**:
    - 조각 glb는 받는 진행이 `MODULE_LOAD_STALL_MS`(15초) 동안 멈추면 기다리지 않고 다음 조각으로 간다. 늦게 오면 그때 합친다. 다 받은 뒤 해석에는 상한을 걸지 않는다.

    - 3D 화면 묶음 `lazy`가 실패하면 `LoadGuard`가 받아 2D로 바꾼다(`chunk_fail`). 전에는 오류 경계가 없어 화면 전체가 내려갈 수 있었다.

    - 빌드 대상을 `es2022`에서 `['safari15','chrome90','firefox90','edge90']`으로 낮춘다(문법만 바뀜).

    - `check:rules`에 규칙 ⑥ `no-new-runtime-api`를 더한다.
  - **학교 공용 IP**:
    - 틀린 입장 코드는 기기 칸(`badCodeDevice` 20/10분)을 먼저 센다. IP 칸은 60에서 300/10분으로 올린다.
    - 맞바꿈: 기기 ID를 바꿔 가며 캐내면 IP 하나로 하루 약 4.3만 번(전에는 약 0.9만 번)을 시도할 수 있다. 6자리 코드 100만 개 가운데 열린 전시는 소수라 받아들인다. 기기 칸이 연타를 먼저 막는다.
    - 함께 관람 `LIVE_CONNECT_PER_IP_MIN`은 120에서 600으로 올린다.
  - **익명 기기 보고**(`POST /api/e/{code}/diag`, `types/diag.ts`):
    - `fail`: 2D로 바꾼 까닭. 서버 메모리에 전시·까닭별 수만 `DIAG_COUNT_WINDOW_MIN` 동안 둔다. 교사 `GET …/live`가 보인다.
    - `report`: 관람 한 번의 반응성. 담는 것은 단계 시각, 이어 그린 프레임 fps p50·p10, 프레임 p95, 누름 → 다음 rAF p50·p95, 긴 작업, 함께 관람 받은 양, 품질 단계다. 서버가 `DATA_DIR/reports/` 날짜 파일에 남기고 `DEVICE_REPORT_KEEP_DAYS`(14일) 뒤 지운다.

  - 대체 도메인(HW-03·HW-04, U-28)은 하지 않는다.

## ADR-071 · 미술관 고도화 v2 설계 고정: 공간 v4·조작 v2·밝기·캐릭터 화풍 (2026-11-13, PRD 19장 G-27~G-31, PRD_V2 M0-1)

- **배경**: 사용자 의견 12가지(2026-11-13)를 담았다. 한 공간에 작품이 몰림, 전시실이 방처럼 좁음, 안내판이 잘리고 칠판 같음, 계단이 작음, 점프가 어색함, 너무 어두움, 출구와 도슨트가 없음 등이다. 요구와 수치는 `docs/PRD_V2.md`가 원본이다. 이 ADR은 구현 전에 굳히는 구조 결정만 적는다.
- **결정 1 · 공간 v4는 `algoVersion ≥ 4`에서만 켠다**
  - 지금 문법(입구 홀 + 4m 회랑 + 번갈아 놓은 관)은 v3로 그대로 둔다.
  - v4 문법은 `computeLayout`이 `input.algoVersion ≥ 4`일 때 고른다. v4가 쓰는 치수는 모두 `config.ts`의 새 묶음 `LAYOUT_V4` 하나에 둔다. 메인홀 폭 18m·천장 10m, 전시실 S 12×10·M 15×12·L 18×14m·천장 6m, 포털 3.6×4.2m, 방 사이 문 2.4×3.6m, 액자 사이 ≥ 2.0m, 베이 4.5m, 관당 작품 상한 8이다.
  - 그래서 v3 결과·해시는 바이트 하나 바뀌지 않는다. `ROOM_SPLIT_AT`(12, PRD 14장)도 v3에서는 그대로이고, v4는 `LAYOUT_V4.splitAt`(8)을 쓴다. 전시실 나눔이 "기본 기준값"이라는 PRD 5.2의 뜻은 같다.
  - **운영 `ALGO_VERSION`은 M3 건축 조각(6m·10m 높이 벽, 홀·포털·계단)이 `assets:build` 예산을 통과한 뒤에 4로 올린다.** 그 전에는 개발에서만 `overrideConfig({ALGO_VERSION: 4})`로 걷는다. 임시로 4m 조각을 `scale`로 늘려 보이는데, 몰딩이 늘어나 보이므로 운영에 내지 않는다.
- **결정 2 · v4 평면은 "메인홀 + 두 날개 순환"이다**(PRD_V2 §5.1)
  - 정문(−Z) 뒤에 메인홀이 +Z로 뻗는다. 전시실은 홀 양옆 날개에 z 방향으로 줄지어 붙는다. 방의 N 벽이 홀 쪽이고 가운데에 포털이 있다. 같은 날개 이웃 방은 L·R 벽의 방 사이 문으로 이어진다(앙필라드).
  - 정지 지점 순서는 대문 → 광장 → 정문 → 홀 → 서쪽 1·2·3(정문 쪽에서 안쪽으로) → 동쪽 4·5·6(안쪽에서 정문 쪽으로) → 홀 → 대문이다.
  - 방 수가 2개 이하면 서쪽만 쓰고, 3개 이상이면 서쪽에 올림 N/2를 둔다. 홀 길이 = max(30m, 긴 날개 줄 + 12m)이며 2m 배수다.
  - 로툰다와 T자 두 번째 홀은 v4 첫 판에 넣지 않는다. 대신 홀 끝 벽에 조형 하이라이트 장식 자리를 둔다. 13개 이상이면 홀이 길어지는 것으로 받아들이고, 걷기 시간 성질 시험은 방 1~12개를 본다.
  - 관(방) 안 계획은 지금 `roomSizing`·`wallPlacement`·`part`의 벽 채우기를 그대로 쓴다. v4에서 바뀌는 것은 크기 표·간격·문 자리·소개 벽(입구 옆 한 베이는 작품 금지)뿐이다. 새 엔진을 따로 만들지 않는다.
- **결정 3 · 배치 출력 스키마 3**: `schemaVersion`은 2 또는 3이다. 3은 v4 문법이 낸다. 새 칸은 모두 선택(optional)이라 v2 배치를 읽는 기기·서버 코드가 깨지지 않는다.
  - `zones[]`: plaza·portico·hall·gallery(partId)와 그 사각형. 그리기 범위·밝기·말풍선 보이기의 단위다.
  - `signs[]`: 종류 ①~⑦(PRD_V2 W-03), 자리·크기, 예약 사각형(작품·문·다른 사인과 겹치지 않음).
    - 글자는 가로 압축·`…` 자르기를 하지 않는다. 판 크기를 글에 맞추고, 길면 두 줄로 쓴다.
    - 제목 아래 끝 높이는 ≥ `LAYOUT_V4.signTitleMinY`(2.6m)이고, 앞 `signClear`(2.5m)에 사람이 설 자리를 두지 않는다.
  - `npcSpots[]`: 도슨트 ID(`docent-plaza`·`docent-hall`·`docent-room`, 그림 세션과 같은 ID), 자리, 바라보는 방향, 구역. 걷는 길·사인·작품 시야 밖, 벽 0.6m 앞이다.
  - `decorSlots[]`: 종류, 자리, 회전, 구역. 베이 가운데·기둥 축에만 대칭으로 둔다.
  - `gate`: 대문 가운데·반지름. `boundary`: 광장 경계 선분.
  - 옛 배치는 읽지 않고 다시 계산한다(ADR-057 규칙). v4 배치 해시 e2e 기대값을 새로 두되, v3 기대값은 바꾸지 않는다.
- **결정 4 · 조작 v2**(PRD_V2 W-01·W-05·W-06·W-07·W-08)
  - Space는 행동 키다. 우선순위는 도슨트 `NPC_TALK_RADIUS_M`·앞 `NPC_TALK_ARC_DEG` → 대문 `GATE_RADIUS_M` → 점프이고, 순수 함수 `resolveAction`이 정한다.
  - 마우스로 누른 HUD 단추는 초점을 놓는다. 입력 칸·창이 열려 있으면 Space를 쓰지 않는다.
  - 점프는 클립 없이 엔진이 연출한다(웅크림·늘림·공중 자세·착지 눌림·되튐, `CHAR_JUMP_SQUASH`). 남의 점프는 위치 메시지 v2(현장 HS-02) 위에 '점프 시작' 사건을 더해 받는 쪽이 같은 포물선을 재생한다. 이것은 현장 H2 뒤에 한다.
  - 경계 밀림·사람끼리 부딪힘은 각자 기기에서 판정한다. 서버 중계를 늘리지 않는다.
  - 대문이 아직 배치에 없는 동안은 `exterior.plaza`에서 정면 반대쪽 끝 가운데를 대문으로 쓴다(M2에서 `layout.gate`로 바꾼다).
  - `재접속하기`는 같은 전시 주소를 다시 여는 것이다. 소켓·장면이 새로 시작되고 별명·캐릭터는 기기 저장으로 유지된다(U-37 기본값).
- **결정 5 · 밝기**(ADR-065 분위기 D 값을 고침): 노출 0.95→1.05, 구운 빛 0.95→1.15, 반구광 0.22→0.30이다. 작품 면(톤 매핑 없음)·빛 웅덩이는 그대로 두어 방 : 작품 ≈ 1 : 4로 좁힌다. 어두운 톤은 유지한다. 실시간 조명은 늘리지 않고, 조명 기구는 발광 재질·구운 빛·빛 번짐 판으로 만든다(M3·M6).
- **결정 6 · `[고정]` 해석 변경**(사용자 최신 지시가 PRD `[고정]`보다 우선)
  - **PRD 1.4 "채팅 하지 않음"**: 머리 위 말풍선은 한다. 기본은 전용 스티커와 정해진 짧은 말뿐이다. 자유 글(20자)은 교사가 켤 때만 쓴다(U-31). 말풍선은 저장하지 않고 잠깐 보였다 사라지며, 작품 반응(G-07, 교사만 봄)과 별개다.
  - **PRD 7.3 "도슨트는 2D 오버레이"**: 3D 도슨트 NPC 3명을 둔다. 대사는 예절 안내이고 `말걸기`마다 섞은 주머니 순서로 나온다.
  - **캐릭터 화풍**(PRD_V2 §3.4·U-39): 쌤유니버스 얼굴 문법의 3D 피규어로 새로 그린다. 쌤유니버스 2D 그림은 화풍 기준으로만 쓴다. 그림·3D 원본은 별도 그림 세션이 `.local/art/`에 만들고, 최적화·배치는 메인 세션이 한다.
- **대안**
  - 지금 회랑을 넓히기만 하는 안: 막다른 방이 그대로이고 "광장 같은 홀"이 없다.
  - 자유 평면(벽을 아무 데나): 결정성·시험·조각 수가 무너진다.
  - v4를 바로 운영에 내기: 4m 조각을 늘린 임시 모습이 학생에게 보인다.
- **결과·위험**
  - 그리기 호출은 홀에서 방을 포털로 보이는 만큼만 그려 지킨다(M2-4).
  - 정적 합치기는 M3-4에서 한다.
  - 걷기 시간 예산(PRD_V2 §5.4)은 성질 시험(M2-6)이 막는다.
  - v3·v4 두 문법을 한동안 함께 둔다. 운영 판을 올린 뒤 2주가 지나고 v3 배치가 남지 않으면 v3 문법을 지우는 것을 따로 정한다.

## ADR-072 · 함께 관람 판 2: 작은 위치 배열·무리마다 한 번·관심 영역·느린 기기 건너뛰기 (2026-11-13, PRD 18장 G-25, FIELD_PLAN H2 HS-02~HS-06·HS-10)

- **배경**: 실시간 접속 때 렉이 있었다(사용자). 허브는 이미 초당 5번·바뀐 사람만 보냈다. 그런데 네 가지 비용이 남아 있었다.
  - 좌표를 반올림하지 않은 긴 JSON을 보냈다.
  - 받는 사람마다 "자기 것을 뺀" 글을 따로 만들었다. 30명 방이면 한 차례에 30번 만들었다.
  - 밀린 기기를 보호하지 않았다.
  - 모두에게 모두를 보냈다.
- **결정**
  - **판 2 약속**(`types/live.ts`, `domain/live/poseCodec.ts`):
    - `hello.v`는 1 또는 2다. 판 2 기기에는 `welcome`·`join`에 방 안 번호 `n`(비어 있는 가장 작은 수)을 붙인다.
    - 위치는 `{"t":"p","at":…,"p":[n,x(cm),y(cm),z(cm),방향(0.001rad, -π~π),걸음,…]}`로 보낸다.
    - `p`에는 받는 사람 자신도 들어 있고, 기기가 자기 번호를 건너뛴다.
    - 판 1 기기(서비스 워커가 옛 앱을 줄 수 있음)는 같은 방에서 예전 형식 그대로 받는다. 판 1 길은 다음 판에서 뺀다.
  - **무리마다 한 번**(HS-03): 바닥 `LIVE_AOI_CELL_M`(15m) 칸마다 글을 하나 만들고, `Buffer` 하나를 같은 칸 모두에게 보낸다.
    - `ws.send(buffer, {binary:false})`로 보낸다. 소켓마다 다시 인코딩하지 않고, 기기는 글 프레임으로 받는다.
  - **관심 영역**(HS-05): 자기 칸과 둘레 8칸의 바뀐 사람은 매 차례 보낸다.
    - `LIVE_FAR_EVERY`(5) 차례마다 그동안 바뀐 모두를 한 번에 보낸다. 이 글은 모든 무리가 같아서 한 번만 만든다.
    - 칸을 옮겨 다녀도 1초 안에 모두의 지금 자리를 받는다. 전시실 대신 거리 칸을 쓰는 까닭은 서버가 배치를 몰라도 되기 때문이다.
  - **느린 기기**(HS-04, `createSlowGuard`):
    - 보낼 줄이 `LIVE_SEND_BUFFER_MAX_BYTES`(32KB)를 넘으면 그 차례 위치를 건너뛰고, 다음 차례에 모두의 지금 자리를 보낸다. "바뀐 사람만" 방식이라 건너뛴 뒤 멈춘 사람이 옛 자리에 남지 않게 하려는 것이다.
    - `LIVE_SLOW_CLOSE_SEC`(15초) 동안 계속 밀리면 1013으로 닫고, 기기는 다시 잇는다.
  - **넘칠 때**(HS-10):
    - 서버 전체 방문자가 `LIVE_MAX_TOTAL`(200)이면 `E_LIVE_FULL`을 준다(혼자 관람으로 이어지고, 교사는 들어온다).
    - 1분 루프 지연 p99가 `LIVE_DEGRADE_LOOP_MS`(80) 이상이면 한 사람 위치를 `LIVE_DEGRADE_EVERY`(2) 차례에 한 번으로 줄인다(초당 5 → 2.5번, 계획의 3과 다름). 다음 1분이 괜찮으면 되돌린다. 바뀔 때 `live_degrade`를 기록한다.
  - **기기**(HS-06 나머지): `p`는 zod 대신 `decodePoses`로 손으로 검사한다. 나머지 메시지는 스키마 그대로다. 보내는 위치는 1cm·0.001rad로 반올림한다.
  - **기록**: `server_stats`에 `liveBuilt`(만든 글 수)·`liveSkipped`·`liveSlowClosed`·`liveDegraded`를 더한다.
- **잰 것**(30명이 한 칸에서 모두 움직일 때, 같은 형식으로 센 값):
  - 한 차례 글은 3,345B(판 1, 받는 사람마다)에서 652B(판 2, 하나)로 줄었다.
  - 학생 한 명이 받는 양은 초당 16.3KB에서 3.2KB로, 서버가 내보내는 양은 초당 0.48MB에서 0.093MB로 줄었다.
  - 한 차례에 만드는 글 수는 30개에서 1개로 줄었다.
  - 시험 `hubV2.test.ts`가 "30명 한 차례 글 하나, 900B 이하"를 지킨다.
- **남은 것**:
  - 부하 도구로 실측(HS-01)을 해야 한다. 30·60·120명, 판 2 걷기 시나리오이고, Codex 몫이다(11/16 뒤).
  - 판 1 길 빼기.
  - 다시 잇기 포기(HS-12 나머지): 버튼 UI가 필요하다.
  - 이벤트 루프 지키기(HS-07, 업로드 처리 양보)는 HS-01 숫자로 정한다.

## ADR-073 · 남의 점프: 따로 된 `jump` 사건 + 받는 쪽 해석식 포물선 (2026-11-13, PRD_V2 W-05·M1b, ADR-072 판 2 위)

- **배경**: 다른 관람객의 점프는 5Hz 위치 표본 2~3개를 선형 보간해 뭉툭하게 오르내렸다. PRD_V2 W-05는 위치 메시지 `move`에 '점프 시작' 값을 더하자고 적었다.
- **결정**
  - **`move` 값이 아니라 따로 된 사건**으로 보낸다.
    - 기기 → 서버 `{t:'jump'}`, 서버 → 판 2 기기 `{t:'jump', sid, at}`(strictObject).
    - 위치 글은 밀리면 건너뛰는 `sendShared`라 점프 순간을 잃을 수 있다. 점프는 꼭 가야 하는 `send`다.
    - 판 1 연결에는 `broadcast`에서 건너뛴다. 판 1이 `jump`를 보내면 지금 규칙대로 `E_VALIDATION`으로 닫는다.
    - 한 연결은 1초에 `LIVE_JUMP_MAX_PER_SEC`(2)번까지 중계하고, 넘는 것은 조용히 버린다.
  - **받는 쪽**: `at`을 위치와 같은 시계 오프셋·`LIVE_INTERP_DELAY_MS`로 늦춰 재생한다.
    - 그동안 높이는 땅 표본끼리 보간한 값 + 해석식 포물선 v·τ − g·τ²/2(`CHAR_JUMP_SPEED_MPS`·`CHAR_GRAVITY_MPS2`)이다.
    - 점프 시작 ~ 착지 + `PEER_JUMP_TAINT_MS` 사이 서버 표본은 공중 y가 섞여 높이 보간에서 뺀다.
    - 몸은 `jumpPose`의 눌림·늘림을 인스턴스 배율로 받는다. 공중에서는 뛰기 클립 위상 `PEER_JUMP_RUN_PHASE`(다리 사이 각이 가장 큰 곳)에 멈춘다.
  - **내 걷기 엔진도 해석식으로** 바꿨다(`walker.stepAir`).
    - 반암시 오일러는 화면 빈도마다 곡선이 달라 30Hz 기기에서 약 5cm 낮았다(서브에이전트 실측).
    - 이제 모든 기기에서 내 곡선 = 남이 보는 곡선이다.
  - 다시 그리기 상한(`LIVE_PEER_REDRAW_FPS` 20)은 그대로다. 그래서 점프 중에도 초당 20장이고, 웅크림 0.08초는 1~2장만 보인다. 캡처에서 끊겨 보이면, 온몸으로 그리는 사람이 점프하는 동안만 상한을 비키는 안을 검토한다.
- **대안**
  - `move`에 점프 값: 위치 글이 건너뛰어지면 점프가 사라진다.
  - 보간 y를 그대로 쓰기: 지금의 뭉툭함이 남는다.
- **결과**: 원격·내 곡선 차는 60Hz에서 최대 0.31mm(바꾸기 전 서브에이전트 실측, ≤ 2cm 기준)다. 해석식으로 바꾼 뒤에는 같은 식이라 시험이 그대로 통과한다. 화면 확인은 미실행이다.

- **결정**
  - **서버 경로 하나로 모은다**: `PUT /api/teacher/exhibitions/{id}/arrangement`, 요청 `{ base: [{ roomId, ids }], rooms: [{ roomId, ids }], restoreFeatured? }`.
    - `base`는 클라이언트가 본 바꾸기 전 배열이다. 서버의 지금 배열에서 그 뒤에 새로 생긴 작품(올리기)을 뺀 것이 `base`와 다르면 409 `E_CONFLICT`다. 집합만 보는 지금 순서 경로는 두 기기의 순서 바꾸기가 말없이 덮이고, 올리는 중에는 거짓 충돌이 난다. 이 비교로 둘 다 막는다.
    - 판마다 빈 배열을 허용하는 새 스키마를 쓴다(`uniqueIds`는 1개 이상이라 마지막 작품을 빼낸 판을 보낼 수 없다). `roomId`와 작품 ID는 한 번씩만 쓸 수 있다.
    - 한 트랜잭션에서 `roomId`·`order`를 정하고, 새로 생긴 작품은 끝에 붙인다.
    - 전시실이 바뀐 작품은 대표작을 푼다. 되돌리기는 `restoreFeatured`로 되살린다.
    - 바뀐 작품의 rev를 올리고 응답에 `revs`를 담는다. 그래서 클라이언트의 다음 제목 자동 저장이 옛 rev로 스스로 충돌하지 않는다.
    - `settle()`로 배치를 다시 계산한다.
    - 같은 판 순서, 다른 판 n번째, 여러 개 옮기기, 되돌리기(`base`·`rooms` 맞바꿈)를 모두 이 경로로 보낸다. 전시실 판 순서(`rooms/order`)에도 `base`를 더한다.
    - 함께 고친다: 되살리기는 그 전시실 끝으로 가게 하고, 올리기 순서는 서버가 정한다.
    - 옛 경로는 남겨 둔다.
  - **클라이언트 끌기**: `@dnd-kit` 그대로(새 의존성 없음).
    - 판마다 `SortableContext`를 두고, 빈 판에는 `useDroppable`을 둔다. `onDragOver`로 그릇을 넘나든다.
    - 폭이 다른 액자가 여러 줄로 꺾이므로 정렬 변형에 맡기지 않는다. 끄는 동안 보드 안 임시 배열을 바꾸고 줄바꿈은 flex에 맡긴다. 판 경계에서 상태가 오가는 것은 막고, `MeasuringStrategy.Always`를 쓴다.
    - 요청은 하나씩 차례로 보내고, 끄는 동안 들어온 새 보기는 놓은 뒤에 반영한다.
    - `DragOverlay`, `autoScroll`을 쓴다.
    - 판 순서는 판 머리 손잡이로만 끈다.
    - 시작 조건(`DRAG_START_PX` 8, `LONG_PRESS_MS` 500)과 키(M 집기, Space·Enter 놓기, Esc)는 지금 값을 유지한다.
  - **디자인 토큰**: 교사 관리 화면 바깥 틀에 `data-surface="manage"`를 달고, `tokens.css`에 돌 바탕·종이 칸·그림자 3단·액자 토큰을 둔다. 학생 관람 테마는 바꾸지 않는다.
  - **지도**: `viewer/map/axo.ts` 순수 함수로 배치 결과를 30° 축측(방위 20°·고도 35°) 모형으로 만든다. 투영, 문을 끊은 벽 조각, 앞뒤 정렬, 작품 자리, 학생 점을 다룬다. SVG 한 장으로 그리고 3D 엔진은 싣지 않는다. 견본은 시안 생성기 `.local/art/teacher-v3/canvas-src/axo.py`다.
  - **수업 수**: `/live`에 `rooms: [{ roomId, count }]`·`elsewhere`·`noPose`를 더한다. 허브는 멤버 위치 목록을 내는 읽기 함수만 두고, 관 → 전시실로 합쳐 세는 일은 application 순수 함수가 한다. 개인 위치는 응답·기록에 남기지 않는다. 학생 기기의 배치 판이 최신과 다를 수 있어 근사치다.
  - **지도의 관과 전시실**: 배치는 큰 전시실을 여러 관으로 나눈다(`partId = {roomId}:{n}`). 지도의 번호·밝힘·수는 관을 전시실로 합친다.
- **대안**
  - PATCH에 `order`를 더해 한 작품씩 옮기기: 여러 개 옮기기와 되돌리기가 요청 여러 번이 된다.
  - `POST …/move {ids, roomId, index}`: 되돌리기에는 여러 전시실 배열을 되살리는 다른 경로가 또 필요하다.
  - 집합만 보는 검사(지금 순서 경로를 넓히기만): 두 기기의 같은 판 순서 바꾸기를 잡지 못하고, 올리는 중에 거짓 충돌이 난다(계획 독립 검토 지적, 2026-11-14).
  - 3D 미리 보기를 지도로 쓰기: 교사 첫 받기가 커지고, 정지 화면에서도 GPU를 쓴다.
